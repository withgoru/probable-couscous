# 디자인 자료

화면 목업과 디자인 시스템을 코드 저장소 안에서 읽을 수 있게 뽑은 폴더입니다. 원본 캔버스: https://claude.ai/artifact/XbYFtDAXHQc4PnXY1Hh4hw (비공개, 열 수 없으면 이 폴더가 기준)

| 파일 | 내용 |
|---|---|
| `screens.md` | 화면별 구성, 상태, 동작, 핵심 문구. **스펙을 쓸 때 먼저 읽는다** |
| `tokens.md` | 색·글자 토큰, 대비 수치, 사용 규칙, shadcn-svelte 대응표 |
| `theme.css` | Tailwind v4 토큰과 shadcn 스타일 컴포넌트 클래스의 원본 (구현에서 그대로 가져다 쓴다) |
| `icons.md` | 쓰는 Iconoir 아이콘 34종 |
| `mockups/*.dc.html` | 화면 원본 마크업(참고용). 브라우저에서 바로 열리지는 않는다 |
| `mockups/_macros.md` | 목업의 `[[icon:..]]`, `[[navbar]]` 같은 표기 설명, 공통 메뉴바 마크업 |

## 쓰는 법

- 스펙 작성 때: `screens.md`에서 관련 화면을 찾아 **동작을 관찰 가능한 문장으로 풀어** 스펙에 쓴다. 화면 이름은 spec의 `screens` 항목에 적는다.
- 구현 때: `theme.css`를 클라이언트의 전역 스타일로 가져오고, 컴포넌트는 shadcn-svelte로 설치한 뒤 `tokens.md`의 "바꾼 점"을 다시 적용한다. 목업 마크업의 클래스 구성을 참고한다.
- 목업과 스펙이 다르면 **스펙이 우선**이다. 목업을 고쳐야 하면 사용자에게 알린다.

## 한계

- 목업의 데이터는 모두 샘플이다. 데이터 구조는 plan에서 정한다.
- 다크 테마, 모바일 외 교수 화면의 좁은 폭, 오류·빈 화면 일부는 아직 디자인하지 않았다.
