# Constitution

모든 스펙, 계획, 구현이 지켜야 하는 원칙입니다.

- 원칙을 어겨야 하는 상황이면 **구현을 멈추고 사용자에게 보고**합니다. 우회하거나 조용히 예외를 만들지 않습니다.
- 이 문서는 사용자만 수정합니다. Claude는 수정이 필요하면 "변경 제안"으로 알립니다.
- 각 원칙에는 번호(C1~C18)가 있고, 계획과 작업은 이 번호로 충족 여부를 밝힙니다.

## 제품 전제

- 본인 강의용 오프라인 수업 도구입니다. 한 강의실 40명 안팎, 최대 200명을 가정합니다.
- 교수가 강좌를 소유하고, 필요하면 조교(관리자)를 지정합니다.
- 해결할 문제: (1) 말로 질문하기 부담스러운 학생이 참여할 방법이 없다. (2) 교수가 슬라이드 밖의 자료를 수업 흐름을 끊지 않고 전달하기 어렵다. (3) 출석과 이해도 확인 도구가 수업을 끊는다.

## 데이터와 개인정보

**C1. 채팅은 참여 점수에 쓰지 않는다.** 채팅 횟수와 내용을 성적 항목으로 내보내는 기능을 만들지 않는다. 참여 점수는 출석과 퀴즈 응답 같은 행동 기록만 쓴다.

**C2. 학생이 만든 데이터는 공개 경로에서 읽을 수 없다.** 채팅, 닉네임, 개인 응답, 출석, 응답 시각은 공개 모듈이 직접 조회하지 못한다. 공개 모듈은 교수가 입력한 데이터와 집계 함수의 출력만 받는다.

**C3. 공개는 되돌리기 어렵다.** 공개 저장소에 올린 내용은 기록에 남는다. 의심스러우면 제외한다(fail closed). 승인 화면에는 되돌리기 어렵다는 확인 문구를 보여준다.

**C4. 퀴즈 통계는 보호 규칙을 거친다.** 아래 값은 초안이며 스펙에서 확정한다.
- 선택지 응답이 5명 미만이면 "기타"로 합친다. 합쳐서도 나머지를 빼면 한 명의 선택이 복원되면 가장 작은 다른 칸과 함께 합친다.
- 응답 인원이 10명 미만이면 선택지 분포를 생략하고 정답률은 구간으로 표시한다.
- 주관식 응답 원문, 응답 시각, 소요 시간, 개별 순위는 공개하지 않는다.
- 응답이 열려 있는 퀴즈의 정답과 통계는 공개하지 않는다.

**C5. 모든 데이터는 강의실 단위로 구분한다.** 모든 테이블과 조회에 강의실 식별자를 둔다. 조직 단위는 자리(비어 있는 칸)만 마련하고 구현하지 않는다.

**C6. 이벤트 기록은 추가만 한다.** 출석, 퀴즈 응답, 채팅, 관리 행동, 신원 조회는 수정하지 않고 쌓는다. 참여 점수는 이벤트에서 계산하는 파생 값이다.

**C7. 정체성은 세 층으로 분리한다.** 계정(이메일, 인증) / 강의실 멤버십(가명, 역할) / 활동 기록(가명만). 활동 기록에 이메일을 넣지 않는다. 가명은 강의실마다 따로 발급한다.

**C8. 권한 판단은 한 곳에서만 한다.** "이 사람이 이 행동을 할 수 있는가"를 판단하는 함수 하나만 둔다. 화면이나 개별 라우트에 권한 판단을 흩어 놓지 않는다.

**C9. 작성자 확인(신원 조회)은 교수 관리 페이지에서만 한다.**
- 정해진 사유 목록에서 선택해야 하고, 모든 조회는 변경할 수 없는 로그로 남는다.
- 한 번에 글 하나의 작성자 한 명만 확인한다.
- 관리자(조교)와 학생은 접근할 수 없다. 참여 점수 화면과 분리한다.

**C10. 학생에게 "익명"이라고 약속하지 않는다.** 실제 구조를 그대로 안내한다. 예: "다른 학생에게는 닉네임으로만 보입니다. 교수님은 심각한 사안에 한해 사유를 기록하고 작성자를 확인할 수 있습니다. 채팅 내용은 참여 점수에 반영되지 않고 공개되지 않습니다."

**C11. 이메일과 학번은 최소한만 수집한다.** 보관 기간과 삭제 정책은 스펙에서 정한다. 학교 규정과 충돌 여부는 미결정 항목으로 기록한다.

## 수업 중 신뢰성

**C12. 장애가 수업을 멈추지 않는다.** 인증 메일 지연, 출석코드 입력 실패, 연결 끊김이 있어도 교수가 수업을 이어갈 수 있는 대체 경로(수기 출석 보정, 채팅 읽기 전용 전환, 재접속 시 놓친 메시지 복구)를 항상 둔다.

**C13. 연결 상태가 아니라 저장소가 진실이다.** 출석과 응답은 연결 상태에 의존하지 않고 저장소에 먼저 기록한다. 서버를 재시작해도 잃지 않는다.

## 품질과 확장

**C14. 접근성은 WCAG 2.2 AA를 기준으로 한다.** 일반 글자 대비 4.5:1, 큰 글자와 UI 구성요소 3:1, 불투명 2px 포커스 링, 터치 영역 44px 이상, 색만으로 상태를 전달하지 않는다(아이콘과 문구 병행). 색 토큰은 디자인 시스템 정의를 따른다.

**C15. 확장은 자리만 마련한다.** 방(room) 발행/구독 인터페이스, 인증 모듈, AI 호출 모듈, 채팅 필터 인터페이스는 교체할 수 있게 한 곳에 모으되, 지금 필요 없는 구현(Redis, 마이크로서비스, 플러그인 구조, 다중 조직)은 만들지 않는다.

**C16. 스펙에 없는 기능을 구현하지 않는다.** 필요해 보이면 "스펙 변경 제안"으로 돌려보낸다.

**C17. 의존성은 신중히 추가한다.** 신규이거나 소규모인 패키지는 추가하기 전에 다운로드 수와 최신 갱신 시점을 확인하고, 버전을 고정하며 lockfile을 커밋한다.

**C18. main은 언제나 수업에 쓸 수 있는 상태다.** 모든 변경은 PR을 거치고(main에 직접 push하지 않는다), CI의 필수 체크가 통과해야 머지한다. 수업 시간에는 배포하지 않는다. 작업 방식은 `docs/workflow.md`를 따른다.

## 필수 회귀 테스트

구현 중 항상 통과해야 하는 테스트입니다. 해당 기능이 만들어지는 스펙에서 먼저 작성합니다.

- (C2) 학생 채팅, 닉네임, 개인 응답, 주관식 텍스트, 응답 시각을 넣고 공개 내보내기를 실행하면 결과에 그 값이 하나도 없다.
- (C4) 5명 미만 선택지가 단독으로 노출되지 않고, 합계에서 나머지를 빼도 그 값이 복원되지 않는다.
- (C4) 응답이 열려 있는 퀴즈는 정답과 통계가 공개 초안에 포함되지 않는다.
- (C7) 활동 기록과 채팅 테이블에서 이메일이 조회되지 않는다.
- (C9) 신원 조회는 사유 없이 실행되지 않고, 실행되면 로그가 남으며, 교수 외 역할은 접근할 수 없다.

## 미결정 (결정되면 위 원칙으로 옮긴다)

- 학교의 외부 서비스 사용과 개인정보 수집 규정 확인
- 인증 메일 발송 방식과 실패 시 대체 경로의 세부
- 퀴즈 재사용 여부(정답 공개 기본 시점)
- 참여 점수 기준의 구체적 수치(구간, 면제 횟수)
- 다크 테마 색 값
- 배포 대상과 방법(수동 실행, 태그 형식)
