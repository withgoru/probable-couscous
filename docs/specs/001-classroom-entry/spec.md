# 로그인, 강좌, 학생 입장

> 규칙: 이 문서에는 **관찰할 수 있는 동작**만 씁니다. 프레임워크, 테이블, API 경로, 라이브러리 이름은 plan.md에 씁니다.

## 목적

교수가 허용된 GitHub 계정으로 로그인해 강좌와 수강생 명단을 만들고, 학생이 가입 없이 초대 링크와 이메일 인증만으로 닉네임을 받아 강좌에 입장한다.

## 시나리오

### S1. 교수 로그인과 로그아웃
- **누가·언제**: 교수가 수업을 준비하려고 서비스를 열 때.
- **무엇을 제공하나**: GitHub로 로그인하는 화면. 허용 목록에 없는 계정이면 이유와 해결 방법을 알려 주는 오류.
- **완료할 작업**: 로그인해서 내 강좌 화면에 도착한다. 끝나면 로그아웃한다.

### S2. 강좌 만들기와 목록 보기
- **누가·언제**: 교수가 새 강좌를 시작하거나 기존 강좌를 찾을 때.
- **무엇을 제공하나**: 내 강좌 목록(진행 중/보관됨 탭), 새 강좌 만들기 폼.
- **완료할 작업**: 강좌를 만들고, 목록에서 열거나 기록을 본다.

### S3. 강좌 보관
- **누가·언제**: 학기가 끝나 더 이상 학생이 입장할 필요가 없을 때.
- **무엇을 제공하나**: 보관 버튼과 확인 문구, 보관됨 탭.
- **완료할 작업**: 강좌를 보관해 학생 입장을 닫는다. 기록은 볼 수 있다.

### S4. 분반 만들기와 새 학기 복제
- **누가·언제**: 같은 강좌를 다른 분반이나 새 학기에 다시 열 때.
- **무엇을 제공하나**: 강좌 카드의 '분반 만들기', '새 학기로 복제'.
- **완료할 작업**: 수강생 명단과 기록이 비어 있는 새 강좌를 만든다.

### S5. 수강생 명단 관리
- **누가·언제**: 교수가 학기 초에 학생을 등록하거나, 늦게 들어온 학생을 더할 때.
- **무엇을 제공하나**: 관리 페이지의 수강생 명단(CSV 올리기, 학생 추가, 빼기, 로그인 끊기).
- **완료할 작업**: 학번·이름·이메일이 정확한 명단을 만든다. 잘못된 줄은 이유와 함께 확인한다.

### S6. 초대 링크 공유
- **누가·언제**: 교수가 학생에게 입장 방법을 알릴 때.
- **무엇을 제공하나**: 강좌별 초대 링크, 복사 버튼, 다시 만들기.
- **완료할 작업**: 링크를 복사해 학생에게 전달한다.

### S7. 학생 입장
- **누가·언제**: 학생이 초대 링크를 열었을 때(수업 시작 직전에 많은 학생이 한꺼번에 들어올 수 있다).
- **무엇을 제공하나**: 이메일 → 인증 코드 → 채팅 이용 안내(닉네임) 순서의 모바일 화면.
- **완료할 작업**: 가입 없이 닉네임을 받고 강좌에 입장한다.

### S8. 로그인 유지와 다시 입장
- **누가·언제**: 입장한 학생이 같은 기기로 다시 오거나 다른 강좌에 들어갈 때.
- **무엇을 제공하나**: '이 기기에서 로그인 유지' 선택. 유지 중이면 인증 없이 입장.
- **완료할 작업**: 매번 메일을 기다리지 않고 들어온다.

### S9. 명단에 없는 이메일로 입장 요청
- **누가·언제**: 수강신청에 쓴 것과 다른 이메일을 입력한 학생, 또는 명단에 늦게 들어온 학생.
- **무엇을 제공하나**: 안내 문구와 '입장 요청 보내기'. 교수 관리 페이지의 입장 요청 목록.
- **완료할 작업**: 학생이 요청을 보내고, 교수가 승인하거나 거절한다.

### S10. 인증 메일이 안 올 때 (대체 경로)
- **누가·언제**: 인증 메일이 늦거나 오지 않아 학생이 입장하지 못할 때.
- **무엇을 제공하나**: 학생 화면의 '교수님께 알리기', 교수 관리 페이지의 '대기 중인 인증' 목록(코드 포함).
- **완료할 작업**: 교수가 학생에게 코드를 알려 주고, 학생이 코드를 요청한 기기에서 입력해 입장한다. 수업은 멈추지 않는다.

### S11. 마이페이지에서 내 강좌 요약 보기
- **누가·언제**: 교수가 현재 진행 중인 강좌를 한눈에 보고 싶을 때.
- **무엇을 제공하나**: @GitHub 계정, 진행 중·보관된 강좌 수, 진행 중 수강생 합계, 진행 중 강좌 목록.
- **완료할 작업**: 요약을 보고 강좌를 연다.

## 수용 기준

번호를 붙입니다. tasks.md가 이 번호로 대응합니다. 각 항목은 사람이 화면에서 확인할 수 있는 문장이어야 합니다.

### 교수 로그인 (S1)
- [ ] AC1. 로그인 화면에 'GitHub로 로그인' 버튼이 있고, 허용 목록에 있는 계정으로 로그인하면 내 강좌 화면이 열린다.
- [ ] AC2. 허용 목록에 없는 계정이면 로그인되지 않고 "이 GitHub 계정은 사용할 수 없습니다 / 허용 목록에 없는 계정입니다. 허용된 계정으로 다시 로그인해 주세요."가 보인다.
- [ ] AC3. 로그인하지 않은 채 내 강좌나 관리 페이지 주소를 열면 로그인 화면으로 이동한다.
- [ ] AC4. 로그인 후 모든 화면의 오른쪽 위 계정 메뉴에 @GitHub 계정, 마이페이지, 로그아웃이 있다. 로그아웃하면 로그인 화면으로 가고, 뒤로 가기를 눌러도 내 강좌가 보이지 않는다.

### 강좌 만들기와 목록 (S2)
- [ ] AC5. '새 강좌 만들기'에서 강좌 이름을 입력하고(분반 이름은 선택) 만들면, 진행 중 목록 맨 앞에 새 강좌가 나타난다.
- [ ] AC6. 강좌 이름이 비어 있으면 '만들기' 버튼을 누를 수 없고, 그 이유("강좌 이름을 입력해 주세요")가 글로 보인다.
- [ ] AC7. 목록에 '진행 중 N / 보관됨 N' 탭이 있다. 강좌 카드에는 이름, 분반, 상태 배지(문구 포함), 수강생 수가 보이고, 진행 중 강좌는 '열기', 보관된 강좌는 '기록 보기' 버튼이 있다.
- [ ] AC8. 교수에게는 자기가 만든 강좌만 보인다. 다른 교수의 강좌 주소를 열어도 열리지 않고 "이 강좌를 볼 권한이 없습니다"가 보인다.

### 강좌 보관 (S3)
- [ ] AC9. 진행 중 강좌에서 '보관'을 누르면 "보관하면 학생이 더 이상 입장할 수 없고 모든 학생의 로그인 유지가 끝납니다. 기록은 볼 수 있습니다." 확인 문구가 나오고, 확인하면 그 강좌가 보관됨 탭으로 옮겨진다.
- [ ] AC10. 보관된 강좌의 초대 링크를 학생이 열면 "이 강좌는 보관되었습니다. 교수님께 문의해 주세요."가 보이고 입장할 수 없다. 로그인 유지 중이던 학생도 같은 안내가 보인다.

### 분반 만들기와 복제 (S4)
- [ ] AC11. 강좌 카드의 '분반 만들기' 또는 '새 학기로 복제'를 누르면 새 강좌의 이름과 분반 이름을 확인·수정하는 폼이 열리고, 만들면 새 강좌가 진행 중 목록에 나타난다.
- [ ] AC12. 복제로 만든 강좌의 수강생 명단, 입장 기록, 초대 링크는 원래 강좌와 별개이며 처음에는 비어 있다(링크는 새로 만들어진다).

### 수강생 명단 (S5)
- [ ] AC13. 관리 페이지의 '수강생 명단'에서 CSV 파일(첫 줄에 제목, 열은 학번·이름·이메일)을 올리면 "N명 추가, M줄 건너뜀"이 보이고, 추가된 학생이 명단에 나타난다.
- [ ] AC14. 건너뛴 줄은 줄 번호와 이유(이메일 형식 오류, 이메일 중복, 학번 중복, 빈 칸)가 목록으로 보이고, 올바른 줄만 등록된다.
- [ ] AC15. '학생 추가'에서 학번, 이름, 이메일을 입력해 한 명씩 추가할 수 있고, 올릴 때와 같은 검사를 받는다. 오류는 입력 칸 옆에 글로 보인다.
- [ ] AC16. 이메일은 앞뒤 공백과 대소문자를 무시하고 같은 이메일로 본다(`Kim@Example.com `과 `kim@example.com`은 중복).
- [ ] AC17. 명단 표에는 학번, 이름, 이메일, 입장 상태(입장 전/입장함)가 보인다. **닉네임은 표시되지 않는다.**
- [ ] AC18. 한 강좌의 명단은 200명까지 등록할 수 있다. 넘으면 "명단은 200명까지 등록할 수 있습니다. N명을 줄여 다시 올려 주세요."가 보이고 아무도 추가되지 않는다.
- [ ] AC19. 명단에서 학생을 '빼기'하면 확인 문구 후 명단에서 사라지고, 그 학생은 이 강좌에 더 이상 입장할 수 없으며 로그인 유지도 끝난다.
- [ ] AC20. 명단에서 학생의 '로그인 끊기'를 누르면 그 학생의 모든 기기가 이 강좌에서 로그아웃되고, 다시 들어오려면 이메일 인증이 필요하다. 다시 입장해도 닉네임은 같다.

### 초대 링크 (S6)
- [ ] AC21. 관리 페이지에 이 강좌의 초대 링크와 '복사' 버튼이 있고, 누르면 "복사했습니다"가 보인다.
- [ ] AC22. '링크 다시 만들기'를 누르면 새 링크가 보이고, 이전 링크를 열면 "이 링크는 더 이상 사용할 수 없습니다. 교수님께 새 링크를 받으세요."가 보인다.
- [ ] AC23. 링크를 열기만 해서는 입장되지 않는다. 학생은 이메일 인증을 거쳐야 한다(링크가 새어도 명단 밖 사람은 들어올 수 없다).

### 학생 입장 (S7)
- [ ] AC24. 초대 링크를 열면 "수강생 명단에 있는 이메일로 입장합니다. 가입은 필요 없습니다."와 이메일 입력 칸, '인증 코드 받기' 버튼이 보인다. 형식이 틀리면 "이메일 형식을 확인해 주세요."가 보인다.
- [ ] AC25. 명단에 있는 이메일로 '인증 코드 받기'를 누르면 그 이메일로 6자리 코드 메일이 가고, 화면은 코드 입력 단계로 바뀐다. 코드는 이 화면을 연 기기에서 입력해야 한다는 안내가 보인다.
- [ ] AC26. 코드 입력 단계에는 6자리 입력 칸, '이 기기에서 로그인 유지' 체크(처음부터 켜져 있음), '확인하고 계속' 버튼이 있다.
- [ ] AC27. 코드가 맞으면 채팅 이용 안내 화면이 나온다. 이 화면에는 닉네임 카드(자동으로 정해진 닉네임)와 안내 3줄이 있다: 다른 학생에게는 닉네임으로만 보인다 / 교수님은 심각한 사안에 한해 사유를 기록하고 작성자를 확인할 수 있다 / 채팅 내용은 참여 점수에 반영되지 않고 공개되지 않는다. '익명'이라는 말은 쓰지 않는다.
- [ ] AC28. '확인하고 입장'을 누르면 입장이 끝나고, 그 강좌 이름과 내 닉네임이 보이는 화면이 열린다.
- [ ] AC29. 닉네임은 같은 강좌에서 다른 학생과 겹치지 않는다. 한 번 받은 닉네임은 같은 강좌에 다시 들어와도 같고, 학생이 직접 바꿀 수 없다. 다른 강좌에서는 다른 닉네임을 받는다.
- [ ] AC30. 코드를 틀리면 "코드가 맞지 않습니다. N번 더 입력할 수 있습니다."가 보이고, 5번 틀리면 그 코드는 쓸 수 없게 되며 "코드를 다시 받아 주세요."가 보인다.
- [ ] AC31. 코드는 받은 지 10분이 지나면 "코드가 만료되었습니다. 코드를 다시 받아 주세요."와 함께 쓸 수 없다.
- [ ] AC32. '코드 다시 받기'는 직전 요청 60초 뒤부터 누를 수 있고, 그 전에는 누를 수 없으며 남은 초가 글로 보인다. 새 코드를 받으면 이전 코드는 쓸 수 없다.
- [ ] AC33. 인증 코드는 코드를 요청한 기기에서만 쓸 수 있다. 다른 기기에서 같은 코드를 입력하면 "코드가 맞지 않습니다"와 같은 문구가 보이고, 요청한 기기의 코드와 남은 입력 횟수에는 영향이 없다. 브라우저 데이터를 지우거나 다른 브라우저로 바꾸면 새 기기로 보므로 그 기기에서 코드를 다시 받아야 한다.
- [ ] AC34. 같은 이메일로 이 강좌에 다시 입장해도 명단의 같은 학생으로 연결된다(학생이 두 번 등록되지 않는다).

### 로그인 유지 (S8)
- [ ] AC35. '로그인 유지'를 켠 채 입장한 학생은 같은 기기에서 같은 강좌 링크를 다시 열면 이메일·코드 입력 없이 바로 입장한다. 이 상태는 강좌가 보관되기 전까지 이어진다.
- [ ] AC36. '로그인 유지'를 끄고 입장한 학생은 브라우저를 닫았다 다시 열면 이메일 인증부터 다시 한다.
- [ ] AC37. 이미 인증된 기기로 같은 학생이 다른 강좌의 초대 링크를 열면, 그 강좌 명단에 있을 때 이메일·코드 입력 없이 채팅 이용 안내 화면으로 간다. 그 강좌의 닉네임은 새로 받는다.

### 명단에 없는 이메일 (S9)
- [ ] AC38. 명단에 없는 이메일을 입력하면 인증 코드 메일을 보내지 않고 "수강생 명단에 없는 이메일입니다. 수강신청에 쓴 이메일인지 확인하고, 계속 안 되면 교수님께 입장을 요청해 주세요."와 '입장 요청 보내기' 버튼이 보인다.

## 오류와 예외 동작

- **인증 메일 지연·미도착**: 학생은 '코드 다시 받기'(60초 간격)나 '교수님께 알리기'를 쓴다. 교수는 관리 페이지에서 코드를 확인해 알려 준다(S10). 이 경로가 있어 메일이 안 와도 수업이 멈추지 않는다(C12).
- **다른 기기에서 코드 입력**: "코드가 맞지 않습니다"로만 보이고 원래 기기의 입장에는 영향이 없다. 정상 학생은 입장하려던 기기에서 코드를 입력하거나 그 기기에서 '코드 다시 받기'를 한다.
- **명단 오류**: CSV에서 잘못된 줄은 건너뛰고 이유를 보여 준다. 올바른 줄은 등록된다. 파일을 읽을 수 없거나 한글이 깨져 보이면 "파일을 읽을 수 없습니다. UTF-8 CSV로 저장해 다시 올려 주세요."가 보인다.
- **입력 중 연결 끊김**: 학생이 코드를 입력하다 연결이 끊기면 입력한 이메일은 유지되고 "연결이 끊겼습니다. 다시 연결되면 이어서 진행합니다."가 보인다. 연결이 돌아오면 같은 단계에서 계속한다.
- **서버를 다시 시작했을 때**: 로그인 유지 중인 학생과 교수 로그인, 명단, 닉네임, 입장 요청, 대기 중인 인증이 그대로 남는다(C13).
- **보관·빼기·링크 재생성 뒤 접속**: 해당 학생이나 링크를 쓰는 사람에게는 이유와 다음 행동(교수님께 문의, 새 링크 받기)을 문구로 알려 준다.
- **권한 없음**: 로그인하지 않았거나 내 강좌가 아니면 내용을 보여 주지 않고 이유를 알려 준다.

## constitution 영향

- C5: 명단, 닉네임, 입장 요청, 로그인 유지, 초대 링크는 모두 강좌(강의실) 단위로 구분한다. AC8, AC12, AC37.
- C6: 승인·거절, 코드 열람, 빼기, 로그인 끊기는 수정·삭제할 수 없는 기록으로 쌓는다. AC48.
- C7: 계정(이메일)과 강좌 멤버십(닉네임)을 분리하고, 닉네임은 강좌마다 따로 받는다. 명단 화면에 닉네임을 두지 않는다. AC17, AC29, AC37.
- C8: 강좌 접근, 명단 관리, 코드 열람 권한은 한 곳의 권한 판단을 거친다(구현은 plan). 화면은 권한 없음을 보여 줄 뿐이다. AC8.
- C9: 닉네임과 실명을 잇는 정보는 교수 화면에 보이지 않는다. 대기 중인 인증에도 닉네임은 없다. AC17, AC45.
- C10: 채팅 이용 안내는 "익명"이라고 약속하지 않고 실제 구조를 그대로 안내한다. AC27.
- C11: 수집은 학번·이름·이메일로 한정하고, 입장 요청은 이름·학번·이메일만 받는다. 강좌 보관 후 6개월에 삭제한다(학교 규정 확인은 미결정).
- C12: 인증 메일이 안 와도 교수가 코드를 알려 입장시킬 수 있다. 명단에 없는 학생도 입장 요청 경로가 있다. AC38~AC47.
- C13: 명단, 입장 요청, 입장 상태는 연결 상태가 아니라 저장된 값이 진실이며 서버를 다시 시작해도 남는다.
- C14: AC50, AC51에서 라벨, 글로 된 오류, 포커스 링, 44px, 키보드 조작, 색만으로 전달하지 않기를 확인한다.
- C16: 설정, 출석, 채팅, 보관 해제 등 이 스펙에 없는 기능은 범위 밖에 적었다.
