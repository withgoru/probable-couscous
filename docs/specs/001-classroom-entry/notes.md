## 위험 1. 200명 동시 코드 요청 (2026-11-22)

**방법**: `server/scripts/load_codes.py --students 200`

- 실제 서버 프로세스를 띄운다. E2E 전용 서버 `client/e2e/server.py`로 uvicorn 1개, SQLite WAL과 `synchronous=FULL`, 메일은 메모리이고 메일 작업 스레드는 켜져 있다.
- 명단 200명을 CSV로 올리고, 학생마다 다른 기기(쿠키)로 링크를 연다.
- 200명이 **같은 순간에** '인증 코드 받기'(`POST /api/join/{토큰}/email`)를 보낸다.
- 유실은 두 가지를 더한 것이다. 성공 응답(`next: code`)을 받지 못한 요청, 그리고 성공이라고 답했는데 DB에 챌린지가 남지 않은 요청이다.
- 측정 환경: Apple M5(10코어), macOS, Python 3.14.2. **서버와 학생 200명이 같은 컴퓨터에 있다**(서로 CPU를 나눠 쓰므로 실제보다 불리한 쪽이다).

| 실행 | p50 | p95 | 최대 | 유실 | 저장된 챌린지 | 메일 200통이 다 나가기까지 |
|---|---|---|---|---|---|---|
| 1 | 164ms | 296ms | 833ms | 0 | 200 | 31.2초 |
| 2 | 156ms | 283ms | 697ms | 0 | 200 | 31.2초 |
| 3 | 162ms | 357ms | 824ms | 0 | 200 | 30.7초 |

**판정: 통과.** 성공 기준(유실 0)을 세 번 모두 만족했다. 가장 늦은 학생도 1초 안에 코드 입력 화면으로 넘어간다.

- 메일 시간은 메모리 메일함(보내는 데 시간이 들지 않음) 기준이다. 초당 8건 상한이면 이론값은 25초이고, 작업 스레드의 대기 간격 때문에 31초쯤 걸렸다. 실제 서비스의 응답 시간은 위험 2에서 본다.
- 다시 재려면: `cd server && .venv/bin/python scripts/load_codes.py --students 200` (`--json`으로 숫자만 받을 수 있다. 유실이 있으면 종료 코드 1)

## 위험 2. 메일 도착 시간 (일부 확인, 2026-11-22)

### 발견: 메일 작업 스레드가 한 통씩 차례로 보내서, 서비스 응답이 느리면 초당 8건에 못 미친다

실제 `ResendMailer`를, 응답을 일부러 늦추는 가짜 Resend 서버에 붙여 200통을 보냈다(같은 컴퓨터, 실험 코드는 버림).

| 서비스 응답 지연(가정) | 200통이 다 나가기까지 |
|---|---|
| 0ms | 29.8초 |
| 100ms | 26.5초 |
| 200ms | 46.4초 |
| 300ms | 66.3초 |

- 한 통을 보내는 데 걸리는 시간이 곧 간격이 된다. 응답이 200ms면 초당 5통쯤, 300ms면 3통쯤이다. plan이 제안한 기준(도착 p95 60초 이내)은 응답이 300ms 근처면 발송만으로도 넘는다.
- 실제 Resend의 응답 시간은 모른다(한국에서 측정 필요). **고칠 방법**: 상한(초당 8건)을 지키면서 몇 통을 동시에 보내게 하는 것. `MailWorker` 안의 구현 변경이고 스펙 동작은 바뀌지 않는다. → 따로 진행할지 사용자에게 묻는다.
- 그동안에도 메일이 늦은 학생은 '교수님께 알리기'로 입장할 수 있다(C12).

### 사용자 확인 절차 (실제 메일)

준비물은 다음과 같다.
- Resend에서 인증한 도메인
- `.env`의 `RESEND_API_KEY`, `MAIL_FROM`(인증한 도메인 주소)
- 200통을 보내려면 Pro 플랜(무료는 하루 100통)
- 받을 학교 메일 주소 여러 개(가능하면 학교 도메인 3곳 이상)

1. 서버를 실제 설정으로 띄우고, 받을 주소들로 명단을 만든다(테스트 강좌).
2. 학생 화면에서 각 주소로 '인증 코드 받기'를 누른 시각과 메일을 받은 시각을 적는다. 받은편지함인지 스팸함인지도 적는다.
3. 아래 표에 채운다. 기준(제안): 도착 p95 60초 이내, 스팸함 0건.

아래 세 줄은 **채우는 방법을 보이는 예시**다(측정값이 아니다). 실제로 잰 값으로 바꾸고, 예시 줄은 지운다.
도착 시간은 '인증 코드 받기'를 누른 시각부터 메일이 받은편지함(또는 스팸함)에 보인 시각까지다.

| 날짜 | 받는 도메인 | 통수 | 도착 p50 | 도착 p95 | 가장 늦게 | 스팸함 | 메모 |
|---|---|---|---|---|---|---|---|
| (예시) 2026-11-24 | 학교 메일 (`○○.ac.kr`) | 10 | 6초 | 14초 | 18초 | 0 | (예시) 무료 플랜, Tokyo 리전, DMARC p=none |
| (예시) 2026-11-24 | `gmail.com` | 5 | 4초 | 9초 | 11초 | 1 | (예시) 첫 통이 스팸함, '스팸 아님' 뒤로는 받은편지함 |
| (예시) 2026-11-24 | `naver.com` | 5 | 5초 | 12초 | 12초 | 0 | (예시) 제목에 코드가 보여 알림만으로 확인 가능 |

## 위험 5. 한국어 엑셀 CSV (동작 확인, 2026-11-22)

엑셀이 저장하는 두 방식과 같은 바이트(줄바꿈 CRLF, 쉼표가 든 이름은 따옴표)를 만들어 실제 앱에 올렸다.

| 엑셀 저장 방식 | 결과 |
|---|---|
| CSV UTF-8(쉼표로 분리): UTF-8 + BOM + CRLF | 3명 모두 등록(따옴표 안의 "박, 민수"도 그대로) |
| CSV(쉼표로 분리): CP949 + CRLF | 아무도 등록하지 않고 "파일을 읽을 수 없습니다. UTF-8 CSV로 저장해 다시 올려 주세요." |

- 같은 내용은 자동 테스트로도 고정돼 있다(`test_roster_import.py`의 BOM·CRLF·따옴표와 CP949 테스트).
- **남은 것**: 실제 엑셀(Windows·Mac)에서 두 방식으로 저장한 파일로 한 번 올려 보기. 샘플 파일을 주면 자동 테스트에 넣을 수 있다.
