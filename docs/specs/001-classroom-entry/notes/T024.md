# T024 구현 노트: 학생 빼기와 로그인 끊기 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC19: 빼면 명단에서 사라지고, 이 강좌에 더 이상 입장할 수 없으며, **로그인 유지도 끝난다**.
- AC20: 끊으면 그 학생의 **모든 기기가 이 강좌에서** 로그아웃되고, 다시 들어오려면 이메일 인증이 필요하며, 닉네임은 같다.
- AC48: 빼기·끊기는 누가·언제·어느 학생인지와 함께 수정·삭제할 수 없는 기록으로 남는다.
- plan: `DELETE /classrooms/{id}/roster/{entry}`, `POST /classrooms/{id}/roster/{entry}/revoke-login`, 권한 `roster.manage`, `memberships.reverify_after`(끊은 시각), 기록 종류 `roster_removed`, `login_revoked`.

## 내가 정한 것 (스펙 밖)

1. **끊기는 `device_logins`를 폐기하지 않고 `reverify_after`만 적는다.** 기기 로그인은 계정 단위라 여러 강좌가 같이 쓴다(AC37). 폐기하면 다른 강좌에서도 로그아웃된다. AC20은 "이 강좌에서"라서 강좌별 멤버십의 `reverify_after`만 바꾼다. 입장 검사(T020의 `_fresh_login`)가 이미 이 값을 본다.
2. **빼기도 같은 `reverify_after`를 적는다.** "로그인 유지도 끝난다"를 이렇게 읽었다. 빼고 나서 실수로 다시 넣어도 예전 기기로 바로 들어오지 못하고 코드부터 받는다. 닉네임은 그대로다(멤버십을 지우지 않는다).
3. **빼기는 행을 지우지 않고 `removed_at`만 적는다**(plan의 열 그대로). `events.subject_roster_entry_id`가 가리킬 대상이 남아야 하고, 실제 삭제는 보관 6개월 뒤 정리 작업(T031)이 한다.
4. **뺄 때 그 학생이 받아 둔 코드를 모두 `superseded`로 바꾼다.** 이렇게 하지 않으면 뺐다가 10분 안에 다시 넣었을 때 예전 코드가 다시 쓰이고, 교수의 '대기 중인 인증' 목록에도 다시 나타난다. 이제는 가장 최근 코드가 `superseded`일 수 있어서, 코드 확인이 이 경우에 "이 코드는 더 이상 쓸 수 없습니다. 코드를 다시 받아 주세요."를 준다(결과 종류는 `expired`. 학생이 할 일은 똑같이 다시 받기다).
5. **입장한 적 없는 학생의 끊기는 409** "아직 입장하지 않은 학생입니다. 끊을 로그인이 없습니다."이고, 기록을 남기지 않는다. 명단의 `entered`(멤버십이 있는지)와 같은 기준이라 T030 화면은 입장한 학생에게만 버튼을 보이면 된다.
   - 걸리는 점: 다른 강좌에서 로그인한 기기로 이 강좌 링크를 처음 열면 코드 없이 들어온다(AC37). 이건 "끊긴 로그인이 되살아난 것"이 아니라 처음 입장이라 막지 않았다.
6. **같은 학생을 두 번 끊어도 된다.** 매번 기록하고 `reverify_after`는 마지막 시각으로 바뀐다.
7. **없는 항목, 이미 뺀 항목, 다른 강좌의 항목은 모두 같은 404**다. "명단에서 찾을 수 없는 학생입니다. 명단을 새로 불러와 확인해 주세요."
8. **기록 내용(`payload`)은 비어 있다(`{}`).** 어느 학생인지는 `subject_roster_entry_id`가 말한다. 닉네임·멤버십 번호는 넣지 않는다(기록에서 닉네임과 사람을 잇지 않으려고, C9).
9. **보관된 강좌에서도 소유자는 빼기·끊기를 할 수 있다.** `roster.manage`가 이미 그렇게 판단한다. 보관 뒤 정리가 막힐 이유가 없다.
10. **실시간 알림**: 빼면 `roster.updated`, 그 학생이 '교수님께 알리기'를 해 둔 코드가 있으면 그 번호로 `pending_auth.updated`도 보낸다(목록에서 사라지므로). 끊기는 바뀌는 목록이 없어 알리지 않는다.
11. `member_identities`는 여전히 `identity` 모듈만 읽는다(C9). 새 함수 `identity.cut_login`이 명단 항목으로 멤버십을 찾아 `reverify_after`를 적는다.

## 일부러 하지 않는 것

- 화면(확인 문구, 표 갱신)은 T030이다.
- 빼거나 끊은 학생이 접속했을 때의 학생 화면 문구는 T026~T028이다. 서버는 이미 있는 응답(`login` 상태, 403 명단 없음, `request_access`)을 그대로 쓴다.
- 이 학생의 입장 요청(`join_requests`)은 건드리지 않는다. 뺀 뒤에 다시 요청할 수 있다(T021 테스트 그대로).
