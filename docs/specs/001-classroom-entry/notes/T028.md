# T028 구현 노트: 학생 화면 3 (채팅 이용 안내와 입장 완료)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC27: 닉네임 카드와 안내 3줄(닉네임으로만 보임 / 교수님은 심각한 사안에 한해 사유를 기록하고 작성자를 확인 / 참여 점수에 반영되지 않고 공개되지 않음). '익명'이라는 말은 쓰지 않는다.
- AC28: '확인하고 입장' 뒤 강좌 이름과 내 닉네임이 보이는 화면.
- AC29: 닉네임은 학생이 바꿀 수 없다.
- AC35, AC37: 로그인 유지 중인 기기는 이메일·코드 없이 입장하고, 다른 강좌에서는 안내 화면으로 바로 간다(새 닉네임).
- 서버는 T020에 이미 있다(`/me`, `/enter`). 이번 작업은 화면만 만든다.

## 내가 정한 것 (스펙 밖)

1. **안내 3줄은 AC27 문장을 그대로 쓰고 끝맺음만 존댓말로 바꿨다.** "다른 학생에게는 닉네임으로만 보입니다." / "교수님은 심각한 사안에 한해 사유를 기록하고 작성자를 확인할 수 있습니다." / "채팅 내용은 참여 점수에 반영되지 않고 공개되지 않습니다." 목업의 첫 줄에는 "다른 학생은 작성자를 알 수 없습니다."가 덧붙어 있지만 스펙 문장에 없어서 넣지 않았다. 아이콘은 목업과 같다(eye-closed, key, shield-check. 모두 꾸밈).
2. **안내 화면 제목은 "입장하기 전에 확인해 주세요"**로 했다. 목업의 "3주차 1회차에 입장합니다"는 회차(002)가 있어야 쓸 수 있다. 제목 위에는 강좌 이름(분반 포함)을 둔다.
3. **닉네임 카드는 따로 뺐다(`NicknameCard`).** 안내 화면과 입장 완료 화면이 같이 쓴다. 첫 글자 동그라미는 꾸밈이라 읽어 주지 않는다. 닉네임을 바꾸는 칸이나 버튼은 없다(AC29).
4. **입장 완료 화면**은 "입장했습니다"(성공 글자색과 체크 아이콘), 강좌 이름(분반 포함), 닉네임 카드만 보인다. 수업 화면(출석, 슬라이드, 채팅)은 002~004에서 이 자리에 이어진다. 할 일이 없으므로 버튼도 없다.
   - 강좌 이름은 서버의 입장 응답(이름만 있음)을 쓰지 않고, 링크를 열 때 받은 이름(분반 포함)을 쓴다. 실제 화면에서 보니 안내 화면은 "웹 프로그래밍 · 월수반"인데 완료 화면은 "웹 프로그래밍"이라 어긋났기 때문이다.
5. **로그인 유지는 화면을 열 때(load) 서버의 `/me`로 판단한다.** 링크 열기가 기기 쿠키를 심으므로 그 다음에 묻는다. `notice`면 안내 화면, `entered`면 입장 완료 화면으로 바로 시작한다. `/me`가 실패하면(서버 오류, 연결 문제) 막지 않고 이메일 단계부터 시작한다. 그사이 보관됐으면(403) 닫힌 화면을 보인다.
6. **'확인하고 입장' 실패 처리**:
   - 401(그사이 로그인이 끊겼거나 끝남, AC20): 이메일 단계로 돌아가 서버 안내를 보인다. 이메일은 그대로 남는다.
   - 403/404(보관, 명단에서 빠짐, 링크 폐기): 서버 안내로 "입장할 수 없습니다" 화면을 보인다.
   - 연결 문제: 버튼 위에 "입장하지 못했습니다. 네트워크 연결을 확인하고 다시 시도해 주세요."를 보이고, 다시 누를 수 있다.
7. 단계가 바뀌면 새 제목으로 포커스를 옮긴다(T026과 같다).

## 테스트 쪽에서 고친 것

- `beforeEach(() => mock.mockReset())`처럼 함수를 **돌려주는** 형태는 vitest가 정리 함수로 여겨 테스트 뒤에 그 mock을 한 번 더 부른다. 이번 `NoticeStep.test.ts`에서는 거부하는 mock이 다시 불려 테스트가 실패했다. T026의 `join.test.ts`에도 같은 모양이 두 곳 있었다(그쪽은 성공하는 mock이라 드러나지 않았다). 모두 중괄호로 바꿨다.

## 확인한 것

- 테스트: `NoticeStep.test.ts` 13개(안내 3줄 문장 그대로, '익명' 없음, 닉네임 변경 없음, 입장 성공과 실패 4종), `join.test.ts`에 안내→입장 4개와 로그인 유지·다른 강좌 3개, `join-load.test.ts`에 상태 확인 5개, `api.test.ts`에 3개를 더했다. 클라이언트 전체 324개와 `svelte-check`가 통과한다.
- 실제 화면(가짜 로그인 서버, 앱 안 브라우저, 375px):
  - 인증한 기기로 링크를 열면 바로 안내 화면이 나온다.
  - '확인하고 입장'을 누르면 입장 완료 화면이 나온다.
  - 다시 열면 바로 입장 완료 화면이다(AC35).
  - 같은 기기로 다른 강좌 링크를 열면 이메일 없이 안내 화면과 새 닉네임이 나온다(AC37).
  - 교수가 로그인을 끊은 뒤 다시 열면 이메일 단계로 돌아가고, 다른 강좌는 그대로다(AC20, T024).
