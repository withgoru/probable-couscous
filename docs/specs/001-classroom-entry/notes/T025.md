# T025 구현 노트: 강좌 보관 (서버와 확인 화면)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC9: 진행 중 강좌에서 '보관'을 누르면 확인 문구가 나온다("보관하면 학생이 더 이상 입장할 수 없고 모든 학생의 로그인 유지가 끝납니다. 기록은 볼 수 있습니다."). 확인하면 그 강좌가 보관됨 탭으로 옮겨진다.
- AC10: 보관된 강좌의 초대 링크를 열면 "이 강좌는 보관되었습니다. 교수님께 문의해 주세요."가 보이고 입장할 수 없다. 로그인 유지 중이던 학생도 같은 안내를 본다.
- plan: `POST /classrooms/{id}/archive`, 기록 종류 `classroom_archived`. 보관 해제는 범위 밖이다(C16).

## 내가 정한 것 (스펙 밖)

### 서버

1. **권한은 `classroom.manage`**다(소유자 전용, plan의 행동 목록 그대로).
2. **학생 차단은 이미 있는 `student.enter` 판단에 맡긴다.** 이 판단은 보관된 강좌를 이미 막고 있고(T018~T020), 로그인 유지 중인 기기도 같은 길을 지나서 같은 안내를 받는다. `device_logins`는 폐기하지 않는다. 기기 로그인은 여러 강좌가 같이 쓰므로, 폐기하면 다른 강좌에서도 로그아웃된다(T024와 같은 이유).
3. **보관하면 이 강좌에서 아직 쓰지 않은 코드를 모두 `superseded`로 바꾼다.** 그러면 아직 보내지 않은 코드 메일도 발송 작업이 버린다(낡은 코드라 보내지 않고, 수신 주소를 비운다. C11). 보관된 강좌의 코드가 메일로 나갈 이유가 없다.
4. **이미 보관된 강좌를 다시 보관하면 409** "이미 보관된 강좌입니다."를 주고, 보관 시각을 바꾸지 않는다. 보관 시각은 6개월 정리(T031)의 기준이라서 다시 눌렀다고 늦춰지면 안 된다. 기록도 처음 한 번만 남는다.
5. **기록 내용은 비어 있다(`{}`)**. 대상 학생이 없으니 `subject_roster_entry_id`도 비어 있다.
6. 응답은 목록 카드와 같은 모양의 강좌 하나다(`status: archived`).

### 화면

7. **'보관' 버튼은 내 강좌 목록의 진행 중 카드에 둔다.** 목업은 위치를 정하지 않았다. AC9의 "보관됨 탭으로 옮겨진다"가 목록 화면을 가리키므로 목록에 두었다. 버튼은 다른 두 버튼보다 눈에 덜 띄게 글자만 있는 버튼(`btn-ghost`)이고, 글자색은 destructive 글자색(#b82a4d)이다. 같은 이름의 버튼이 카드마다 있어서 접근 이름은 "보관: 강좌 이름 (분반)"이다(분반 만들기 버튼과 같은 방식).
8. **확인 창은 bits-ui의 AlertDialog**를 쓴다(이미 설치된 의존성이고, shadcn-svelte가 쓰는 것과 같다. 새 의존성 없음). 제목은 "{강좌 이름 (분반)} 강좌를 보관할까요?"이고, 본문은 AC9 문구를 그대로 쓴다. 제목에 '강좌를'을 붙인 이유: 이름 끝 글자에 받침이 있는지에 따라 '을/를'이 바뀌어 틀리기 쉽기 때문이다.
9. **창이 열리면 포커스는 '취소'에 간다.** 보관은 되돌릴 수 없어서 Enter를 실수로 눌러도 보관되지 않게 했다. '보관' 버튼은 destructive 채움색이다.
10. **확인한 뒤**에는 목록을 다시 불러오고, 보관됨 탭으로 옮기고, "강좌를 보관했습니다: 이름"을 알린다. 포커스는 보관됨 탭에 둔다(눌렀던 카드는 진행 중 목록에서 사라졌다). **취소나 Esc**를 누르면 창을 닫고 포커스를 눌렀던 '보관' 버튼으로 돌려준다.
11. **오류는 창 안에 보이고 창은 그대로 둔다.** 409(다른 창에서 이미 보관함)는 목록을 다시 불러오고 "보관됨 탭에서 확인하세요."를 덧붙인다. 그 밖의 서버 오류에는 "잠시 뒤 다시 시도해 주세요.", 연결 오류에는 강좌 만들기와 같은 문구("…네트워크 연결을 확인하고 다시 시도해 주세요.")를 붙인다. 보관하는 동안에는 두 버튼 모두 누를 수 없다.

## 확인한 것

- 서버: `test_classroom_archive.py` 15개. 서버 전체 테스트, constitution 테스트, ruff 모두 통과. 서버 쪽 변형 6개는 모두 테스트가 잡았다.
- 화면: `courses.test.ts`에 10개를 추가했다. 클라이언트 전체 193개와 `svelte-check`가 통과한다.
- 실제 화면: 가짜 로그인으로 서버를 띄워 앱 안 브라우저에서 확인했다. 확인 → 보관됨 탭 이동과 알림, 키보드만으로 열기·이동·확인(창 안에서 포커스가 맴돈다), Esc로 닫으면 포커스 복귀, 두 버튼과 카드의 '보관' 버튼 높이 44px, 포커스 링(2px, 간격 2px), 390px 폭에서 가로 스크롤 없음(작은 화면에서는 '보관'이 위, '취소'가 아래에 꽉 차게 놓인다).

## 일부러 하지 않는 것

- 보관 해제(스펙 범위 밖, 미결정 항목).
- 관리 페이지(기록 보기)에 '보관' 버튼을 두는 것. 목록에만 둔다.
- 보관된 강좌의 관리 페이지에서 명단 추가·CSV·초대 링크 같은 변경 버튼을 숨기는 것. 서버도 소유자에게 허용한다(`roster.manage`). **사용자 결정(2026-11-22): 지금처럼 허용한다.**
- 교수 관리 화면 실시간 알림. 보관은 목록 화면에서 일어나고 그 화면은 직접 다시 불러온다.
