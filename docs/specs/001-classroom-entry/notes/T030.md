# T030 구현 노트: 명단 화면 확장 (빼기와 로그인 끊기)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC19: '빼기'하면 확인 문구 후 명단에서 사라지고, 그 학생은 입장할 수 없으며 로그인 유지도 끝난다.
- AC20: '로그인 끊기'를 누르면 그 학생의 모든 기기가 이 강좌에서 로그아웃되고, 다시 들어오려면 이메일 인증이 필요하며, 닉네임은 같다.
- tasks: 빼기와 로그인 끊기의 확인 문구, 실행 뒤 표 갱신. 서버는 T024에 있다.

## 내가 정한 것 (스펙 밖)

1. **명단 표에 '관리' 열을 더하고 학생마다 '빼기'를 둔다. '로그인 끊기'는 입장한 학생에게만 둔다.** 입장한 적 없는 학생은 끊을 로그인이 없다(서버도 409를 준다, T024). 같은 이름의 버튼이 줄마다 있어서 접근 이름은 "빼기: 이름 (학번)", "로그인 끊기: 이름 (학번)"이다. 빼기 글자는 destructive 글자색이다.
2. **둘 다 확인 창을 거친다.** AC19는 확인 문구를 요구하고, 로그인 끊기도 학생의 모든 기기를 로그아웃시켜 되돌릴 수 없어서 같게 했다. 확인 창 문구는 다음과 같다.
   - 빼기: "{이름 (학번)} 학생을 명단에서 뺄까요?" / "빼면 이 학생은 이 강좌에 입장할 수 없고 로그인 유지도 끝납니다. 다시 추가하면 이메일 인증을 거쳐 같은 닉네임으로 입장합니다." 뒷문장은 T024에서 정한 동작(다시 넣으면 코드부터, 닉네임은 같음)을 교수에게 알려 준다.
   - 로그인 끊기: "{이름 (학번)} 학생의 로그인을 끊을까요?" / "이 학생의 모든 기기가 이 강좌에서 로그아웃됩니다. 다시 들어오려면 이메일 인증이 필요하고, 닉네임은 같습니다."
   - 조사는 바뀌지 않는 '학생을', '학생의' 뒤에만 붙인다(이름 끝 글자에 따라 틀리지 않게).
3. **확인 창은 다시 쓸 수 있게 따로 만들었다(`ConfirmDialog`).** 포커스는 열리면 '취소'에, 실행 버튼은 destructive 채움, 실행 중에는 두 버튼 모두 비활성, 오류는 창 안에 보인다. T025의 보관 확인 창(`ArchiveDialog`)과 동작이 같지만 이번에는 고치지 않았다. 범위를 넘고 이미 머지된 동작을 건드리기 때문이다. 나중에 합칠 수 있다.
4. **실행한 뒤**에는 "○○ 학생을 명단에서 뺐습니다." / "○○ 학생의 로그인을 끊었습니다."를 표 바로 위에 보이고 명단을 다시 불러온다. 포커스는 다음과 같이 돌린다.
   - 빼기: 그 줄이 사라지므로 표 영역으로 간다.
   - 로그인 끊기: 줄이 그대로 있으므로 누른 버튼으로 돌아간다.
   - 취소: 누른 버튼으로 돌아간다.
5. **오류 처리**: 이미 빠진 학생(404, 다른 창에서 뺌)은 서버 이유를 보이고 명단을 다시 불러온다. 입장 전이라 끊을 로그인이 없으면(409) 서버 이유를 보인다. 연결 문제는 "처리하지 못했습니다. 네트워크 연결을 확인하고 다시 시도해 주세요."를 보인다.
6. 표의 최소 폭을 늘렸다(32rem → 44rem). 버튼 열 때문이고, 좁은 화면에서는 기존처럼 표 영역만 가로로 스크롤한다(키보드로 닿는 영역).

## 확인한 것

- 테스트: `RosterSection.test.ts`에 빼기·끊기 11개를 더했다(버튼 표시 조건, 확인 문구, 취소 포커스, 실행과 갱신, 실행 중 비활성, 404·409·연결 오류, 44px). 기존 표 테스트는 '관리' 열에 맞게 고쳤다. `api.test.ts`에 3개를 더했다. 클라이언트 382개와 `svelte-check`가 통과한다. 서버는 바뀌지 않았다.
- 실제 화면(가짜 로그인 서버, 앱 안 브라우저):
  - 입장한 학생에게만 '로그인 끊기'가 있다.
  - 키보드만으로 확인 창을 열면 포커스가 '취소'에 있다. Tab으로 실행 버튼으로 가서 Enter로 끊으면 결과 문구가 보이고 포커스가 그 버튼으로 돌아온다.
  - '빼기'를 같은 방식으로 실행하면 그 줄이 사라지고, 인원이 2명에서 1명으로 바뀌고, 포커스가 표 영역으로 간다.

- `ArchiveDialog`를 `ConfirmDialog`로 바꾸는 정리(3번).
