# T023 구현 노트: 교수 화면 실시간 (RoomBus, WebSocket)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC40: 새 입장 요청은 새로고침 없이 목록에 나타난다. AC45: '대기 중인 인증'도 마찬가지.
- plan: `/ws/admin/{classroom_id}`, 교수 로그인과 강좌 소유 확인, 서버→클라이언트 이벤트만, **DB 기록 뒤에 보낸다**, 재접속하면 HTTP로 목록을 다시 받는다. `RoomBus`는 프로세스 안 메모리 구현.
- 이벤트 이름(plan): `join_request.created/updated`, `pending_auth.created/updated`, `roster.updated`.

## 내가 정한 것 (스펙 밖)

1. **이벤트는 "무엇이 바뀌었다"만 알린다.** 내용은 종류와 번호뿐(`{"type":"join_request.created","id":7}`)이다. 이름·학번·이메일·코드는 싣지 않는다. 화면은 이벤트를 받으면 HTTP 목록을 다시 불러온다.
   - 이유: (1) WebSocket은 로그아웃·권한 변경을 연결 중에 다시 확인하기 어렵다. 이벤트에 개인정보가 없으면 그 틈이 있어도 새는 것이 없다(조회는 매번 HTTP 권한 판단을 거친다). (2) 대기 중인 인증은 코드를 볼 때마다 기록(`code_revealed`)해야 해서(AC48) 코드를 이벤트로 밀어 보내면 기록 없이 코드가 노출된다.
2. **"ready" 메시지로 빈틈 없이 이어 붙인다.** 서버는 구독을 먼저 걸고 나서 `{"type":"ready"}`를 보낸다. 화면은 `ready`를 받은 뒤에 HTTP 목록을 불러온다. 그러면 목록을 받는 사이에 생긴 변화도 큐에 쌓여 있어 놓치지 않는다. 재접속도 같은 순서다.
3. **DB 기록(커밋)이 끝난 뒤에만 발행한다.** 트랜잭션 블록 밖에서 `bus.publish`를 부른다. 처리가 실패하면(409, 500 등) 발행하지 않는다. 테스트는 발행하는 순간 다른 DB 연결로 값이 보이는지 확인한다.
4. **`RoomBus.publish`는 스레드에서 불러도 안전하게** 만든다. 라우트 함수는 스레드풀에서 돌고 WebSocket은 이벤트 루프에서 돌기 때문이다(`call_soon_threadsafe`).
5. **느린 연결은 큐를 100개로 제한하고 넘치면 `{"type":"resync"}`로 대신한다.** 화면은 `resync`를 받으면 목록을 다시 불러온다. 한 연결이 느려도 서버 메모리가 늘지 않는다.
6. **WebSocket은 `Origin` 검사를 직접 한다.** 브라우저는 WebSocket에 쿠키를 같이 보내므로(교차 사이트 WebSocket 하이재킹) HTTP의 `Origin` 검사 미들웨어가 못 막는 부분을 연결 단계에서 막는다. 서비스 주소와 다르거나 없으면 거부.
7. **권한은 기존 `guard`를 그대로 쓴다**(C8). `get_actor`가 `Request`가 아니라 `HTTPConnection`을 받도록 바꿔 HTTP와 WebSocket이 같은 코드를 탄다. 거부는 연결 단계의 HTTP 응답(401/403/404)으로 끝난다. 권한 행동은 `pendingauth.view`가 아니라 `classroom.manage`(소유자 전용)를 쓴다. 이 연결은 입장 요청·명단·대기 인증을 모두 받기 때문이다.
8. **'교수님께 알리기'를 반복해도 이벤트는 처음 한 번만 보낸다.** 반복 이벤트는 화면의 재조회를 부르고, 재조회마다 `code_revealed`가 쌓이기 때문이다(T022 PR에서 걱정한 부분). 그래서 `notify_professor`가 처음(`ok`)과 반복(`again`)을 구분하도록 고친다.

## 새 의존성: `websockets` (plan에 없던 것, C17 확인)

- 테스트 클라이언트로는 WebSocket이 되는데 **실제 uvicorn은 `websockets`(또는 `wsproto`)가 없으면 연결을 거부한다**. plan의 의존성 표에 빠져 있었다. 실제 서버를 띄워 확인하다 발견했고, 추가해서 다시 확인했다.
- 선택: `websockets==17.4` (uvicorn이 가장 먼저 찾는 구현, 순수 Python 의존성만).
- C17 확인(2026-11-20): 최신 17.4가 2026-10-30에 나옴(3주 전, 17.1~17.4가 8월~10월에 계속 갱신), 월 다운로드 약 5.4억, Python 3.11 이상. 새 하위 의존성 없음(`constraints.txt`에는 이 한 줄만 늘었다).
- plan.md는 승인된 문서라 고치지 않았다. 필요하면 plan에 한 줄 더하는 PR을 따로 만들 수 있다.

## 확인한 것 (실제 서버)

- uvicorn으로 띄워 브라우저(앱 안 브라우저)의 `WebSocket`으로 연결: `ready`, 요청 생성, 승인(요청 갱신과 명단 갱신) 이벤트가 순서대로 도착.
- 다른 출처(`https://evil.example`)와 `Origin` 없음은 로그인 쿠키가 있어도 403, 로그인 없음은 401.

## 일부러 하지 않는 것

- 시간이 지나 코드가 만료되는 것은 서버가 밀어 보내지 않는다(타이머를 두지 않는다). 화면(T029)이 목록에 있는 만료 시각으로 스스로 '만료됨'으로 바꾸면 된다. 지금 응답에는 만료 시각이 없어서, T029에서 `expires_at`을 더할지 정해야 한다 → **T029 때 확인할 일**.
- 연결 중 로그아웃해도 연결을 끊지 않는다(위 1번 이유로 노출되는 정보가 없다). 필요하면 이후에 `logout`에서 구독을 닫는다.
- 학생 화면에는 실시간이 없다(plan).
- 여러 서버로 늘리는 경우(Redis 등)는 `RoomBus` 구현만 바꾸면 되게 인터페이스만 맞춘다. 구현은 만들지 않는다(C15).
