# T035 구현 노트: Resend 연동 (ResendMailer)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC25: 명단 이메일로 '인증 코드 받기'를 누르면 6자리 코드 메일이 간다.
- plan: `Mailer`는 Resend 구현 하나만 만들고, 서비스를 바꾸면 구현만 교체한다(C15). HTTP 호출은 표준 라이브러리로 한다(C17). 위험 2: API가 팀당 초당 10회라 초당 8건 이하로 보낸다.
- tasks: 가짜 HTTP 서버로 성공, 429 재시도, 5xx 재시도, 초당 8건 상한을 확인한다. API 키는 환경 변수에서만 읽고 로그에 남지 않는다.

## Resend API 확인 (공식 문서, 2026-11-22)

- `POST https://api.resend.com/emails`, `Authorization: Bearer <키>`, 본문은 `from`·`to`(배열)·`subject`·`text`이고, 성공하면 `{"id"}`가 온다.
- 오류: 400·401·403·404·405·409·422·429·500·503. 429에는 `retry-after`(초)와 `ratelimit-reset`(초) 헤더가 온다. 기본 상한은 팀당 초당 10회다.
- `Idempotency-Key`(1~256자)는 24시간 동안 기억된다. 같은 키에 같은 내용이면 다시 보내지 않고 같은 응답을 준다. 같은 키에 다른 내용이면 409, 처리 중이면 409(나중에 다시)다.

## 내가 정한 것 (스펙 밖)

1. **`ResendMailer`는 한 번 보내고 결과만 나눈다.** 다시 시도, 지수 대기, 초당 상한, 수신 주소 비우기는 이미 있는 작업 스레드(`MailWorker`, T017)가 맡는다. 결과는 이렇게 나눈다.
   - 성공: 2xx
   - 다시 시도: 429(`retry-after`, 없으면 `ratelimit-reset`만큼 기다림), 5xx, 408, 409 중 "처리 중"·"잠김", 연결 실패·시간 초과(10초)
   - 포기: 그 밖의 4xx. 키·권한·발신 도메인 인증·입력 오류, 같은 키에 다른 내용이 해당한다. 다시 보내도 받아들여지지 않는다.
   - 하루·한 달 할당량 초과(429)도 다시 시도한다. 작업 스레드의 최대 8번, 최대 5분 대기 안에서 풀리지 않으면 포기한다. 그동안 학생은 '교수님께 알리기'로 입장한다(C12).
2. **같은 발송 요청은 항상 같은 `Idempotency-Key`(`mail-outbox/{발송 요청 번호}`)로 보낸다.** 작업 스레드는 '최소 한 번' 보낸다(보낸 직후 기록 전에 멈추면 다시 보냄). 이때 학생에게 같은 메일이 두 번 가지 않게 Resend가 알아본다. 메일 내용(`MailMessage`)에 키 칸을 하나 더했다.
3. **비밀 값과 개인정보를 남기지 않는다.**
   - API 키는 설정(환경 변수 또는 `.env`)에서만 받는다. 로그, 오류 문구, `ResendMailer`와 `Settings`의 출력 형태에 나오지 않는다.
   - 설정의 다른 비밀 값(GitHub 비밀값, 서버 비밀값)도 출력 형태에서 뺐다(`repr=False`).
   - 서비스의 오류 문구에는 수신 주소가 섞일 수 있다. 그래서 로그에는 상태 코드와 오류 이름만 남긴다(C11).
4. **설정에서 고른다.** `RESEND_API_KEY`가 있으면 Resend로 보내고, 없으면 지금처럼 메모리에만 모은다(개발·테스트). 키만 있고 `MAIL_FROM`이 없으면 서버가 뜨지 않는다. 이때 "Resend에서 인증한 도메인의 주소로 MAIL_FROM을 설정해 주세요."를 보인다. 메일이 조용히 안 나가는 것보다 낫다고 봤다.
5. 요청의 User-Agent는 서비스 이름(`classroom-server`)만 담는다(개인정보 없음).
6. `.env.example`의 메일 항목 설명을 보강했다: `MAIL_FROM` 형식(인증한 도메인), 키를 커밋하지 않기, 초당 건수 기본값.

## 확인한 것

- `test_resend.py` 29개를 추가했다. 가짜 Resend 서버(표준 라이브러리 HTTP 서버)로 다음을 확인한다.
  - 요청 모양, 같은 발송 요청의 같은 키, 429의 대기 시간, 5xx·409 재시도, 그 밖의 4xx 포기, 연결 실패와 시간 초과

- 서버 605개 + constitution 23개, ruff 통과.
- 변형 13개 중 12개를 잡았다. 놓친 1개(`ResendMailer`의 출력 형태 함수 빼기)는 결과가 같다. 기본 출력 형태에도 키가 나오지 않는다.

## 실제 발송은 아직 확인하지 않았다

- 인증한 도메인과 실제 API 키가 있어야 한다. **사용자가 `.env`에 `RESEND_API_KEY`와 `MAIL_FROM`을 넣으면** 확인할 수 있다. 200명 규모의 도착 시간과 스팸함 분류(plan 위험 2)는 T036에서 측정해 기록한다.
