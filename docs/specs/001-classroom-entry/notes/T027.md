# T027 구현 노트: 학생 화면 2 (코드 단계)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC25, AC26: 이 기기에서 입력해야 한다는 안내, 6자리 칸, '이 기기에서 로그인 유지'(처음부터 켜짐), '확인하고 계속'.
- AC30~AC33: 틀림(남은 횟수), 5번이면 다시 받기, 10분 만료, 60초 뒤 다시 받기와 남은 초, 다른 기기는 같은 "코드가 맞지 않습니다".
- AC44: 도움 카드의 '메일이 오지 않나요?'와 세 버튼, '교수님께 알렸습니다…' 문구.
- 오류와 예외: 입력 중 연결이 끊기면 이메일을 유지하고 "연결이 끊겼습니다. 다시 연결되면 이어서 진행합니다."를 보인다.
- 서버는 T016, T019, T022에 이미 있다(이번 작업은 화면만).

## 내가 정한 것 (스펙 밖)

1. **규칙은 서버가 판단하고, 화면은 서버의 안내를 그대로 보인다.** 남은 횟수, 만료, 잠김, 이미 사용됨, 다른 기기 모두 서버 문구를 칸 옆에 보인다. 화면에서 하는 검사는 "6자리를 모두 입력해 주세요."(목업 문구) 하나다.
2. **칸에는 숫자만 6자리까지 남긴다.** 메일에서 복사한 "123 456" 같은 공백과 하이픈은 버린다. **브라우저의 `maxlength`는 쓰지 않는다.** 실제 브라우저에서 확인해 보니 `maxlength`가 공백까지 세어 "983 952"를 "98395"로 잘랐다(jsdom 테스트는 `maxlength`를 따르지 않아서 잡지 못했다). 6자리 제한은 입력 처리가 숫자만 세어서 한다.
2-1. **붙여 넣기는 붙여 넣은 글에서 6자리 코드를 찾아 칸을 그 코드로 바꾼다.** 코드로 보는 것은 앞뒤가 숫자가 아닌 6자리이고, 가운데 공백·하이픈 하나는 허용한다. 메일 첫 줄("{강좌 이름} 입장 인증 코드: 123456")이나 제목, 본문을 통째로 붙여 넣어도 강좌 이름의 숫자(예: "자료구조 2")나 "10분"이 섞이지 않는다. 몇 자리 쳐 둔 뒤에 붙여 넣어도 이어 붙지 않는다. 숫자만 다 남기는 방식으로는 "자료구조 2 … 349498"이 "234949"가 되고, "12"를 쳐 둔 뒤 붙여 넣으면 "123494"가 되어 둘 다 틀린 코드였다. 코드 전체가 아닌 숫자 몇 개는 가로채지 않고 평소처럼 넣는다.
3. **틀린 코드는 지우고 칸으로 포커스를 돌린다.** 바로 다시 쓰기 쉽게 하려는 것이다. 다시 쓰기 시작하면 오류 표시가 사라진다.
4. **'코드 다시 받기' 카운트다운은 서버가 알려 준 남은 초로 시작한다.** 남은 초는 마감 시각에서 계산하므로 탭이 잠시 멈춰도 어긋나지 않는다. 버튼 아래에 "N초 뒤에 다시 받을 수 있습니다."를 글로 보인다. 1초마다 바뀌는 글이라 알림 영역(`aria-live`)에는 두지 않고, 버튼의 설명(`aria-describedby`)으로만 잇는다. 서버가 429로 남은 시간을 주면 그 값으로 다시 센다.
5. **새 코드를 받으면** "새 코드를 보냈습니다. 이전 코드는 쓸 수 없습니다."를 알리고, 칸을 비우고, 다시 60초를 센다. **'교수님께 알리기'도 다시 누를 수 있게 된다.** 이전 알림은 이전 코드의 것이라 교수님 목록에서 사라지기 때문이다(T022).
6. **'교수님께 알리기'를 누르면** 서버의 문구를 보이고 버튼은 숨긴다(반복해도 서버는 한 번만 알린다). 포커스는 코드 칸으로 간다. 교수님이 알려 주는 코드를 같은 칸에 입력하기 때문이다(AC46).
7. **연결이 끊기면** 경고 알림 하나("연결이 끊겼습니다…")를 보이고 입력(코드, 이메일, 로그인 유지 선택)은 그대로 둔다. 브라우저의 `offline` 이벤트로 바로 알리고, `online`이 되면 알림을 거둔다. 확인·다시 받기·알리기 중 연결 실패도 같은 알림을 쓴다. 다시 연결된 뒤 같은 단계에서 이어서 누르면 된다.
8. **이메일 단계에서 방금 코드를 받은 이메일을 다시 보내면(60초 안) 막지 않고 코드 단계로 보낸다.** 남은 초로 카운트다운을 시작한다. 실제 화면에서 '이메일 다시 입력' → 같은 이메일로 다시 보내기를 해 보니, 이전에는 "코드는 N초 뒤에 다시 받을 수 있습니다." 오류만 나오고 이미 받은 코드를 넣을 곳이 없어 최대 60초를 멈춰 있어야 했다(C12와 어긋남). 이미 보낸 코드는 살아 있으니 그 코드를 입력하게 했다.
9. **코드를 받은 뒤 명단에서 빠졌으면**(서버가 `request_access`를 줌) 이메일 단계로 돌아가 명단 밖 안내와 '입장 요청 보내기'를 보인다. 링크가 닫혔으면(404/403) 닫힌 화면으로 바뀐다.
10. **코드가 맞은 뒤의 화면은 자리만 만든다.** "인증되었습니다"와 닉네임을 보인다. 채팅 이용 안내와 '확인하고 입장'은 T028이다.
11. **도움 카드의 버튼은 세로로 쌓는다.** 목업은 두 개를 나란히 두었지만, 버튼이 셋으로 늘었고 375px에서 "코드 다시 받기"와 남은 초가 함께 들어가기 어렵다. 모두 44px 높이, 전체 폭이다.
12. `ApiError`에 `data`를 더했다. 서버의 오류 내용 중 안내 말고 함께 온 값(`outcome`, `remaining`, `wait_seconds`)을 담는다. 기존 동작은 그대로다.

## 확인한 것

- 테스트: `CodeStep.test.ts` 35개(입력, 오류 5종, 도움 카드, 다시 받기 카운트다운(가짜 시계), 연결 끊김, 크기). `join.test.ts`에 코드 단계 연결 4개, `api.test.ts`에 코드 단계 API 4개를 더했다. 클라이언트 전체 285개와 `svelte-check`가 통과한다.
- 실제 화면(가짜 로그인 서버, 마지막 메일을 보여 주는 개발용 경로, 앱 안 브라우저, 375px):
  - 코드 칸 높이 72px, 가로 스크롤 없음.
  - 틀린 코드를 넣으면 "코드가 맞지 않습니다. 4번 더 입력할 수 있습니다."가 보이고, 칸이 비워지고, 포커스가 돌아온다.
  - 카운트다운이 줄어든다. '교수님께 알리기'를 누르면 문구가 보이고 포커스가 칸으로 간다.
  - "496 517"을 입력하면 `496517`이 된다(2번의 버그를 고친 뒤).
  - 맞는 코드를 넣으면 "인증되었습니다"와 닉네임이 보인다.
  - 60초 안에 이메일을 다시 보내면 코드 단계로 간다(8번).

- 붙여 넣기: 앱 안 브라우저는 실제 클립보드 붙여 넣기(Cmd+V)가 동작하지 않았다(빈 텍스트 칸에도 붙여 넣기 이벤트가 오지 않음). 그래서 Chrome의 `ClipboardEvent`에 붙여 넣을 글을 담아 보냈다. "12"를 쳐 둔 뒤 메일 본문 전체("자료구조 2 입장 인증 코드: …\n\n이 코드는 10분 동안")를 붙여 넣으면 정확한 코드만 남았고, 서버도 그 코드를 받아 입장했다. 브라우저 기본 입력으로 " 784 841 "을 넣어도 `784841`이 됐다. **실제 휴대폰에서 메일 앱의 코드를 길게 눌러 붙여 넣는 것은 T036(실기기 확인)에서 본다.**

## 일부러 하지 않는 것

- 코드 칸을 여섯 칸으로 나누지 않는다. 한 칸이면 붙여 넣기, 자동 채우기, 화면 읽기 도구가 모두 단순하다(목업과 같다).
- 서버의 10분 만료를 화면에서 미리 세지 않는다. 만료는 입력했을 때 서버가 알려 준다(AC31 문구).
- 이 단계에서 새로고침하면 이메일 단계부터 다시 시작한다. 같은 이메일을 다시 넣으면 8번 덕분에 바로 코드 단계로 온다.
