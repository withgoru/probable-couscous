# T036 구현 노트: 부하 측정과 수동 확인 기록

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 결과 자체는 `docs/specs/001-classroom-entry/notes.md`에 있다.

## 내가 정한 것 (스펙 밖)

1. **부하 측정 스크립트는 E2E 전용 서버를 다시 쓴다**(`client/e2e/server.py`). 실제 uvicorn 프로세스와 실제 SQLite(`synchronous=FULL`)이고, 가짜 로그인과 메모리 메일함이다. 저장된 행을 세려고 그 서버가 DB 파일 경로를 선택적으로 받게 했다(기존 사용법은 그대로다).
2. **"유실"은 두 가지를 센다.** 성공 응답(`next: code`)을 받지 못한 요청, 그리고 성공이라고 답했는데 DB에 남지 않은 요청이다. 유실이 있으면 스크립트가 종료 코드 1로 끝난다. 일부러 유실을 만드는 숨은 옵션으로 이 동작을 테스트한다.
3. **200명이 같은 순간에 보낸다.** 각자 기기(쿠키)를 먼저 받아 두고 신호 하나로 동시에 출발한다. 링크 열기는 측정에서 뺐다.
4. **메일 발송 속도를 따로 실험했다.** 메모리 메일함은 보내는 데 시간이 들지 않아 실제와 다르다. 그래서 `ResendMailer`를 응답을 늦추는 가짜 서버에 붙여 200통의 소요 시간을 쟀다(실험 코드는 저장소에 넣지 않았다). 작업 스레드가 한 통씩 차례로 보내서, 응답이 200ms면 46초, 300ms면 66초가 걸렸다. 고치는 것은 `MailWorker` 구현 변경이라 이 작업 범위 밖이고, 사용자에게 따로 진행할지 묻는다.
5. **한국어 엑셀 CSV는 엑셀이 쓰는 바이트를 만들어 실제 앱에 올렸다.** 실제 엑셀로 저장한 파일은 없어서 남은 일로 적었다.
6. **실제 메일(위험 2)과 실기기(위험 4)는 사용자가 해야 한다.** 따라 할 절차와 채울 표를 `notes.md`에 만들었다.
7. **tasks의 T036은 체크하지 않았다.** 완료 기준이 위험 1, 2, 4, 5의 결과 기록인데 2와 4가 아직 비어 있다. 사용자가 확인해 표를 채우면 그때 체크한다.
