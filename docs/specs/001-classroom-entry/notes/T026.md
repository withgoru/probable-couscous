# T026 구현 노트: 학생 화면 1 (이메일 단계, 링크 상태, 입장 요청)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

- AC24: 안내 문구, 이메일 칸, '인증 코드 받기'. 형식이 틀리면 "이메일 형식을 확인해 주세요."
- AC10, AC22: 보관된 강좌, 폐기된 링크는 각각의 안내 문구를 보이고 입장할 수 없다.

- AC51: 390px 폭에서 가로 스크롤이 없다. 서버는 T018, T021에서 이미 있다(이번 작업은 화면만).

## 내가 정한 것 (스펙 밖)

1. **주소는 `/join/{토큰}`**이다. 서버가 만드는 초대 링크와 같다(T014). 이 주소는 교수 로그인 가드가 막지 않고 `/api/me`도 부르지 않는다. 교수로 로그인한 브라우저에서 열어도 교수 메뉴를 붙이지 않는다(학생 화면). 정확히 `/join/한 칸`만 해당하고 `/join`, `/join/a/b`는 그대로 보호된다.
2. **링크 상태는 화면을 열 때 확인한다.** 폐기된 링크(404)와 보관된 강좌(403)는 오류 화면이 아니라 "입장할 수 없습니다" 제목과 **서버가 준 안내 문구 그대로**를 보인다. 문구를 화면에 다시 적지 않아 서버와 어긋나지 않는다. 서버 오류와 연결 문제는 기존 오류 화면이 안내한다. 이메일이나 입장 요청을 보내는 사이에 닫혀도(404/403) 같은 화면으로 바뀐다.
3. **이메일 형식은 화면에서 먼저 검사한다**(서버와 같은 규칙). 서버에 묻지 않고 바로 알려 주기 위해서다. 비어 있으면 "이메일을 입력해 주세요."(서버와 같은 문구)를 보인다. 고쳐 쓰면 오류 표시가 사라진다. 서버의 칸 오류도 같은 자리에 보인다.
4. **명단 밖·이미 요청함·거절됨 안내는 이메일 칸 아래에 보이고, 칸은 그대로 둔다.** 학생이 이메일을 잘못 쓴 경우가 많을 테니 바로 고칠 수 있게 했다. 고쳐 쓰면 이전 안내는 사라진다. '입장 요청 보내기' 버튼은 명단 밖일 때만 있다. 색은 명단 밖=warning, 요청함=info, 거절=destructive이고, 모두 아이콘과 글로 전달한다(C14).
5. **입장 요청 폼은 이름과 학번만 받는다.** 이메일은 방금 입력한 것을 보여 준다. 다른 이메일로 하려면 '이메일 다시 입력'으로 돌아간다. 빈 칸·길이 검사는 화면에서 하지 않고 서버의 안내를 칸 옆에 보인다(규칙을 한곳에 둔다). 학번 칸은 숫자 키패드가 뜨도록 `inputmode="numeric"`이지만, 학번에 글자가 섞여도 받는다(`type="text"`).
6. **요청 뒤에는 결과 안내만 남기고 폼은 닫는다.** 그사이 명단에 추가됐다는 응답(`already_on_roster`)이면 '이메일 다시 입력' 버튼을 함께 보인다.
7. **코드 단계는 자리만 만든다.** 명단에 있는 이메일이면 "인증 코드를 입력하세요", 보낸 주소, "코드는 지금 이 화면을 연 기기에서 입력해야 합니다."(AC25), '이메일 다시 입력'을 보인다. 6자리 입력, 로그인 유지, 도움 카드는 T027이다.
8. **단계가 바뀌면 새 제목으로 포커스를 옮긴다.** 화면을 읽어 주는 도구도 바뀐 것을 안다. 이메일 단계로 돌아오면 바로 고칠 수 있게 포커스는 이메일 칸으로 간다.
9. **'으로/로' 같은 조사를 주소나 이름 뒤에 붙이지 않는다.** 끝 글자에 따라 달라져 틀리기 쉽다. "6자리 코드를 보냈습니다: 주소"처럼 쓴다(T025 확인 창과 같은 이유).
10. 목업 맨 아래의 "이메일은 출석 기록에 쓰이고, 채팅에는 닉네임만 표시됩니다."는 넣지 않았다. 스펙에 없는 문구이고 출석은 003이다.
11. 아이콘을 넷 더 가져왔다(`link`, `mail`, `send`, `info-circle`). Iconoir는 이미 쓰는 의존성이다.
