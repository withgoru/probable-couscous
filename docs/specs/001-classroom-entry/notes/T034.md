# T034 구현 노트: 접근성·키보드·390px 점검

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙에서 읽은 것

- AC50: 모든 입력 칸에 보이는 이름표, 오류는 칸 옆에 글로, 색만으로 상태를 전달하지 않는다. 버튼과 입력 높이는 44px 이상이고, 키보드 포커스는 2px 불투명 링으로 보인다.
- AC51: 키보드만으로 로그인, 강좌 만들기, 명단 올리기, 학생 입장을 끝낼 수 있다. 학생 화면은 390px에서 가로 스크롤이 없다.
- tasks: 자동 접근성 점검 도구를 쓸지는 C17 확인 뒤 정한다.

## 의존성 (C17, 2026-11-22 조회, 사용자 승인)

- `@axe-core/playwright` 4.14.0을 개발용으로 고정했다. 2026-10-15 공개, 최근 한 달 약 1억 다운로드. 하위 의존성은 `axe-core` 하나로, lockfile에 4.14.1(2026-11-16 공개, 월 약 4.8억)로 고정됐다.
- plan 의존성 표에는 없던 것이다. plan은 승인 문서라 고치지 않고 이 노트에 이유를 남긴다. 화면마다 WCAG 2.2 AA 규칙(대비, 이름표, 역할, 이름 등)을 사람이 빠뜨리지 않게 자동으로 훑는 데 쓴다.
- lockfile은 CI와 같은 npm 10(10.9.4)으로 만들었다(T033에서 정한 방식).

## 내가 정한 것 (스펙 밖)

1. **키보드 흐름 테스트는 Tab, Enter, Space와 글자 입력만 쓴다.** 교수(1280px 노트북)와 학생(390px 휴대폰) 순서는 다음과 같다.
   - 교수: 로그인 → 새 강좌 만들기 → 열기 → CSV 파일 칸에서 Space로 파일 선택 → 올리기
   - 학생: 초대 링크 → 이메일 → 코드 → 확인하고 입장
   - 끝나면 교수 명단에 '입장함'이 보인다.
   - 닿을 때까지 Tab을 누르고, 60번 안에 닿지 못하면 실패다.
2. **Tab으로 지나가는 모든 요소를 점검한다.**
   - 포커스 링: 링 색(#0a2463)의 2px 이상 box-shadow 또는 2px 이상 실선 outline
   - 크기: 버튼, 입력, 버튼 모양 링크, 탭은 높이 44px 이상. 체크 상자는 누를 수 있는 줄(label)의 높이로 본다.
   - 화면별 점검에서는 Tab으로 한 바퀴 돌며 같은 것을 본다.
   - 포커스 링이 전환 효과 중간 값으로 읽히지 않도록 테스트에서는 전환 효과를 끈다.
3. **axe는 화면마다 돈다.**
   - 교수: 로그인, 내 강좌, 새 강좌 폼, 보관 확인 창, 마이페이지, 관리 페이지(입장 요청이 있는 상태), 빼기 확인 창
   - 학생(390px): 이메일, 형식 오류, 명단 밖 안내, 입장 요청 폼, 그 폼의 오류, 코드 단계, 코드 오류, 채팅 이용 안내, 입장 완료, 닫힌 링크
   - 학생 화면은 문서 전체에 가로 스크롤이 없는지도 함께 본다.
4. **점검이 실제로 실패할 수 있는지 확인했다.** 로그인 화면에 일부러 낮은 대비 글자와 이름표 없는 입력 칸을 넣으면 axe가 둘 다 잡았다(`color-contrast`, `label`). 이때 SPA가 그리기 전에 점검하면 빈 화면을 통과시킬 수 있음을 알게 되어, 점검 전에 화면 제목(`h1`)이 보일 때까지 기다리게 했다. 포커스 점검은 아래의 실제 문제를 잡아서 동작이 확인됐다.

## 찾아서 고친 것 (화면)

- **내 강좌의 탭 패널**(`Tabs.Content`)이 키보드 포커스를 받는데 링이 없었다. 탭 패널은 WAI-ARIA에 따라 포커스를 받는다. 다른 요소와 같은 2px 링을 줬다.
- **수강생 명단 표의 스크롤 영역**(키보드로 가로 스크롤하려고 포커스를 받는 영역)에 브라우저 기본 1px 링만 있었다. 2px 링을 줬다.
- **CSV 파일 칸**의 높이가 38px이었다. 44px 이상으로 고쳤다(`min-h-11`).
- **'이 기기에서 로그인 유지' 체크 상자**에 브라우저 기본 1px 링만 있었다. 기본 체크 상자는 box-shadow 링을 그리지 않아서, 2px 실선 outline(링 색)으로 포커스를 보이게 했다.
- axe는 위 수정 전후 모두 위반이 없었다. 대비 등은 디자인 토큰 단계에서 이미 검증됐다.

## 확인한 것

- E2E 13개(기존 9 + 새 4)가 모두 통과한다. 클라이언트 단위 테스트 382개와 `svelte-check`도 통과한다. 서버는 바뀌지 않았다.
- E2E가 쓰는 파이썬 경로를 절대 경로로 바꿨다. 상대 경로라서 가상환경 경고가 나왔다.

## 일부러 하지 않는 것

- 실제 화면 읽기 도구(VoiceOver, TalkBack)와 실기기 확인은 T036이다.
- 교수 화면의 390px 가로 스크롤은 점검하지 않았다(AC51은 학생 화면). 교수 화면은 노트북 기준이고, 명단 표는 표 영역만 가로로 스크롤한다.
- 계정 메뉴(로그아웃)의 키보드 이동은 AC51 목록에 없어 흐름에 넣지 않았다. 다만 Tab 한 바퀴 점검은 메뉴 버튼까지 지나간다.
