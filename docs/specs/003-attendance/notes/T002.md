# T002 구현 노트: 권한 행동 `attendance.manage`, `attendance.self`

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- plan 인터페이스: `attendance.manage`는 소유 교수만 쓰고, 보관된 강좌도 된다. 거절 문구는 "이 강좌에 대한 권한이 없습니다."다(AC26). `attendance.self`는 그 강좌에 입장한 학생만 쓰고, 교수는 `forbidden`이다(AC27). 열기·연장·마감·다시 받기는 002의 `session.present`를 쓴다.

## 내가 정한 것

1. **`attendance.manage`는 002의 교수 전용 묶음(`_SESSION_OWNER_ONLY`)에 넣었다.** 거절 사유와 보관된 강좌 허용이 `session.manage`와 같기 때문이다. `session.present`처럼 보관된 강좌를 막는 조건은 붙이지 않았다.
2. **`attendance.self`의 판단 순서는 이렇다.** 학생이 아니면 `forbidden`, 다른 강좌면 `not_member`, 보관된 강좌면 `archived`다.
   - 명단에서 빠졌거나 로그인이 끊긴 학생은 `class_access.class_actor`가 멤버십 없는 학생 행위자로 만든다. 그래서 `not_member`로 거절된다. 표에 이 경우(`not_entered`)를 따로 넣었다.
3. **교수 쿠키가 학생 로그인보다 앞선다**(`class_access.py`의 기존 동작). 한 브라우저에 둘 다 있으면 `attendance.self`는 늘 `forbidden`이다. E2E에서는 교수와 학생을 서로 다른 컨텍스트로 연다(002와 같다).

## T004~T011에 넘길 것 (검증에서 나온 것)

- **교수 전용 출석 라우트는 `guard`가 아니라 `class_access.guard_class`로 건다.**
  - `guard`의 `get_actor`는 교수만 알아본다. 그래서 학생이 시도하면 401 "로그인이 필요합니다."가 나가고, AC26 문구("이 강좌에 대한 권한이 없습니다.")가 나오지 않는다. 002의 노트 경로가 실제로 이렇게 동작한다.
  - `guard_class`를 쓰면 입장한 학생, 입장하지 않은 학생, 다른 교수 모두 403 AC26 문구를 받는다.
  - 차이 하나: 없는 강좌는 로그인하지 않은 사람에게도 404다(`guard`는 401로 숨긴다). 강좌 번호는 이미 교수 화면 주소에 드러나 있어 받아들인다.
- **학생 경로의 `not_member` 문구.** 지금 문구 "이 강좌에 입장한 학생만 볼 수 있습니다."는 출석을 보낼 때 어색하다. T008에서 출석 경로에 맞는 문구(무엇이 잘못됐고 어떻게 고치는지)를 정한다.

## 확인한 것

- 새 테스트 7개는 처음에 행동이 없어 수집 단계에서 실패했다. 지금은 서버 955개, constitution 35개, ruff check가 통과한다.
- 변형 검사(서브에이전트): 14개 모두 잡혔다. 바꾼 내용은 묶음에서 빼기, 소유자 전용으로 옮기기, 학생 확인·강좌 비교·보관 확인 지우기, 사유 바꾸기, 교수 허용, 거절 상태 코드 바꾸기 등이다.
- 리뷰(서브에이전트): plan·T002와 맞다. 위 "T004~T011에 넘길 것" 두 가지가 나왔다.
