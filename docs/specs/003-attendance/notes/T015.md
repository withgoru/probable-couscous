# T015 구현 노트: 서버 시각 맞추기와 코드 받아 오기(클라이언트)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC3: 코드는 15초마다 바뀌고, 교수 화면·프로젝터·같은 교수의 다른 화면이 같은 순간에 같은 코드를 보인다.
- 스펙 오류 표:
  - 교수 연결이 끊기면 코드가 흐려지고 낡은 코드를 띄우지 않는다. 프로젝터는 서버 시각으로 계속 바꾼다.
  - 프로젝터가 끊기면 끊김 표시와 흐린 코드를 보인다.
- plan '코드 전달':
  - `GET …/attendance/code`로 지금·다음 코드, 경계 시각, 서버 시각을 받는다.
  - 요청 왕복의 중간값으로 서버 시각과의 차이를 구한다.
  - 경계에서 다음 코드로 바꾸고 곧바로 그다음을 받는다. 받기에 실패하면 흐리게 한다.
- plan '마감': 화면이 마감 시각(서버 시각)에 스스로 닫은 뒤 `live`를 다시 받는다.

## 내가 정한 것

1. **모듈 하나**: `client/src/lib/attendanceCode.ts`의 `connectAttendanceCode(강좌, 회차, {onClosed})`.
   - `subscribe`, `serverNow()`, `refresh()`, `stop()`을 준다. 교수 수업 화면(T016)과 프로젝터(T019)가 함께 쓴다.
   - 상태: `loading` → `open` → `closed`, 그리고 `denied`. 함께 `code`, `slotEndsAt`, `closesAt`(모두 서버 시각 ms), `stale`, `message`를 준다.
   - 경계와 마감에만 알린다. 남은 시간 막대·원은 화면이 `slotEndsAt - serverNow()`와 `SLOT_MS`로 따로 그린다.
2. **서버 시각 차이**:
   - 한 응답의 값은 `server_now - (보낸 때 + 받은 때) / 2`다. 받은 때는 본문을 읽기 전에 잰다.
   - 최근 응답 8개(약 2분) 가운데 왕복이 가장 짧았던 응답의 값을 쓴다. 중간값 추정의 틀림은 가는 길과 오는 길의 차이의 절반이라, 왕복이 짧을수록 정확하다.
   - 최근 것만 보므로, 기기 시계가 바뀌어도(NTP, 잠자기) 곧 다시 맞는다(리뷰).
   - 왕복이 음수이거나 10초를 넘으면 쓰지 않는다. 그사이 기기 시계가 바뀌었을 수 있다(리뷰).
3. **경계**:
   - 서버 시각으로 지금 칸을 골라 보이고, 그 칸이 끝나는 때(또는 마감)에 타이머를 건다. 경계에서는 받아 둔 다음 코드로 곧바로 바꾸고 그다음을 받는다.
   - 경계 바로 뒤라 서버가 아직 앞 칸이면 다음 코드가 오지 않는다. 그러면 1초 뒤 다시 받아 채운다. 시차 추정이 조금 앞설 때 생긴다.
4. **흐림(`stale`)**:
   - 받기가 실패하면 흐림이다: 연결 실패, 5초 안에 답이 없음(리뷰), 5xx, 시각을 읽지 못한 응답.
   - 1·2·5·10초 간격으로 다시 받는다. 성공하면 간격을 처음부터 다시 센다.
   - 실패해도 받아 둔 다음 칸 코드는 그 칸 동안 흐리게 보인다. 서버 시각으로 맞는 코드라 "낡은 코드"가 아니라고 보았다(학생은 그 코드로 출석할 수 있다).
   - 받아 둔 칸이 다 지나면 코드를 비운다(`open`, 코드 없음, 흐림).
5. **닫힘**:
   - 마감 시각(서버 시각)이 되거나 409를 받으면 닫힌다. `onClosed`는 한 번만 부른다. 끊긴 채로 마감 시각이 지나도 닫힌다.
   - 닫힌 뒤에도 `refresh()`는 다시 받는다. 다시 받기나 연장 알림 뒤 화면이 부르면 다시 열린다(리뷰).
6. **`denied`**(리뷰): 401·403·404는 다시 시도하지 않고 멈춘다. 끝없이 "다시 연결하는 중"을 보이지 않기 위해서다.
   - 401: "출석코드를 볼 수 없습니다. 다시 로그인한 뒤 수업 화면을 새로 열어 주세요."
   - 403·404: 서버가 준 안내.
7. **화면이 다시 보이면**(리뷰): `visibilitychange`에서 곧바로 다시 그리고 받는다. 숨긴 탭과 잠든 노트북은 타이머가 늦게 깨기 때문이다.
8. **받는 도중 `refresh()`**: 끝난 뒤(실패여도) 곧바로 한 번 더 받는다. 연장 알림이 다시 시도 간격만큼 늦지 않게 하려는 것이다.
9. **서버 시각 읽기**: 파이썬 isoformat의 마이크로초를 밀리초 세 자리로 자른 뒤 읽는다. 세 자리보다 긴 소수는 표준 밖이라 브라우저마다 다를 수 있다(리뷰).
10. **글꼴 모양**: 저장소 `src/lib`와 같게 탭과 작은따옴표를 썼다. 저장소에 prettier 설정 파일이 없다.

## T016·T019에 넘길 것

- 화면은 `attendance.updated`(연장·마감·다시 받기)를 받으면 `refresh()`를 부른다. 시작과 종료는 `session.updated` → `live`에서 창 상태를 읽어 모듈을 만들거나 멈춘다(plan 인터페이스).
- 첫 받기가 실패하면 `loading`과 흐림이고, 받아 둔 칸이 다 지나면 `open`, 코드 없음, 흐림이다. 두 경우 모두 "연결이 끊겼습니다. 다시 연결하는 중…"으로 보인다.
- `denied`면 `message`를 보인다.

## 확인한 것

- 새 테스트(vitest, 가짜 시계, 가짜 fetch, 서버 시계를 7.3초 앞서게 둔 가짜 서버)는 처음에 모듈이 없어 실패했다.
- 지금은 35개, 클라이언트 868개, svelte-check 0개 오류다.
- 변형 검사(서브에이전트): 36개 중 22개를 잡았다.
  - 동작이 같은 변형 다섯: 닫힌 뒤 칸 비우기, close·stop의 타이머 지우기, 멈춘 뒤 fail. 다른 곳의 확인이 막는다.
  - 왕복이 같을 때 어느 값을 쓸지(`<`와 `<=`)는 거의 같다고 보아 테스트하지 않았다.
  - 나머지는 테스트를 더해 잡았다: 정확히 경계, 다시 시도 간격과 성공 뒤 처음부터, 받는 중 refresh가 실패 뒤에도 곧바로, 다시 시도 대기 취소, 마감 뒤 409의 onClosed 한 번, 멈춘 뒤 409, 시각을 읽지 못한 응답.
  - 리뷰 반영 뒤 다시 걸어 본 변형 9개 중 8개를 잡았다. 남은 하나는 "소수 자르기를 빼기"다. Node(V8)는 마이크로초도 읽어서 테스트로 갈리지 않는다. Safari에서 실제로 읽히는지는 아직 보지 않았다(실기기 확인 목록).
- 리뷰(서브에이전트) 반영: 위 2(최근 값, 음수 왕복), 4(시간 제한), 5(다시 열기), 6, 7, 8, 9, 그리고 가짜 서버의 시각 모양을 실제 서버와 맞춘 것.
