# T009 구현 노트: 수기 출석 요청과 승인·거절 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC17: 학생은 사유(1~200자)를 써서 보낸다. 같은 회차에 다시 보낼 수 없고, 회차가 진행 중인 동안만 보낸다.
- AC18: 교수 수업 화면에 "수기 출석 요청 N"이 있다.
- AC19: 승인하면 "출석 (수기)", 거절하면 학생 화면에 안내가 나온다. 처리는 되돌리지 않는다.
- AC20: 수업이 끝난 뒤에도 처리할 수 있다.
- plan 인터페이스:
  - 학생: `POST /class/{id}/sessions/{s}/attendance-requests {reason}` → 201. 진행 중이 아니면, 이미 보냈으면, 이미 출석이면 409다.
  - 교수: `POST /classrooms/{id}/attendance-requests/{r}/approve|reject`. 이미 처리했으면 409다.
- T001 노트: 사유는 서버에서 앞뒤 공백을 지운 값을 검사하고 저장한다.

## 내가 정한 것

1. **사유**: 파이썬 `str.strip()`(탭·줄바꿈·전각 공백까지)으로 지운 값이 1~200자여야 하고, 지운 값을 저장한다. 벗어나면 422 "사유를 1~200자로 적어 주세요."다.
2. **요청 확인 순서**(쓰기 잠금 안에서):
   - 회차가 진행 중인지 본다. 아니면 409 "수업이 진행 중일 때만 수기 출석을 요청할 수 있습니다."다.
   - 지금 명단의 항목인지 본다(T008과 같다).
   - 이미 출석이면 409 "이미 출석했습니다."다.
   - 이미 보냈으면 409 "이미 요청을 보냈습니다. 교수님이 확인하면 출석 처리됩니다."다. 처리된 뒤에도 마찬가지다.
   - 동시에 두 번 보내도 두 번째가 409다(500이 아니다).
3. **출석 마감 뒤에도 수업 중이면 요청할 수 있다**(AC17은 "회차가 진행 중인 동안"). 교수가 결석으로 바꾼 학생(마지막 기록이 결석)도 요청할 수 있다.
4. **처리**:
   - 처리 기록(`attendance_decisions`)과 승인 기록(`request_approved`)이 한 트랜잭션이다.
   - 응답은 `{id, decision, status}`다. 보관된 강좌와 끝난 회차에서도 된다(`attendance.manage`).
5. **이미 출석한 학생의 요청을 승인하면, 처리는 `approved`로 남기고 승인 기록은 더하지 않는다.** 요청을 보낸 뒤 코드로 출석한 경우다. 코드 출석이 "출석 (수기)"로 내려가지 않게 하려는 것이다.
6. **"수기 출석 요청 N"은 아직 결석인 학생의 처리하지 않은 요청만 센다**(리뷰에서 나온 것, 스펙에 없는 판단).
   - 요청 뒤 코드로 출석한 학생은 승인할 필요가 없는데 교수 화면에 남으면 헷갈린다.
   - 처리 기록은 만들지 않는다(처리는 교수가 하는 일).
   - T010의 대기 요청 목록도 같은 기준으로 한다.
7. **명단에서 빠진 학생의 요청은 처리할 수 없다(404).** 목록에 없고, 빠진 명단 항목에 출석을 남기지 않는다(T008과 같다).
8. **사유는 학생이 쓴 글이라 요청한 학생 자신과 교수의 목록(T010)에만 나간다.** 수업 방 발행, `live`, `events`에 싣지 않는다(C2). 요청과 처리는 `events`에 쌓지 않는다(plan, 보관 정리 때 지워야 하기 때문).
9. **한 학생의 마지막 기록 읽기를 `attendance_state.last_status` 하나로 모았다.** 코드 출석, 요청, 처리, `live`가 함께 쓴다.

## T010·T018에 넘길 것 (검증에서 나온 것)

- **T018(교수 수업 화면의 요청 펼침)은 T010의 목록이 있어야 한다.**
  - AC18은 요청마다 학번·이름·사유·시각을 보여야 한다. 그런데 이 작업에는 목록을 돌려주는 경로가 없다. `tally`·`live`에는 수만 있다.
  - tasks.md에서 T018의 의존은 T009·T017뿐이다. **T010을 더해야 한다**(tasks.md는 승인 문서라 고치지 않았다).
  - T018을 T010 뒤에 하면 그대로 된다.
- T010의 대기 요청 목록 형태: `{id, roster_entry_id, student_no, name, reason, created_at}`. 위 6번 기준(처리 안 됨, 지금 명단, 아직 결석)을 쓴다.
- 화면은 `attendance.tally`의 `pending`이 바뀌면 목록을 다시 받는다.
