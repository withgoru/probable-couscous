# T004 구현 노트: 출석 받는 시간 설정 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC1:
  - 강좌마다 5·10·15분 중 하나를 고르고, 처음 값은 10분이다.
  - 다음에 시작하는 수업부터 쓰인다(시작은 T005).
  - 분반 만들기·새 학기 복제는 원래 강좌의 값을 가져간다.
- plan 인터페이스:
  - `PUT /classrooms/{id}/attendance-settings {minutes}`. 5·10·15 말고는 422다.
  - 바꾸면 `events`에 `attendance_minutes_changed`를 남기고, 내용에는 분 값만 넣는다.
- AC26: 다른 교수나 학생이 시도하면 "이 강좌에 대한 권한이 없습니다."가 나온다.

## 내가 정한 것

1. **출석 라우트는 새 모듈 `app/attendance.py`에 모은다.** T005 이후의 출석 라우트도 여기에 둔다.
2. **교수 전용 라우트는 `guard_class(Action.ATTENDANCE_MANAGE, …)`로 건다**(T002 노트).
   - 입장한 학생과 다른 강좌 학생 모두 403 AC26 문구를 받는다.
   - 아직 로그인 전인 사람(코드를 넣지 않은 학생 포함)은 401 로그인 안내를 받는다.
   - 없는 강좌는 404다.
3. **값 검사는 직접 한다.**
   - 정수 5·10·15만 받는다. `10.0`, `"10"`, `true`, `null`, 빈 본문은 모두 같은 한국어 안내로 422다.
   - 문구: "출석 받는 시간은 5분, 10분, 15분 중에서 골라 주세요."
4. **같은 값으로 저장하면 기록하지 않는다.** 응답은 똑같이 200이고, 바뀐 경우에만 `{from, to}`를 기록한다.
   - 읽기·바꾸기·기록을 한 쓰기 트랜잭션에서 하므로, 기록이 실패하면 값도 바뀌지 않는다(C6).
5. **보관된 강좌에서도 바꿀 수 있다.** `attendance.manage`가 보관된 강좌를 허용하기 때문이다(plan). 화면에서 숨길지는 T023에서 정한다.
6. **강좌 정보 응답**(목록·하나)에 `attendance_minutes`를 더했다. 관리 페이지(T023)가 처음 값을 여기서 읽는다.
7. **테스트 도우미 `tests/attendance_world.py`를 새로 만들었다.**
   - 강좌 만들기, 명단 넣기, 입장한 학생 클라이언트가 들어 있다. 003의 서버 테스트 파일들이 함께 쓴다.
   - 지금까지는 테스트 파일마다 이 도우미를 따로 정의했다.
   - 학번을 주지 않으면 이메일 앞부분으로 만든다. 여러 학생을 넣어도 명단에서 겹치지 않는다.

  - 다른 하나(트랜잭션 밖에서 기록)는 "기록 실패 시 값 유지" 테스트를 더해 잡았다.
