# T010 구현 노트: 출석 현황과 직접 바꾸기 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC21: 교수는 학생마다 상태를 출석·결석으로 직접 바꾼다(요청이 없어도, 끝난 회차도).
  - 결석 → 출석은 "출석 (수기)"다.
  - 코드 출석을 결석으로 바꿀 때는 확인을 묻는다(화면 몫).
- AC22: 학번, 이름, 상태(출석/출석 (수기)/결석), 출석 시각과 "출석 N / M"을 보인다.
- AC23: 한 번도 시작하지 않은 회차는 표가 없다.
- AC25: 지금 명단만 보인다. 나중에 들어온 학생은 이전 회차가 결석이다. 빠진 학생의 기록은 남는다.
- plan 인터페이스:
  - `GET /classrooms/{id}/sessions/{s}/attendance`: 학생마다 `{roster_entry_id, student_no, name, status, at, source}`, `N / M`, 대기 요청. 시작 안 한 회차는 `{started: false}`다.
  - `PUT …/attendance/{roster_entry_id} {status: present|absent}`: 시작 안 한 회차는 409다.

## 내가 정한 것

1. **현황 응답**은 `{started: true, present, roster, pending, students, requests}`다.
   - `students`는 명단 순서(항목 번호 순, 명단 화면과 같다)다. 학번 순 정렬은 화면(T024)이 한다.
   - `requests`는 T009 노트의 형태 `{id, roster_entry_id, student_no, name, reason, created_at}`다.
2. **`source`**는 마지막 기록이 무엇인지다.
   - `code`, `request`(승인), `manual`(직접 출석·결석), 기록이 없으면 `null`이다.
   - 화면은 `source === "code"`이고 출석일 때 결석으로 바꾸기 전에 AC21 확인을 묻는다.
3. **`at`**은 출석을 만든 마지막 기록의 시각이다(코드 출석, 승인, 직접 출석). 결석이면 `null`이다.
   - 결석으로 바꿨다가 다시 출석으로 바꾸면 그 바꾼 시각이다.
4. **"시작한 적이 있다"는 `first_started_at`이 있다는 뜻이다.** 끝난 회차와 진행 중인 회차 모두 표가 있다.
5. **직접 바꾸기**:
   - 결석 → 출석은 `manual_present`, 출석(코드·수기) → 결석은 `manual_absent` 기록을 더한다. 행위자는 교수 `github_id`다.
   - **같은 상태로 바꾸면 기록을 더하지 않고 알리지 않는다.** 코드로 출석한 학생에게 "출석"을 눌러도 "출석 (수기)"로 내려가지 않는다.
   - 확인 순서(쓰기 잠금 안):
     1. 회차(다른 강좌면 404)
     2. 시작한 적 없음(409 "아직 수업하지 않은 회차입니다.")
     3. 지금 이 강좌 명단의 항목인지(아니면 404 "명단에 없는 학생입니다. 명단을 새로 고친 뒤 다시 시도해 주세요.")
   - 상태 값이 `present`/`absent`가 아니거나 없으면 422 "상태는 출석 또는 결석으로 골라 주세요."다.
   - 보관된 강좌에서도 된다(`attendance.manage`, 끝난 뒤 정리용).
   - 바꾼 뒤 커밋하고 `attendance.tally`(교수)와 `attendance.mine`(그 학생, 입장한 적이 있으면)을 알린다.
   - `events`에는 쌓지 않는다(학생에 대한 일, plan).
6. **현황은 읽기 트랜잭션 하나로 읽는다**(`db.read_snapshot`, 리뷰에서 나온 것).
   - 명단, 기록, 요청을 따로 읽으면 그사이 들어온 학생의 요청이 명단에 없는 채로 끼어들 수 있었다(500).
   - 쓰기 잠금은 잡지 않는다.
7. **대기 요청 기준은 T009 노트 6번과 같다**(처리 안 됨, 지금 명단, 아직 결석).
   - 교수가 직접 출석으로 바꿔도 요청은 목록에서 빠진다. 처리 기록은 남기지 않는다.
   - 요청 뒤 코드로 출석해 빠졌던 요청은 교수가 결석으로 바꾸면 다시 보인다. 처리하지 않았고 결석이기 때문이다(스펙에 없는 판단, 테스트로 고정).
8. **멤버십 찾기를 `identity.membership_of_entry`에 두었다**(C9: `member_identities`는 identity만 읽는다).
9. **`attendance_state`를 정리했다.**
   - 마지막 기록 읽기를 `latest_marks`(회차 전체)와 `last_mark`(한 학생) 둘로 모았다.
   - 출석 수와 현황이 같은 `mark_view`·`waiting_requests`를 쓴다.
   - `latest_kinds`·`status_of`는 쓰는 곳이 없어져 뺐다.

## T021(학생 화면)에 넘길 것

- 교수가 요청한 학생을 직접 출석으로 바꾸면 `attendance.mine`은 `{status: "manual", request: "pending"}`이다. 처리 기록이 없어서다.
- 화면은 `status`가 결석이 아니면 `request`보다 출석 배지를 앞세워야 한다.

## 확인한 것

- 새 테스트는 처음에 35개 중 31개가 실패했다. 통과한 4개는 라우트가 없어 우연히 맞은 것이었다.
- 지금은 40개, 서버 1200개, constitution 35개, ruff check가 통과한다.
- 변형 검사(서브에이전트): 44개 중 39개를 잡았다.
  - 동작이 같은 변형 둘:
    - `first_started_at` 대신 `status != 'scheduled'`
    - 멤버십 찾기에서 강좌 조건 빼기(명단 항목 번호가 한 강좌에만 속한다)
  - 테스트를 더해 잡은 것:
    - 다른 회차 기록 섞기(두 회차 테스트)
    - 409와 404 순서
    - 읽기 트랜잭션 빼기(읽는 도중 다른 연결이 처리를 쓰는 테스트)
- 리뷰(서브에이전트) 반영:
  - 위 6번을 고쳤다.
  - 7번의 다시 보이는 요청, T021에 넘길 것을 적었다.
  - 빈 본문, 코드 출석 → "출석"의 알림 없음, 결석으로 바뀐 학생의 `mine` 테스트를 더했다.
  - 경로 숫자가 아닌 값(`…/attendance/abc`)은 FastAPI 기본 422(영어)다. 화면은 이 값을 보내지 않는다.

## 확인이 필요한 질문

- 위 7번: 코드로 출석해 빠졌던 요청이, 교수가 결석으로 바꾸면 "수기 출석 요청 N"에 다시 세어지는 것. 다시 세지 않게 하려면 말해 달라.
