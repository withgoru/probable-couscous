# T013 구현 노트: 서버 재시작 뒤 출석 유지(C13)

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- 스펙 오류 표 "서버를 다시 시작함":
  - 출석 받는 시간(마감 시각), 출석 기록, 수기 요청과 그 처리는 남는다(C13).
  - 코드는 서버를 다시 시작해도 같은 순간에 같은 값이다.
- plan '출석코드':
  - 코드는 저장하지 않고, 서버 비밀값, 창의 난수, 15초 칸 번호로 계산한다.
  - 받는 순간의 칸과 바로 앞 칸을 받는다.
- plan '마감': 마감 시각은 DB에 있고, 타이머 작업이 없다.
- plan 위험 5: 틀린 코드 제한은 메모리에 있어 재시작 때 풀린다. 받아들인 위험이다.

## 내가 정한 것

1. **새 코드는 없다.** T004~T009가 이미 DB에 먼저 쓰고 답한다. 이 작업은 실제 프로세스를 죽이고 다시 띄우는 회귀 테스트(`tests/test_restart_attendance.py`, `constitution` 표시)만 더한다.
   - 001 `test_restart_process.py`의 `Process`(SIGKILL)를 그대로 쓴다.
2. **재시작 전에 해 두는 일**(학생 다섯 명):
   - 창을 열고 5분 연장한다.
   - 학생 1은 코드로 출석한다.
   - 학생 2의 요청은 승인하고, 학생 5의 요청은 거절한다. 학생 3의 요청은 대기로 둔다.
3. **재시작 뒤 확인하는 것**:
   - **출석 현황**: 학생마다 상태, 출처, 시각, 대기 요청이 같다.
   - **학생 화면**: 학생 2는 `manual`/`approved`, 학생 5는 `absent`/`rejected`다.
   - **처리**: 처리한 요청을 다시 승인하면 409 "이미 처리한 요청입니다."다. 대기 요청은 재시작 뒤에도 승인된다.
   - **마감 시각**: 연장한 값이 그대로다.
   - **같은 칸의 코드**:
     - 재시작 전후의 코드 응답(지금 칸과 다음 칸)을 "칸이 끝나는 시각"으로 맞춰 비교한다.
     - 재시작이 15초보다 짧으면 적어도 한 칸이 겹친다. 겹치는 칸이 없으면 실패로 알린다.
   - **바로 앞 칸의 코드**:
     - 테스트가 DB의 창 번호·난수와 테스트 서버 비밀값으로 직접 계산해 보내고, 받아들여지는지 본다.
     - 칸 경계 2초 안이면 다음 칸까지 기다린다.
     - 서버 출력만으로 하려면 최대 15초를 기다려야 해서 계산을 택했다. 비밀값이 서버 스크립트와 같은지도 테스트한다.
   - **같은 누름의 재전송**(같은 `client_key`): 재시작 뒤에도 처음 답 그대로다.
4. **마감한 창도 확인한다**(리뷰): 마감한 뒤 한 번 더 죽이고 띄운다.
   - 코드 받기는 409다.
   - 닫힌 창의 맞는 코드도 "출석 시간이 끝났습니다…"(409)로 거절한다.
5. **학생이 차례로 들어오는 도우미**: 002 `enter`는 메일이 하나라도 있으면 읽어서, 두 번째 학생부터 앞 학생의 코드를 읽었다.
   - 이 파일에는 새 메일을 기다리는 `enter`를 두었다. 002 테스트는 학생이 한 명이라 그대로 두었다.
6. **틀린 코드 제한이 풀리는 것**(위험 5)은 확인하지 않는다. 받아들인 동작이고 C13과 상관없다.

## 확인한 것

- 이미 있는 구현을 지키는 테스트라 처음부터 통과했다. 그래서 변형 검사로 실패할 수 있음을 확인했다.
- 지금은 2개(본 테스트, 비밀값 확인)이고, 여러 번 돌려도 통과한다. 서버 1244개, constitution 40개, ruff check가 통과한다.
- 변형 검사(서브에이전트): 15개 중 14개를 잡았다. 잡은 것은 다음과 같다.
  - 비밀값이나 칸 번호를 프로세스마다 다르게 하기
  - 시작할 때 난수를 새로 만들기
  - 연장 값을 메모리에만 두기
  - 시작할 때 코드 출석이나 승인 기록, 대기 요청을 지우기, 창을 닫기
  - 지금 칸만 받기
  - 재전송 확인 빼기
- 남은 1개(시작할 때 처리 기록 지우기)는 위 3번의 "다시 승인하면 409"를 더해 잡았다(다시 돌려 확인).
- 리뷰(서브에이전트) 반영:
  - 거절한 요청
  - 대기 요청 처리
  - 마감한 창
  - 연장 응답과 마감 시각이 같은지
  - 비밀값이 서버 스크립트와 같은지
