# 작업: 출석 (코드, 수기 보정)

> 규칙: 작업 하나는 혼자 검토할 수 있는 크기입니다. 모든 수용 기준(AC)은 하나 이상의 작업에 대응해야 합니다. 설계 논의는 plan.md에 씁니다.

- 작업마다 브랜치 하나, Draft PR 하나입니다(`feat/003-T0nn-요약`). 한 번에 작업 하나만 구현하고, 테스트를 먼저 씁니다.
- 순서는 이렇습니다.
  - 기반(T001~T003)과 서버(T004~T013)를 먼저 합니다.
  - 화면 작업 앞에 프로젝터 실험(T014)을 둡니다.
  - 화면(T015~T025)은 해당 서버 작업이 끝난 뒤 시작합니다.
  - 마지막 세 작업(T026~T028)은 전체를 확인합니다.
- AC가 없는 작업은 constitution이나 plan이 요구하는 기반·검증 작업입니다.
- 작업마다 스펙 밖의 판단은 `notes/T0NN.md`에 남깁니다(001·002와 같음).

  - 대응 AC: AC2, AC7, AC5(종료로 닫힘)
  - 의존: T003, T004

- [x] **T006. 연장·마감·다시 받기 서버**
  - 대응 AC: AC4, AC5
  - 의존: T005
  - 먼저 쓸 테스트:
    - 연장하면 마감 시각이 5분 늦춰진다. 열린 창이 없으면 409다.
    - 마감하면 `closed_at`이 기록된다.
    - 다시 받기는 이전 창을 닫고 강좌의 분 값으로 새 창을 연다. 새 난수라 같은 순간의 코드가 다르고, 이미 출석한 학생은 그대로다.
    - 진행 중이 아닌 회차는 409 "진행 중인 수업에서만 출석을 받을 수 있습니다."다.
    - 행동마다 `events`가 기록되고 `attendance.updated`가 발행된다.
    - 보관된 강좌에서는 거부된다(`session.present`).
  - 완료 기준: 테스트가 통과한다.
  - 관련 원칙: C6, C8, C13

- [x] **T008. 학생 코드 출석 서버**
  - 대응 AC: AC6, AC12, AC13, AC14, AC16, AC27
  - 의존: T003, T005
  - 먼저 쓸 테스트: 통합 테스트.
    - 받는 코드: 지금 코드와 바로 앞 코드는 출석이다.
    - 틀린 코드는 422와 AC13 문구이고, 5번째로 틀리면 429와 `retry_after`다.
    - 마감 시각이 지나면 409와 AC14 문구다.
    - 같은 `client_key`로 다시 보내면 처음과 같은 200을 주고 기록은 하나다.
    - 다른 기기로 다시 넣으면 `already: true`이고 상태는 그대로다. 수기로 이미 출석한 학생도 `already: true`다.
    - 명단에서 빠졌거나 로그인이 끊긴 학생은 거부된다.
    - 출석한 뒤 발행:
      - `attendance.tally`는 교수에게만 간다.
      - `attendance.mine`은 그 학생의 연결에만 간다(`_pump`의 멤버십 대상).
  - 완료 기준: 테스트가 통과한다.
  - 관련 원칙: C5, C6, C7, C8, C13

- [x] **T009. 수기 출석 요청과 승인·거절 서버**
  - 대응 AC: AC17, AC18, AC19, AC20
  - 의존: T008
  - 먼저 쓸 테스트:
    - 학생 요청:
      - 사유는 앞뒤 공백을 빼고 1~200자다. 벗어나면 422다.
      - 진행 중인 회차에서만 보낼 수 있고, 회차마다 한 번이다(두 번째는 409).
      - 이미 출석이면 409 "이미 출석했습니다."다.
    - 교수 처리:
      - 승인하면 같은 트랜잭션에서 `request_approved` 기록이 생기고 상태가 "출석 (수기)"가 된다.
      - 거절하면 상태가 그대로다.
      - 두 번째 처리는 409 "이미 처리한 요청입니다."다.
      - 끝난 회차와 보관된 강좌에서도 처리할 수 있다.
    - 발행: 요청과 처리 뒤 교수에게 `tally`, 그 학생에게 `mine`이 간다.
  - 완료 기준: 테스트가 통과한다.
  - 관련 원칙: C6, C7, C8, C12, C13

- [x] **T010. 출석 현황과 직접 바꾸기 서버**
  - 대응 AC: AC21, AC22, AC23, AC25
  - 의존: T009
  - 먼저 쓸 테스트:
    - 출석 현황(`GET …/sessions/{s}/attendance`):
      - 지금 명단 학생마다 학번, 이름, 상태(present/manual/absent), 시각, `source`를 준다.
      - `N / M`과 대기 요청을 함께 준다.
      - 한 번도 시작하지 않은 회차는 `{started: false}`다.
      - 중간에 명단에 들어온 학생은 이전 회차가 결석이다.
      - 명단에서 빠진 학생은 나오지 않지만 기록은 남는다.
    - 직접 바꾸기(`PUT …/attendance/{roster_entry_id}`):
      - 결석에서 출석으로 바꾸면 manual이고, 코드 출석을 결석으로 바꿀 수 있다.
      - 끝난 회차도 되고, 시작하지 않은 회차는 409다.
      - 다른 강좌의 명단 항목은 404다.
    - 직접 바꾼 뒤 `tally`와 `mine`이 발행된다.
  - 완료 기준: 테스트가 통과한다.
  - 관련 원칙: C5, C6, C7, C8
