# 계획: 출석 (코드, 수기 보정)

> 규칙: 스펙의 요구사항을 다시 쓰지 않습니다. "어떻게 만들 것인가"만 씁니다. 확인되지 않은 가정은 아래 "위험과 검증"으로 보냅니다.

## 접근 요약

출석 받는 시간은 회차마다 DB의 행 하나(열린 시각, 마감 시각, 난수)로 두고, 수업 시작과 같은 쓰기 트랜잭션에서 연다.
출석코드는 저장하지 않는다. 서버 비밀값, 그 행의 난수, 15초 칸 번호로 HMAC을 계산하므로 서버를 다시 시작해도 같은 순간에 같은 값이 나온다.
교수 화면과 프로젝터는 HTTP로 "지금 코드와 다음 코드, 칸이 바뀌는 시각, 서버 시각"을 받아 자기 시계를 서버 시각에 맞춰 바꾼다. 교수 연결이 끊겨도 프로젝터는 따로 계속 바꾼다.
출석, 수기 요청, 그 처리, 교수의 직접 바꾸기는 새 표들에 추가만 하고, 상태는 회차·학생별 마지막 기록에서 계산한다.
실시간 알림은 002의 수업 방(`class:{강좌}`)과 `version` 방식을 그대로 쓴다.

## 스펙의 미결정 질문에 대한 답 (사용자 결정 2026-11-27)

스펙의 미결정 질문에도 옮겼다(2026-11-27 sdd-analyze 반영).

- 보관 기간: 001과 같다. 강좌를 보관하고 6개월이 지나 정리할 때(001 `purge`) 출석 기록, 수기 요청과 사유, 그 처리도 함께 지운다. 교수는 그 전에 CSV를 받아 둔다. 학교 규정 확인은 constitution 미결정과 같이 남는다.
- 틀린 코드 제한: 1분에 5번(AC13 그대로).
- 수기 요청 사유: 자유 글, 1~200자(앞뒤 공백을 뺀 길이).
- 프로토타입 3번과 4번: 아래 "위험과 검증" 1, 2로 확인한다.

## 기술 선택과 근거

| 영역 | 선택 | 근거 | 대안 |
|---|---|---|---|
| 서버·DB·실시간 | 001·002와 같다. FastAPI 단일 프로세스, SQLite(WAL, `synchronous=FULL`), 수업 방 `RoomBus` | CLAUDE.md 확정 스택. 001 위험 1에서 200명 동시 쓰기 유실 0 | 없음 |
| 출석코드 | `HMAC-SHA256(SERVER_SECRET, "attendance:{창 번호}:{창 난수}:{칸}")`을 정수로 바꿔 `% 1_000_000`, 6자리로 0 채움. 칸 = `floor(유닉스 ms / 15000)`(모든 강좌가 같은 경계). 받는 코드는 받은 순간의 칸과 바로 앞 칸 두 개, 비교는 `hmac.compare_digest` | AC3·오류 표 "다시 시작해도 같은 값"을 저장 없이 만족. 다시 받기는 새 창 행(새 난수)이라 새 코드(AC5). 001 인증 코드가 이미 HMAC을 쓴다 | 칸마다 코드를 DB에 쓰기: 쓰기가 늘고 얻는 것이 없다 |
| 코드 전달 | 교수·프로젝터 화면이 `GET …/attendance/code`로 지금·다음 코드와 경계 시각, 서버 시각을 받는다. 화면은 요청 왕복의 중간값으로 서버 시각과의 차이를 구해 경계에서 다음 코드로 바꾸고, 바꾸자마자 그다음 코드를 받는다. 받기에 실패하면(연결 끊김) 코드를 흐리게 한다 | 서버에 칸마다 도는 작업이 없다(재시작·다중 화면에 강하다). 다음 코드를 미리 받아 경계에서 화면들이 함께 바뀐다(AC3). 학생에게 코드가 가지 않는다 | 서버가 15초마다 WebSocket으로 밀기: 작업 관리와 재시작 처리가 생기고, 프로젝터 연결만 끊겨도 코드가 멈춘다 |
| 마감 | 마감 시각을 DB에 저장하고, "열림"은 `closed_at IS NULL AND closes_at > 지금`으로 판단한다. 시간이 지나 닫힐 때 서버는 아무것도 쓰지 않고, 화면이 마감 시각(서버 시각 기준)에 스스로 닫은 뒤 `live`를 다시 받아 확인한다 | 타이머 작업 없이 재시작해도 같다(C13). 서버는 받는 순간의 시각으로만 판단한다 | 마감 타이머: 재시작 때 다시 걸어야 한다 |
| 틀린 코드 제한 | 메모리의 미끄럼 창(강좌·멤버십별 틀린 시각 목록). 1분 안에 5번이면 가장 오래된 틀림 + 60초까지 막고 남은 초를 돌려준다 | 출석 결과가 아니라 입력 속도 제한이라 연결 상태로 둬도 된다. 쓰기가 늘지 않는다 | DB에 시도 기록: 200명 몰림에 쓰기만 는다. 재시작 때 풀리는 것은 위험 5 |
| 출석 상태 계산 | 회차·명단 항목별로 `attendance_marks`의 마지막 행(번호가 가장 큰 행). `code`면 출석, `manual_present`·`request_approved`면 출석 (수기), `manual_absent`나 기록 없음이면 결석 | C6: 상태는 기록에서 계산한다. 직접 바꾸기를 몇 번 해도 기록이 남는다 | 상태 열 하나를 고치기: C6 위반 |
| CSV | 표준 `csv` 모듈, UTF-8 BOM, 줄 끝 CRLF. `=`, `+`, `-`, `@`, 탭, CR로 시작하는 칸은 앞에 `'`를 붙인다. 파일 이름은 `Content-Disposition: attachment; filename*=UTF-8''…`(강좌 이름·분반) | AC24 "엑셀에서 한글이 깨지지 않는다". 수식 주입 막기. 새 의존성 없음 | xlsx: 새 의존성 |
| 클라이언트 | SvelteKit SPA, Svelte 5, Tailwind v4, bits-ui, Iconoir(001·002와 같음). 남은 시간 막대와 원형 표시는 SVG와 CSS | 새 의존성 없음 | 없음 |

### 의존성 확인 (C17)

새 의존성 없음. HMAC은 표준 `hmac`, CSV는 표준 `csv`.

## 데이터 모델 변경

마이그레이션 `0004_attendance.sql`. 새 표는 모두 `classroom_id`를 가진다(C5). 이메일·이름·학번 열이 없다(C7). 학생은 명단 항목 번호(`roster_entry_id`, 001 `events.subject_roster_entry_id`와 같은 뜻)와, 학생이 직접 한 일이면 멤버십 번호로 가리킨다. 학번·이름은 출석 현황과 CSV를 만들 때 `roster_entries`에서 읽는다.

- `classrooms.attendance_minutes INTEGER NOT NULL DEFAULT 10 CHECK (attendance_minutes IN (5, 10, 15))`(`ADD COLUMN`). 분반 만들기·새 학기 복제(001 AC12)는 이 값을 가져간다(스펙 AC1).
- `attendance_windows`: `id`, `classroom_id`, `session_id`, `nonce`(난수 16바이트, 16진 문자열), `opened_at`, `closes_at`, `closed_at`(비어 있을 수 있음), `opened_by`(`start`/`reopen`). 부분 고유 색인 `(session_id) WHERE closed_at IS NULL`로 회차마다 "아직 닫지 않은 창"이 하나다. 다시 받기는 같은 트랜잭션에서 이전 창의 `closed_at`을 채우고(시간이 지나 이미 닫혔으면 `closes_at`, 아니면 지금) 새 행을 넣는다. 연장은 `closes_at`을 5분 늦춘다(열려 있을 때만). 수업 종료(002)는 같은 트랜잭션에서 열린 창의 `closed_at`을 채운다. 이 표는 상태 표이고, 열기·연장·마감 행동은 `events`에 따로 쌓는다.
- `attendance_marks`(추가만): `id`, `classroom_id`, `session_id`, `roster_entry_id`, `membership_id`(학생이 코드로 출석했을 때만), `kind`(`code`/`request_approved`/`manual_present`/`manual_absent`), `actor_kind`(`student`/`professor`), `actor_ref`(멤버십 번호 또는 교수 `github_id`), `request_id`(승인일 때), `client_key`(코드 출석일 때, 같은 누름의 재전송 구분), `created_at`. 고유 색인 `(session_id, roster_entry_id) WHERE kind = 'code'`로 코드 출석은 회차마다 한 번(AC16, 다른 기기 포함). 색인 `(session_id, roster_entry_id, id)`.
- `attendance_requests`(추가만): `id`, `classroom_id`, `session_id`, `roster_entry_id`, `membership_id`, `reason`(1~200자), `created_at`. 고유 `(session_id, roster_entry_id)`(AC17 같은 회차에 한 번).
- `attendance_decisions`(추가만): `request_id` 기본 키(처리는 한 번, AC19 되돌리지 않음), `classroom_id`, `decision`(`approved`/`rejected`), `github_id`, `decided_at`. 승인은 같은 트랜잭션에서 `attendance_marks`에 `request_approved`를 넣는다.
- 세 기록 표에는 `UPDATE`를 막는 트리거를 둔다(001 `events`와 같은 방식, C6). `DELETE`는 트리거로 막지 않는다. 사용자 결정대로 보관 6개월 정리에서 지워야 하기 때문이다. 대신 "이 표들을 지우는 코드는 `purge.py` 한 곳뿐"을 회귀 테스트로 고정한다.
- `events`에 종류만 더한다: `attendance_minutes_changed`, `attendance_opened`(시작·다시 받기), `attendance_extended`, `attendance_closed`. 행위자는 교수(시작 때 자동으로 열리면 수업을 시작한 교수). 내용에는 회차·창 번호, 분 값만 넣는다. 학생에 대한 일(출석, 요청, 처리, 직접 바꾸기)은 `events`에 넣지 않는다. `events`는 지울 수 없는데, 사용자 결정은 출석 기록을 정리 때 지우는 것이기 때문이다.
- 정리(001 `purge._purge_one`): 같은 트랜잭션에서 `attendance_decisions`, `attendance_marks`, `attendance_requests`, `attendance_windows`를 그 강좌 것만 지우고 수를 `pii_purged` 기록에 더한다.

## 인터페이스

경로 앞에 `/api`. 변경 요청은 001과 같이 `Origin` 검사. 모든 처리기는 `authz.decide`를 거친다(C8).

- 권한 행동 추가:
  - `attendance.manage`: 출석 받는 시간 설정, 출석 현황, CSV, 요청 처리, 직접 바꾸기, 코드 받기. 소유 교수만, 보관된 강좌도 된다(끝난 뒤 정리용). 거절 사유는 002의 `no_class_permission`("이 강좌에 대한 권한이 없습니다.", AC26).
  - 열기·연장·마감·다시 받기는 002의 `session.present`(소유 교수, 진행 중인 강좌만).
  - `attendance.self`: 그 강좌에 입장한 학생만(`class.view`의 학생 조건과 같고, 교수는 `forbidden`). 명단에서 빠졌거나 로그인이 끊긴 학생은 001 `entered_membership`에서 이미 걸러진다(AC27).
- HTTP, 교수:
  - `PUT /classrooms/{id}/attendance-settings {minutes}`(5·10·15 말고는 422)
  - `POST /classrooms/{id}/sessions/{s}/attendance/reopen`, `…/extend`, `…/close`. 회차가 진행 중이 아니면 409 "진행 중인 수업에서만 출석을 받을 수 있습니다.", 연장·마감할 창이 없으면 409 "출석을 받고 있지 않습니다."
  - `GET /classrooms/{id}/sessions/{s}/attendance/code` → `{current: {code, ends_at}, next: {code, ends_at}, closes_at, server_now}`. 열려 있지 않으면 409.
  - `GET /classrooms/{id}/sessions/{s}/attendance` → 지금 명단 학생마다 `{roster_entry_id, student_no, name, status: present|manual|absent, at, source}`, 위의 `N / M`, 이 회차의 대기 요청. 한 번도 시작하지 않은 회차는 `{started: false}`(AC23).
  - `PUT /classrooms/{id}/sessions/{s}/attendance/{roster_entry_id} {status: present|absent}`(끝난 회차도 된다, 시작하지 않은 회차는 409). 코드 출석을 결석으로 바꾸는 확인은 화면 몫이다(서버는 `source`를 준다).
  - `POST /classrooms/{id}/attendance-requests/{r}/approve`, `…/reject`. 이미 처리됐으면 409 "이미 처리한 요청입니다."
  - `GET /classrooms/{id}/attendance.csv`
- HTTP, 학생(`attendance.self`):
  - `POST /class/{id}/sessions/{s}/attendance {code, client_key}` → 200 `{status, already}`, 422 `{detail: AC13 문구}`, 429 `{retry_after}`, 409 마감(AC14 문구). 같은 `client_key`의 재전송은 처음과 같은 200을 준다(오류 표 "두 번 기록되지 않는다"). 다른 기기로 다시 넣으면 `already: true`(AC16).
  - `POST /class/{id}/sessions/{s}/attendance-requests {reason}` → 201. 진행 중인 회차가 아니면 409, 이미 보냈으면 409, 이미 출석이면 409 "이미 출석했습니다."
- 002의 `GET /class/{id}/sessions/{s}/live`에 `attendance`를 더한다:
  - 교수: 창(`open`, `closes_at`), `present`, `roster`, `pending`, `server_now`.
  - 학생: 창(`open`, `closes_at`), 자기 `status`, 자기 요청 상태(`none`/`pending`/`approved`/`rejected`), `server_now`. 다른 학생 정보는 없다(AC27).
  - 학생 화면은 입장 뒤 이 값으로 출석코드 단계를 보일지 정한다(AC10, AC15).
- WebSocket(002 `/ws/class/{강좌}`), 서버 → 화면. 모든 발행은 DB 기록 뒤(C13).
  - `attendance.updated{회차, 창 요약, version}`: 모든 화면. 열기·연장·마감·다시 받기·수업 종료 때 회차 `version`을 올리고 보낸다. 학생 화면이 출석코드 단계로 바꾸거나(AC11) 수업 화면으로 돌아가는 근거다(AC14). 프로젝터는 카드를 띄우거나 내린다(AC8, AC9).
  - `attendance.tally{회차, present, roster, pending}`: 교수 화면만(002 `PROFESSOR_ONLY`). 출석·요청·처리·직접 바꾸기마다(AC6, AC18). `version` 없이 절댓값이라 늦게 와도 다음 값이 덮는다.
  - `attendance.mine{회차, status, request}`: 그 학생의 연결만. `_pump`에 멤버십 대상 발행을 더한다(002 `goodbye`의 멤버십 비교와 같다). 승인·거절(AC19), 다른 기기의 출석(AC16)을 알린다.
- 화면:
  - 교수 수업 화면(002 `/courses/[id]/live`): 위쪽 출석코드 상자, "출석 N / M", "수기 출석 요청 N" 펼침.
  - 프로젝터(002 `/courses/[id]/projector`): 002가 남긴 오른쪽 사이드바 슬롯에 출석코드 카드(400px, `screens.md`), 슬라이드 iframe은 남은 폭에 맞춘다.
  - 학생(`/join/[token]`): 입장 흐름 끝의 출석코드 단계, 수업 정보 줄의 "출석 완료" 배지, 수기 출석 요청 버튼과 대화상자.
  - 관리 페이지: 강좌 설정의 출석 받는 시간 선택, 회차를 고르면 출석 현황 표(거르기, 직접 바꾸기, 대기 요청), 출석부 내려받기.

## 확장 지점 (자리만)

- 출석 상태의 종류는 계산 함수 하나(`attendance_status`)에만 둔다. 지각(범위 밖)이 생기면 여기와 `kind`만 늘린다.
- 참여 점수(006)는 `attendance_marks`에서 계산한다. 지금은 읽는 함수만 하나로 둔다.
- 한 회차에 여러 번 따로 받기(범위 밖)는 창을 여러 개로 세면 된다. 지금은 창이 여럿이어도 출석은 회차 단위로 하나다.
- 조교의 승인(범위 밖)은 `attendance.manage`의 판단에 역할을 더하면 된다.

## constitution 점검

해당 없음: C3(공개 전환), C4(퀴즈 통계), C9(작성자 확인), C10(채팅 안내)은 이 스펙이 만들지 않는다.

| 원칙 | 충족 방법 |
|---|---|
| C1 | 출석은 `attendance_marks`에만 쌓고 채팅과 섞지 않는다. 006은 이 표에서 계산한다 |
| C2 | 출석, 요청 사유, 처리는 교수 전용 경로(`attendance.manage`)와 학생 본인 경로(`attendance.self`)로만 나간다. 공개 경로(M3)의 후보가 되지 않는다 |
| C5 | 새 표 네 개 모두 `classroom_id`. 모든 조회에 `classroom_id` 조건. 회차와 명단 항목이 같은 강좌인지 쓰기 전에 확인한다 |
| C6 | 출석·요청·처리·직접 바꾸기는 추가만 하는 표에 쌓고 `UPDATE` 트리거로 막는다. 상태는 마지막 기록에서 계산한다. 교수의 열기·연장·마감은 `events`에 쌓는다. 지우기는 보관 6개월 정리뿐이다(사용자 결정, 테스트로 고정) |
| C7 | 새 표에 이메일·이름·학번 열이 없다. 학생은 명단 항목 번호와 멤버십 번호로만 가리킨다. 출석 현황과 CSV의 학번·이름은 교수가 올린 명단에서 읽는다. CSV에 이메일이 없다 |
| C8 | 새 행동 `attendance.manage`, `attendance.self`를 `authz.decide`에 더하고 새 라우트는 모두 `guard`를 거친다. 001의 라우트 전수 검사가 새 라우트도 본다 |
| C11 | 새로 모으는 개인정보는 요청 사유(학생이 쓴 글)뿐이고, 보관 6개월 정리 때 지운다 |
| C12 | 코드로 출석하지 못하면 수기 요청과 교수의 직접 바꾸기가 있다. 교수 연결이 끊겨도 프로젝터는 HTTP로 코드를 받고 학생은 출석할 수 있다 |
| C13 | 창(마감 시각), 출석, 요청, 처리는 DB에 쓴 뒤 발행하고 응답한다. 코드는 저장된 값으로 계산되어 재시작해도 같다 |
| C14 | 001 토큰과 포커스 링, 44px. 입력 칸은 `inputmode="numeric"`, `autocomplete="one-time-code"`. 상태는 아이콘과 글. 출석 결과와 요청 결과는 `aria-live="polite"`. 15초마다 바뀌는 코드는 낭독하지 않는다(`aria-live` 밖, 남은 시간은 글로도 보인다) |
| C15 | 코드 계산, 상태 계산, 제한기를 각각 함수 하나로 둔다. 여러 서버용 제한기는 만들지 않는다 |
| C16 | 지각, 대리 출석 막기, 학생 기록 화면, 조교, 설정 화면, 여러 번 받기는 만들지 않는다 |
| C17 | 새 의존성 없음 |
| C18 | 측정 스크립트는 CI에 넣지 않는다. 서버·클라이언트 테스트는 기존 CI 작업에서 돈다 |

## 테스트 전략

테스트를 먼저 쓴다.

- **필수 회귀(constitution 표시)**
  - (C7) 새 표 네 개에 이메일 열이 없고, 이메일이 조회되지 않는다. 새 `events` 종류의 내용에 이메일·이름·학번이 없다. CSV에 이메일이 없다(001 테스트의 표 목록에 더한다).
  - (C8) 새 HTTP 라우트가 모두 권한 판단을 거친다(001 라우트 전수 검사). 다른 교수, 학생, 다른 강좌 학생의 거절.
  - (C6) 기록 표의 `UPDATE`가 막힌다. 출석 표를 지우는 코드가 `purge.py` 밖에 없다.
  - (C13) 서버를 다시 시작한 뒤 창, 출석, 요청이 남고 같은 순간의 코드가 같다(001 `test_restart_process.py` 방식).
- **단위**: 코드 계산(같은 입력 같은 값, 6자리 0 채움, 창 난수가 다르면 다른 값), 받는 칸(지금·바로 앞은 받고 두 칸 앞과 다음 칸은 거절), 제한기(5번째 틀림에서 막힘, 남은 초, 60초 뒤 풀림), 상태 계산(기록 순서별 결과), 서버 시각 차이 계산, CSV(BOM, CRLF, 수식 주입 막기, 시작한 회차만, 출석 횟수), 사유 길이, 권한 판단 표의 새 행동.
- **통합(서버, 가짜 `Clock`, 메모리 `RoomBus`)**: 수업 시작이 강좌 설정 분으로 창을 연다(설정을 바꾸면 다음 시작부터), 이어서 하기는 열지 않는다, 연장·마감·다시 받기(새 코드, 출석 유지), 수업 종료가 창을 닫는다, 마감 시각이 지나면 코드 출석 거절, 맞는 코드·바로 앞 코드·틀린 코드·잠금, 같은 `client_key` 재전송, 다른 기기의 두 번째 출석, 수기 요청(진행 중만, 한 번, 이미 출석이면 거절), 승인·거절(한 번만, 끝난 뒤에도), 직접 바꾸기(끝난 회차, 시작 안 한 회차 거절), 출석 현황이 지금 명단만 보임과 중간에 들어온 학생의 이전 회차 결석, `live`의 `attendance`(학생은 자기 것만), 발행 순서(DB 기록 뒤)와 대상(`tally`는 교수만, `mine`은 본인만), 보관 6개월 정리가 출석 표를 지우고 수를 기록, 분반 복제가 분 설정을 가져감.
- **클라이언트(vitest)**: 출석코드 상자(남은 시간, 경계에서 다음 코드, 연결 끊김에 흐림), 프로젝터 카드 띄우고 내리기, 학생 출석코드 단계(숫자만, 틀리면 비움, 잠금 남은 초, 보내기 실패 시 숫자 유지, 마감되면 수업 화면과 안내), 수기 요청 대화상자(1~200자), 출석 현황 거르기와 결석으로 바꾸기 확인.
- **E2E(Playwright, 002 `e2e/server.py`)**: 교수 화면·프로젝터·학생 둘을 서로 다른 컨텍스트로 열어 수업 시작 → 학생 하나는 코드로 출석(교수 화면의 수가 바뀜), 다른 하나는 수기 요청 → 교수 승인 → 배지. 마감·다시 받기에 프로젝터 카드가 사라지고 다시 나온다. 관리 페이지에서 직접 바꾸기와 CSV 내려받기. axe 검사와 390px 가로 넘침 없음.
- **측정(구현 뒤, 수동 기록)**: 위험 1의 프로젝터 실험, 위험 2의 200명 출석. 결과는 `notes/`와 000 표에 쓴다.
