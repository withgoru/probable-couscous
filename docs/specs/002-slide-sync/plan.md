# 계획: 슬라이드 동기화와 교수 메시지·자료 푸시

> 규칙: 스펙의 요구사항을 다시 쓰지 않습니다. "어떻게 만들 것인가"만 씁니다. 확인되지 않은 가정은 아래 "위험과 검증"으로 보냅니다.

## 접근 요약

회차와 그 회차의 **현재 위치·가장 멀리 간 위치는 서버 DB가 진실**이다(C13). 교수가 넘기면 서버가 먼저 DB에 쓰고 같은 강좌의 수업 방(`RoomBus`)에 위치를 발행하며, 교수 화면·프로젝터·학생 화면은 그 발행을 받아 따라간다. 슬라이드는 교수가 **저장소에 둔 슬라이드 템플릿**(동기화 애드온과 빌드 설정이 들어 있음)으로 로컬에서 빌드한 zip을 올리고, 서버는 이를 검사해 강좌별 폴더에 풀어 같은 출처의 `/decks/{묶음}/`에서 권한을 확인하며 내려준다. 우리 SvelteKit 화면은 슬라이드를 **iframe으로 얹고**, iframe 안의 애드온과는 `postMessage`로만 대화한다(위치 지시, 슬라이드 수와 단계 수 보고). WebSocket 연결은 우리 화면이 가지며 슬라이드 묶음 안에는 인증이나 연결 코드가 없다. 보낸 항목은 HTTP로 저장한 뒤 같은 방으로 발행하고, 다시 연결한 화면은 HTTP로 현재 상태를 통째로 다시 받아 놓친 것을 채운다.

| 업로드 | `python-multipart`(001에서 이미 사용)로 받고 임시 파일에 흘려 쓴다. 표준 `zipfile`로 검사 후 임시 폴더에 풀고 이름을 바꿔 한 번에 교체 | AC6, 오류 표의 "반쯤 올라간 묶음은 쓰이지 않는다". 새 의존성 없음 | 없음 |

| 실시간 | 새 방 `class:{강좌}`와 WebSocket `/ws/class/{강좌}`. 교수 넘기기만 WebSocket으로 받고(응답 확인 포함), 그 밖의 바꾸기는 HTTP | 넘기기는 잦고 지연에 민감하다. 보내기·거두기·시작·종료는 드물고 중복 방지가 중요해 HTTP가 단순하다 | 넘기기도 HTTP: 요청마다 연결 비용이 들어 지연이 는다 |

| 동기화 현황 | 연결마다 메모리에 `follow`/`browse` 상태를 두고 바뀌면 교수에게만 숫자 두 개를 보낸다. DB에 쓰지 않는다 | AC15, C7. 연결 상태는 진실이 아니라 현황이다 | DB 기록: 의미가 없고 쓰기만 는다 |
| 클라이언트 | SvelteKit SPA, Svelte 5, Tailwind v4, bits-ui, Iconoir(001과 같음). 새 화면 `/courses/[id]/live`(교수 수업 화면), `/courses/[id]/projector`, 학생은 기존 `/join/[token]`의 입장 뒤 화면을 수업 화면으로 바꾼다 | CLAUDE.md 확정 스택 | 없음 |

## 데이터 모델 변경

마이그레이션 `0002_class_sessions.sql`. 세 표 모두 강좌 소속이라 `classroom_id`를 가진다(C5). 학생을 가리키는 열이 없다(C7).

- `class_sessions`: `id`, `classroom_id`, `name`, `sort_order`, `status`(scheduled/live/ended), `deck_id`(비어 있을 수 있음), `current_slide`, `current_click`, `furthest_slide`, `furthest_click`, `version`, `first_started_at`(AC8 "진행 회차"와 AC4 삭제 가능 여부), `started_at`, `ended_at`, `created_at`. 부분 고유 색인: 강좌당 `status='live'` 하나(AC10, 경쟁 상태도 DB가 막는다).
- `decks`: `id`, `classroom_id`, `session_id`, `original_name`, `slide_count`(노트 파일 기준), `size_bytes`, `uploaded_at`, `removed_at`. 파일은 `DATA_DIR/decks/{classroom_id}/{id}/`. 묶음 행은 바꾸지 않고, 지우면 `removed_at`을 쓰고 파일을 지운다.
- `session_items`: `id`, `classroom_id`, `session_id`, `body`(비어 있을 수 있음, 2000자 이하), `url`(비어 있을 수 있음, http/https), `client_key`(보내는 화면이 만든 난수, `(session_id, client_key)` 고유로 두 번 저장 방지), `created_at`, `retracted_at`.
- `events`에 종류만 더한다(표는 그대로): `session_created`, `session_renamed`, `session_deleted`, `session_started`, `session_ended`, `session_resumed`, `deck_uploaded`, `deck_removed`, `item_sent`, `item_retracted`. 행위자는 교수 `github_id`. 내용에는 회차·묶음·항목 번호만 넣고 글 본문은 넣지 않는다(본문은 `session_items`에 남는다).
- 넘기기는 `class_sessions`의 위치 열만 바꾸고 `events`에 쌓지 않는다(수업 하나에 수백 번이고 활동 기록이 아니다).
- 복제(AC42): 원래 강좌의 `class_sessions`를 같은 이름·순서·`scheduled`로 새로 만들고, 살아 있는 묶음은 파일을 하드 링크(안 되면 복사)로 새 강좌 폴더에 두고 새 `decks` 행을 만든다. `session_items`와 위치·시각은 복사하지 않는다. 강좌 사이에 행이나 파일 경로를 공유하지 않는다(C5).
- 보관 6개월 정리(001 `purge`)는 이 표들을 건드리지 않는다. 개인정보가 없다.

## 인터페이스

경로 앞에 `/api`. 변경 요청은 001과 같이 `Origin` 검사. 모든 처리기는 `authz.decide`를 거친다.

- 권한 행동 추가(C8): `session.manage`(회차와 묶음 관리, 소유 교수), `session.present`(시작·종료·이어서·넘기기·보내기·거두기, 소유 교수, 강좌가 `active`일 때만 시작·이어서 → AC11), `class.view`(소유 교수 또는 그 강좌에 입장한 학생: 회차 목록, 현재 상태, 묶음 파일), `deck.notes`(소유 교수만).
- HTTP, 교수:
  - `GET/POST /classrooms/{id}/sessions`, `PATCH/DELETE /classrooms/{id}/sessions/{s}`
  - `PUT /classrooms/{id}/sessions/{s}/deck`(zip 업로드), `DELETE …/deck`, `GET …/deck/notes`
  - `POST …/sessions/{s}/start`, `POST …/end`, `POST …/resume` (진행 중인 다른 회차가 있으면 409와 그 회차 번호)
  - `POST …/sessions/{s}/items`(`client_key` 포함), `POST …/items/{i}/retract`
- HTTP, 교수와 학생(`class.view`):
  - `GET /class/{id}/sessions`(학생은 종료·진행 중만, 교수는 전부)
  - `GET /class/{id}/sessions/{s}/live`(상태 통째로: 회차 상태, 묶음 번호와 슬라이드 수, 현재·가장 멀리 간 위치, 거두지 않은 항목, `version`. 학생에게는 거둔 항목을 빼고 준다)
- 정적: `GET /decks/{deck_id}/{경로}`(`class.view`, 묶음의 강좌로 판단. 001의 `_safe_file`과 같이 폴더 밖 경로 거절)
- WebSocket `/ws/class/{classroom_id}`: 연결 때 `class.view`를 확인하고 교수인지 학생인지 기억한다. 프로젝터는 교수 연결에 `role=projector`를 붙인다.
  - 서버 → 화면: `session.updated{회차, 상태, version}`, `position{회차, 현재, 가장 멀리, version}`, `item.created{회차, 항목, version}`, `item.retracted{회차, 항목 번호, version}`, `presence{follow, browse}`(교수에게만), `resync`, `goodbye{reason}`(학생이 명단에서 빠지거나 로그인이 끊기면 그 학생 연결에 보내고 닫는다 → AC44)
  - 화면 → 서버: 교수 `goto{회차, 슬라이드, 단계, req}` → 서버가 범위를 검사하고 DB에 쓴 뒤 `ack{req, version}`과 `position` 발행. 학생 `mode{follow|browse}`.
  - 모든 발행은 DB 기록이 끝난 뒤에 한다(C13).
- 001과 이어지는 곳: 명단 빼기·로그인 끊기(001 T024)가 방에 `member_revoked{멤버십}`을 발행하면 WebSocket 처리기가 해당 연결을 닫는다. 강좌 보관 때 진행 중인 회차를 어떻게 할지는 스펙 미결정이라 이 plan에서 동작을 정하지 않는다.
- 설정 추가: `DATA_DIR`, `DECK_MAX_BYTES`(기본 100MB), `DECK_MAX_UNZIPPED_BYTES`(기본 300MB), `DECK_MAX_FILES`(기본 5000).

## 확장 지점 (자리만)

- `RoomBus`: 001의 인터페이스를 그대로 쓰고 방 이름만 더한다. 여러 서버용 구현은 만들지 않는다(C15).
- `DeckStore`: 묶음 파일 저장·내려주기·지우기를 한 모듈에 둔다. 지금은 로컬 폴더 하나. 배포 대상이 정해져 오브젝트 저장소가 필요해지면 이것만 바꾼다.
- 프로젝터 오른쪽 사이드바 자리: 프로젝터 화면에 슬롯만 두고 비워 둔다(003 출석코드, 004 채팅이 채운다). 학생 수업 화면의 탭도 '자료' 하나로 시작하되 탭 목록을 늘릴 수 있게 둔다.
- 교수 보조 화면(ProfessorSplit): 넘기기를 WebSocket `goto`로 받으므로 나중에 다른 기기에서도 같은 메시지를 보내면 된다. 지금 화면은 만들지 않는다.

## constitution 점검

해당 없음: C1(채팅 점수), C3(공개), C4(퀴즈 통계), C9(작성자 확인), C10(채팅 안내), C11(새로 모으는 개인정보 없음)은 이 스펙이 만들지 않거나 건드리지 않는다.

| 원칙 | 충족 방법 |
|---|---|
| C2 | 새 표에는 교수가 입력한 것(회차 이름, 묶음, 보낸 항목)만 있다. 학생별 따라가기 상태는 메모리에만 있고 저장하지 않는다. 공개(006)는 거두지 않은 `session_items`만 후보로 받게 될 것이다 |
| C5 | `class_sessions`, `decks`, `session_items`, 묶음 폴더 모두 강좌 단위. 모든 조회에 `classroom_id` 조건. 복제는 행과 파일을 새 강좌로 따로 만든다 |
| C6 | 회차·묶음·보내기·거두기 행동을 `events`에 추가만 한다. 거두기는 `session_items.retracted_at`을 쓰지만 본문은 남기고 `item_retracted`를 따로 쌓는다(001의 입장 요청 상태와 같은 방식) |
| C7 | 새 표에 이메일·이름·학번·멤버십 열이 없다. 연결의 학생 정보는 멤버십 번호로 메모리에만 있고 교수에게는 숫자만 간다 |
| C8 | 새 행동 4개를 `authz.decide`에 더하고, 정적 묶음 경로와 WebSocket도 `guard`를 거친다. 001의 라우트 전수 검사 테스트가 새 라우트도 검사한다 |
| C12 | 연결이 끊겨도 화면은 마지막 상태를 두고, 다시 붙으면 HTTP로 상태를 통째로 받아 위치와 놓친 항목을 되찾는다. 묶음이 열리지 않아도 보내기는 쓸 수 있다 |
| C13 | 진행 중 여부, 위치, 가장 멀리 간 위치, 항목은 DB에 쓴 뒤에 발행한다. 넘기기 확인(`ack`)도 DB 기록 뒤에 보낸다. 서버를 재시작하면 화면은 다시 붙어 DB 값으로 이어진다 |
| C14 | 001의 토큰과 포커스 링. 상태는 아이콘과 글을 함께. 도착 알림은 `aria-live="polite"`, 교수 화면의 키보드 넘기기는 입력 칸에 초점이 있으면 무시. 학생 화면 390px 기준. iframe에는 `title`을 붙인다 |
| C15 | `RoomBus`, `DeckStore`를 인터페이스 뒤에 둔다. 오브젝트 저장소, 여러 서버, 보조 화면은 만들지 않는다 |
| C16 | 출석, 채팅, PDF, 파일 첨부, 자동 종료, 보관 시 회차 종료는 만들지 않는다 |
| C17 | 서버·클라이언트에 새 의존성 없음. Slidev는 교수용 템플릿에만, 버전 고정과 lockfile |
| C18 | `slides-template/`은 CI의 `server`, `client` 작업과 분리한다. 템플릿 빌드 확인은 CI에 넣지 않는다(교수 컴퓨터용이고, 무거운 의존성을 CI에 들이지 않는다). 대신 테스트용 작은 묶음 zip을 저장소에 고정해 서버 테스트가 쓴다 |

## 테스트 전략

테스트를 먼저 쓴다. 필수 회귀 테스트 중 이 스펙이 새로 만드는 것은 없지만, 아래 둘은 `constitution` 표시로 넓힌다.

- **필수 회귀 넓히기(constitution 표시)**
  - (C7) 새 표 세 개에 이메일·이름·학번 열이 없고, 새 `events` 종류의 내용에도 없다(001 테스트의 표 목록에 더한다).
  - (C8) 새 HTTP 라우트, `/decks/…`, `/ws/class/…`가 모두 권한 판단을 거친다.
- **단위**: 위치 계산(다음·이전, 단계 넘기기, 처음과 끝), 가장 멀리 간 위치 갱신(되돌아가도 줄지 않음), 학생 넘기기 범위, zip 검사(템플릿 표시, 크기, 경로 탈출, 링크, 폭탄, 파일 수), 기준 경로 바꾸기, 링크 검사(http/https), 항목 중복 방지(`client_key`), 권한 판단 표의 새 행동.
- **통합(서버, 가짜 `Clock`, 메모리 `RoomBus`)**: 회차 만들기·이름 바꾸기·삭제 조건, 시작(묶음 없음 확인은 화면 몫, 서버는 허용)·진행 중 하나·보관된 강좌 거절, 종료·이어서, 묶음 올리기·바꾸기 금지(진행 중)·지우기, 반쯤 올라간 묶음이 쓰이지 않음, 넘기기 → DB 기록 → `ack`와 발행 순서, 끊겼다 붙어 `live`로 놓친 항목 회복, 거둔 항목이 학생 `live`에 없음, 학생 열람 범위(가장 멀리 간 위치), 다른 강좌 학생·명단에서 빠진 학생 거절과 연결 닫기, 복제 시 회차와 묶음 복사(항목 제외), 서버 재시작 뒤 진행 중 회차와 위치 유지(C13, 001 `test_restart_process.py` 방식).
- **클라이언트(vitest)**: 교수 수업 화면의 버튼 흐림·키보드 넘기기·연결 끊김 표시, 보내기 칸 검사와 실패 시 글 유지, 학생 따라가기/직접 넘겨 보기 전환과 범위 끝 문구, 도착 알림과 읽지 않은 수, `postMessage` 출처 확인. iframe은 가짜 애드온으로 바꿔 끼운다.
- **E2E(Playwright)**: 테스트용 묶음으로 교수 화면·프로젝터·학생 두 명을 서로 다른 컨텍스트로 열어 넘기기·직접 넘겨 보기·보내기·거두기·종료·다시 보기를 확인한다. 학생 연결을 끊었다 붙여 놓친 항목이 나타나는지 본다. axe 검사와 390px 가로 넘침 없음(001 T034 방식).
- **측정(구현 뒤, 수동 기록)**: 위험 1의 200명 동기화, 위험 4의 첫 로딩. 결과는 `notes.md`에 쓴다.
