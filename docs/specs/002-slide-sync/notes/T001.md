# T001 구현 노트: 슬라이드 템플릿과 테스트용 묶음

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- plan: 교수는 저장소의 `slides-template/`으로 로컬에서 빌드한다. 고정 기준 경로 `/__deck__/`, `routerMode: hash`, `--without-notes`, 외부 요청 끄기, 노트는 `classroom-deck.json`에 따로. 애드온은 `postMessage`로만 대화하고, 지시하지 않은 이동은 막고 방향을 `deck:intent`로 알린다(AC26).
- tasks: 템플릿으로 만든 4장짜리(단계 0·3·0·1개) 테스트용 묶음을 저장소에 고정하고, 서버 테스트가 그 약속을 확인한다. CI는 템플릿을 빌드하지 않는다.

## 내가 정한 것 (스펙 밖)

1. **빌드는 항상 임시 폴더(`slides-template/.build/`)에서 한다.** Slidev는 `setup/` 폴더를 슬라이드 파일이 있는 폴더에서만 읽는다(실험으로 확인: 다른 폴더의 `slides.md`를 빌드하면 템플릿의 다리가 빠진다). 그래서 슬라이드 폴더를 복사하고 템플릿의 다리를 덮어 넣은 뒤 빌드한다. 교수가 강의별 슬라이드를 아무 폴더에 둬도 되고, 다리를 실수로 빼거나 바꿀 수 없다.
2. **머리말은 고치지 않고 확인만 한다.** `routerMode: hash`, `fonts.provider: none`, `favicon: false`가 없으면 묶음을 만들지 않고 넣을 줄을 그대로 보여 준다. 교수의 파일을 몰래 바꾸는 것보다 낫다고 봤다.
3. **zip은 `fflate`로 만든다.** Node 표준 라이브러리에 zip이 없고, macOS의 `zip` 명령에 기대면 Windows에서 못 쓴다. C17 확인(2026-11-24): `fflate` 0.8.3, 주 1.7억 다운로드, 2026-07 갱신, 의존성 없음. 템플릿에만 들어가고 서버·클라이언트에는 없다.
4. **같은 입력이면 같은 zip.** 파일 시각을 고정하고 이름 순으로 담는다. 테스트용 묶음을 다시 만들어도 바이트가 같아 쓸데없는 변경이 생기지 않는다(두 번 만들어 해시가 같음을 확인).
5. **`classroom-deck.json` 형식**: `{"format": 1, "slide_count", "slides": [{"no", "title", "note"}]}`. `format`은 나중에 형식이 바뀔 때 서버가 알아보게 둔 것이다. 숨긴 슬라이드(`hide`, `disabled`)는 빼고 센다. 첫 슬라이드의 제목은 Slidev 규칙대로 머리말의 `title`이 된다.
6. **빌드에서 `404.html`, `_redirects`를 뺀다.** hash 방식이라 쓰지 않는다.
7. **다리 안의 동작**
   - 수업 화면 안(iframe)에서 열렸을 때만 켜진다. 혼자 열면(`npm run dev`) 평소 Slidev다.
   - Slidev의 내비게이션 막대와 '이동' 창을 감춘다(눌러도 막히므로 헷갈림만 준다). `contextMenu: false`, `drawings.enabled: false`도 머리말 예시에 넣었다.
   - `deck:goto`가 `deck:limit` 뒤를 가리키면 limit 위치로 간다. 범위 판단은 부모(학생 화면)가 하지만, 다리도 한 번 더 막는다.
   - `deck:mode`는 지금 표시용 값만 문서에 남긴다(이동 규칙은 모드와 상관없이 같다: 지시만 따르고 나머지는 `deck:intent`).
   - 같은 출처의 부모가 보낸 메시지만 받고, 부모에게 보낼 때도 같은 출처로만 보낸다.
8. `dependabot.yml`에 `/slides-template`을 더했다. Slidev를 올리면 테스트용 묶음도 다시 만들어야 해서 README에 적었다.
9. C17 검사 테스트(`test_dependency_pinning.py`)에 템플릿의 버전 고정과 lockfile 확인을 더했다(`constitution` 표시).

## 확인한 것

- `test_deck_fixture.py` 5개(기준 경로, 노트 파일, 노트가 빌드에 없음, 외부 주소 없음, 다리 메시지 이름)와 템플릿 버전 고정 테스트. 처음에는 묶음과 템플릿이 없어 실패했다. 서버 643개, constitution 24개, ruff 통과.
- **브라우저 확인(Playwright, Chromium, 데스크톱과 iPhone 13 흉내, 실험 코드는 버림)**: 테스트용 묶음을 `/decks/7/`로 바꿔 띄웠다.
  - `deck:goto` (2, 1) → `deck:moved` 슬라이드 2, 단계 1, 단계 수 3, 전체 4
  - 키보드 →·← → `deck:intent` next, prev, 위치는 그대로
  - **터치 스와이프(왼쪽, 오른쪽) → `deck:intent` next, prev**, 위치는 그대로. 실험 때 확인하지 못했던 스와이프가 신호로 잡히는 것을 흉내 낸 터치로 확인했다. 실기기 확인은 T030 목록에 남긴다
  - limit (2, 2)에서 goto (4, 1) → (2, 2)에 멈춤
  - 내비게이션 막대 감춤
  - 다른 출처 부모: 부모가 메시지를 하나도 받지 못하고 goto도 무시됨
- 오류 확인: 머리말에서 `routerMode`를 빼면 넣을 줄을 보여 주고 종료 코드 1. 템플릿 폴더 자신의 `slides.md`도 빌드된다(처음에 자기 안으로 복사하려다 실패해 고쳤다).
