# T034 구현 노트: 교수 — 학생에게 공개 스위치와 종료 확인 문구

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC47: '이 회차의 자료'의 묶음 옆에 **학생에게 공개** 스위치. 새로 올리거나 바꾼 묶음은 꺼짐. 상태 글 두 가지. 회차 상태와 관계없이 바꾼다.
- AC37: '수업 종료' 확인 문구가 공개 묶음이면 "…학생은 슬라이드와 받은 자료를 계속 볼 수 있습니다.", 비공개이거나 묶음이 없으면 "…학생은 받은 자료를 계속 볼 수 있습니다. 슬라이드는 공개해야 볼 수 있습니다.".
- AC45: 44px 이상, 키보드, 초점 링, 읽는 이름.

## 내가 정한 것 (스펙 밖)

1. **스위치 모양**
   - 디자인 시스템의 `.switch`(높이 28px)를 `role="switch"` 버튼으로 쓰고, "학생에게 공개" 글자와 함께 높이 44px의 `label`로 감쌌다. 글자를 눌러도 바뀌고, 누를 수 있는 범위가 44px이다.
   - 읽는 이름은 그 글자이고(`aria-labelledby`), 상태 글은 설명으로 잇는다(`aria-describedby`). 바뀌면 화면 낭독기가 켬·끔을 읽는다.
   - E2E 점검 도구가 스위치를 체크 상자처럼 `label`의 높이로 재도록 고쳤다.
2. **바꾸는 동안**
   - 누르는 즉시 바뀐 상태를 보인다. 저장하는 동안 다시 눌러도 한 번만 보낸다.
   - 실패하면 원래대로 되돌리고 이유와 할 일을 보인다. 서버가 거절하면 그 안내를, 연결 문제면 "공개 여부를 바꾸지 못했습니다. 네트워크 연결을 확인하고 다시 눌러 주세요."를 보인다.
   - 묶음이 이미 지워졌으면(다른 탭 등) 안내하고 구역을 다시 불러와 빈 상태를 보인다(리뷰에서 찾음).
   - 저장한 뒤 다시 불러오기가 실패해도 "바꾸지 못했다"고 하지 않는다(리뷰에서 찾음).
3. **묶음을 올리는 동안에는 스위치를 흐린다**(리뷰에서 찾음). 서버는 그 순간의 묶음을 바꾸므로, 새 묶음이 저장된 직후 누르면 옛 묶음에 대한 클릭이 새 묶음을 공개할 수 있다. 새 묶음은 비공개로 시작해야 한다(AC47).
4. **수업 중에도 바꿀 수 있다**: 바꾸기·지우기와 달리 흐리지 않는다(AC47). 교수 수업 화면에는 스위치를 두지 않았다. 관리 페이지에서 바꾸면 수업 화면이 `deck.updated`로 따라와 종료 확인 문구도 맞게 바뀐다.
5. **받아들인 것**: 관리 페이지 탭을 두 개 열어 한쪽에서 바꾸면, 다른 탭은 새로 고칠 때까지 예전 상태를 보인다. 스펙이 요구하지 않는다.
