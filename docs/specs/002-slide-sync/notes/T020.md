# T020 구현 노트: 교수 수업 화면 — 메시지·자료 보내기 탭

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC31: 오른쪽에 **메시지·자료 보내기**. 글 칸(1~2000자)과 링크 칸(선택), **학생에게 보내기**. 보내면 '보낸 항목' 맨 위에 시각과 함께 추가. 둘 다 비면 버튼이 흐려진다.
- AC32: 링크가 http:// 또는 https://가 아니면 보내지 않고 "링크는 http:// 또는 https://로 시작해야 합니다.".
- AC35: 보낸 항목마다 **거두기**. 확인 뒤 학생 화면에서 사라지고, 교수 목록에는 "거둔 항목 · 학생에게 보이지 않습니다.". 되살리지 않는다.
- AC36: 목록 아래 "보낸 항목은 수업이 끝난 뒤 공개할 목록으로 정리됩니다.".
- 오류 동작
  - 보내기 실패: 목록에 넣지 않는다. 글이 칸에 남고 "보내지 못했습니다. 연결을 확인하고 다시 보내 주세요."가 보인다. 두 번 저장되지 않는다.
  - 교수 연결이 끊김: 보내기를 흐린다(T019에서 넘긴 일).
  - 슬라이드 묶음이 열리지 않음: "슬라이드를 열 수 없습니다. 메시지·자료 보내기는 계속 쓸 수 있습니다.".

## 내가 정한 것 (스펙 밖)

1. **배치**: 교수 수업 화면이 두 열이 된다. 왼쪽 슬라이드, 오른쪽 24rem 보내기 카드(목업 Main). 좁은 화면에서는 아래로 내려간다. 채팅 탭(004)이 생기기 전이라 탭 줄 없이 카드 하나다.
2. **목록의 진실은 수업 상태(`items`)다.** 방금 보낸 항목과 방금 거둔 표시는 상태가 다시 오기 전에도 바로 보인다(내 쪽에 잠깐 두고, 상태가 오면 그것을 따른다). 보내거나 거둔 뒤에는 상태를 다시 받는다.
3. **두 번 저장되지 않게(`client_key`)**
   - 실패한 뒤 같은 글을 다시 누르면 같은 열쇠로 보낸다. 서버가 이미 저장했으면 그 항목을 돌려준다.
   - **글이나 링크를 고쳐서 다시 보내면 새 열쇠다.** 응답만 잃은 첫 시도를 서버가 저장해 두었으면, 같은 열쇠로는 고친 글 대신 예전 글이 돌아오기 때문이다(리뷰에서 찾음).
   - 열쇠는 `crypto.getRandomValues`로 만든 16바이트 16진수다. `crypto.randomUUID`는 보안 연결(https, localhost)에서만 있어서, 강의실 LAN 주소처럼 http로 열면 화면이 깨졌다(리뷰에서 찾음).
4. **글은 쓴 그대로 보낸다**(줄바꿈, 들여쓰기, 코드 조각). 공백만 있으면 빈 칸이다. 링크는 앞뒤 공백을 뗀다. 화면의 링크 검사는 서버와 같은 규칙이다(전체가 `http(s)://` 뒤 공백 없는 글자).
5. **오류**
   - 칸 오류(링크 형식, 서버의 칸 오류)는 그 칸 옆에 보이고 칸과 잇는다. 초점을 그 칸으로 옮겨 화면 낭독기가 이유를 읽게 한다.
   - 서버의 다른 거절(4xx, 예: 수업이 끝남)은 서버 문구를 그대로 보인다. 연결 실패와 서버 오류(5xx)는 스펙 문구를 보인다.
   - 어느 경우든 글은 칸에 남는다.
6. **보내는 동안**: 다시 보내지 않고, 칸은 읽기 전용이다(그 사이 쓴 글이 지워지지 않게). 끊긴 동안에는 보내기를 `aria-disabled`로 흐리고 끊김 안내와 잇는다. 글은 미리 써 둘 수 있다.
7. **보냈다는 알림**: 보내면 글이 칸에서 사라지므로 "학생에게 보냈습니다."를 늘 있는 알림 자리(`role="status"`)로 알린다. 스펙에 정해진 문구가 없어 정했다. 화면에도 작게 보인다.
8. **거두기**: 확인 창 "이 항목을 거둘까요?" / "학생 화면에서 바로 사라지고 되살릴 수 없습니다. 이 목록에는 거둔 항목으로 남습니다.". 버튼의 읽는 이름은 "거두기: {글 앞 40자}…"다(글 전체 2000자를 읽지 않게).
9. **링크**는 새 탭으로 열고 `rel="noopener noreferrer"`다. 서버가 http(s)만 받는다.
10. **회차가 바뀌면** 보내기 칸을 새로 시작한다(쓰던 글, 열쇠, 방금 보낸 항목).
11. **T018 문구 고침**: 묶음이 열리지 않을 때의 문구를 오류 동작 문구 "슬라이드를 열 수 없습니다. 메시지·자료 보내기는 계속 쓸 수 있습니다."로 바꿨다. T018에서 잘못 썼다.

## 확인한 것

- 테스트를 먼저 썼다.
  - `SendPanel.test.ts` 27개, `api.test.ts` 3개
  - 교수 수업 화면 5개(문구 고침 포함)
  - E2E "메시지·자료를 보내고 거둔다": 링크 형식 거절 → 보내기 → 서버 상태 확인 → axe → 거두기
- 검증은 서브에이전트가 했다.
  - 변형 검사: 19개 중 13개를 잡았다. 남은 6개는 의미 없는 하나(링크 칸은 브라우저가 공백을 이미 뗀다)를 빼고 모두 테스트를 더해 잡았다.
  - 코드 리뷰: 고친 글이 예전 글로 바뀌는 문제, http에서 열쇠 만들기 실패, 보내는 동안 쓴 글이 지워짐, 보냈다는 알림 없음, 오류 뒤 초점, 긴 버튼 이름, 방금 거둔 항목 표시, 회차 바뀜을 찾았다. 모두 고쳤다.
  - 고친 것은 변형 9개로 다시 확인했다(모두 잡음).
- 화면을 찍어 두 열 배치를 확인했다.
- 클라이언트 587개, svelte-check, 빌드, E2E 16개 통과.
