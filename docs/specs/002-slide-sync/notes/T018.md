# T018 구현 노트: 교수 수업 화면 — 슬라이드와 넘기기

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC12: 메뉴바가 없다. 위쪽에 강좌·회차 이름, 경과 시간, 접속 학생 수, **프로젝터 화면 열기**, **수업 종료**.
- AC13: 현재 슬라이드(16:9), **이전**·**다음**, 다음 슬라이드 미리보기, 발표자 노트. →·Space는 다음, ←는 이전. 글 입력 칸에 초점이 있으면 동작하지 않는다.
- AC14: 다음은 남은 단계 → 다음 슬라이드의 첫 단계. 처음과 끝에서 해당 버튼이 흐려진다.
- AC16·AC17: 다시 열어도 마지막 위치. 두 화면이 같은 위치를 보인다.
- tasks: `ack` 전에는 같은 요청을 다시 보내지 않음, 노트 파일과 빌드의 슬라이드 수가 다르면 알림, 묶음이 없거나 열리지 않으면 "슬라이드를 열 수 없습니다…".

## 내가 정한 것 (스펙 밖)

1. **위치는 서버만 정한다.** 누르면 `goto`를 보내고, 슬라이드는 서버가 DB에 쓴 뒤 발행한 위치로만 움직인다(C13). 이 화면과 다른 탭이 같은 길로 움직이므로 AC17이 따로 처리 없이 지켜진다.
2. **"자리 잡음"(settled)**: 현재 슬라이드가 서버 위치를 그렸다고 알려 온 뒤에만 넘긴다. 그 전에는 그 슬라이드의 단계 수를 모른다. 이 틈에 누르면 단계를 건너뛰거나 이전 슬라이드의 단계 수로 계산한다(리뷰에서 찾음).
   - 기다리는 동안(ack 대기, 슬라이드가 따라오는 중) 버튼은 `aria-disabled`로 흐리게만 하고 누른 것은 받지 않는다. 진짜 `disabled`는 처음과 끝에서만 쓴다. 기다릴 때마다 초점을 잃지 않게 하려는 것이다.
   - 처음과 끝에는 "첫 슬라이드입니다.", "마지막 슬라이드입니다."를 버튼과 연결해 보인다.
   - 지금 위치("2 / 4 슬라이드 · 단계 1/3")는 화면 낭독기에도 알린다(`aria-live="polite"`).
3. **이전**: 앞 단계로 간다. 첫 단계였으면 이전 슬라이드의 마지막 단계로 간다. 이 탭이 그 슬라이드를 그린 적이 없어 단계 수를 모르면 그 슬라이드의 처음으로 간다(예: 새로 고친 직후). 계산은 `src/lib/slides.ts`에 있고 학생 화면도 쓴다.
4. **키보드**
   - 다른 키를 함께 누른 것(Ctrl, Cmd, Alt), 길게 눌러 반복되는 키, Shift+Space는 받지 않는다.
   - 글 입력 칸에 초점이 있으면 받지 않는다.
   - 버튼이나 링크에 초점이 있으면 Space는 그 버튼을 누르는 것이다. 화살표는 그래도 넘긴다.
   - 현재 슬라이드 iframe 안에 초점이 있을 때 누른 키는 애드온이 막고 방향(`deck:intent`)만 알려 온다. 그것도 넘기기로 받는다.
5. **애드온 수정(`slides-template/setup/root.ts`)**: Slidev가 처음 뜰 때 주소를 맞추는 이동을 애드온이 "다음으로 넘기려 함"으로 알렸다. 그래서 화면을 열기만 해도 수업이 한 장 넘어갔다(E2E에서 찾음). 같은 자리로 가는 이동은 막기만 하고 알리지 않게 고쳤다. 테스트용 묶음(`server/tests/fixtures/deck-small.zip`)도 다시 빌드했다. 사용자가 실제로 넘기면 목표 위치가 지금과 달라서 그대로 알린다(리뷰가 Slidev 53 코드로 확인).
6. **서버 수정 두 가지**
   - `GET …/live`의 회차에 `started_at`(마지막으로 시작 또는 이어서 한 시각)을 더했다. 경과 시간에 쓴다. 이어서 했으면 그때부터 센다.
   - `/decks/{묶음}/`(빈 경로)가 404였다(T006 버그, E2E에서 찾음). 데이터 폴더가 링크 뒤에 있으면(macOS의 임시 폴더처럼) `index.html` 경로를 링크를 풀지 않고 비교했기 때문이다. 이제 같은 기준으로 풀어서 비교한다. 폴더 밖 확인은 오히려 더 엄격해졌다.
7. **위쪽 줄**
   - 경과 시간은 "12분", 한 시간부터 "1시간 5분"이다. 15초마다 다시 센다.
   - 접속 수는 현황(`presence`)의 따라가기 수와 직접 넘겨 보기 수를 더한 값이다. 받기 전에는 보이지 않는다.
   - 프로젝터 화면 열기는 `/courses/{강좌}/projector`를 이름 붙은 창(`classroom-projector`)으로 연다. 다시 누르면 같은 창을 쓴다. 그 화면은 T022에서 만든다.
   - **수업 종료 버튼은 있지만 아직 아무 일도 하지 않는다.** 확인 창과 종료는 T021에서 붙인다.
8. **메뉴바 숨기기**: 레이아웃이 `/courses/{id}/live`, `/courses/{id}/projector`에서는 공통 메뉴바를 그리지 않는다(`src/lib/routes.ts`).
9. **노트**
   - 회차와 묶음이 정해지면 한 번 받는다. 묶음이 바뀌면 늦게 온 예전 응답은 버린다.
   - 노트의 슬라이드 수와 빌드가 알려 온 슬라이드 수가 다르면 "노트(4장)와 슬라이드(5장)의 수가 다릅니다." 및 "슬라이드 템플릿으로 다시 빌드해 올려 주세요."를 보인다.
10. **다음 슬라이드 미리보기**는 다음 위치를 보이고, 끝이면 지금 위치를 보인다. 보기용 사본이라 화면 낭독기와 Tab에서 뺐다(`aria-hidden`, `inert`).
11. **상태가 없을 때**
    - 처음 불러오기 전에는 "수업을 불러오는 중…"이다. `classLive`에 `loaded`를 더해, 불러오기 전에 "수업이 없다"고 말하지 않는다.
    - 불러오기에 실패하면 이유와 "잠시 뒤 자동으로 다시 불러옵니다."를 보인다.
    - 진행 중인 수업이 없으면 관리 페이지로 가는 길을 보인다. 끝났으면 "수업이 끝났습니다."다.
12. **한 열 배치**: 오른쪽의 메시지·자료 보내기 탭은 T020에서 붙는다. 그때 목업처럼 두 열이 된다.

## 확인한 것

- 테스트를 먼저 썼다.
  - `slides.test.ts` 10개, `routes.test.ts` 2개
  - 교수 수업 화면 `live.test.ts` 48개(불러오기 3개 포함)
  - `classLive.test.ts` 1개, `api.test.ts` 1개
  - 서버 `test_class_state.py` 2개, `test_deck_serving.py` 1개
- E2E `class-live.spec.ts` 2개는 실제 서버와 실제 묶음으로 확인한다. 한 탭에서 넘기면 다른 탭이 따라오고, 다시 열어도 마지막 위치이며, 끝까지 넘기면 다음이 흐려진다. 이 E2E가 위의 서버 버그와 애드온 버그를 찾았다.
- 검증은 서브에이전트가 했다.
  1. 변형 검사: 19개 중 15개를 잡았다. 남은 4개(이전 단계 1→0, 딱 60분, 끝에서의 미리보기, 다른 슬라이드의 단계 수 무시)는 테스트를 더해 잡았다.
  2. 코드 리뷰: 높은 우선순위 3개(단계 건너뜀, 버튼 위 Space, 초점 잃음), 중간 2개(불러오는 중 "수업 없음", 늦은 노트), 낮은 것(낭독, 이유 문구, 미리보기 숨김)을 찾았다. 모두 고쳤다.
  3. 고친 뒤 다시 검증: 변형 17개 중 12개를 잡았다. 남은 5개는 테스트를 더해 모두 잡았다(따라오는 중의 단계 표시와 끝 판단, 같은 슬라이드의 다른 단계, 기다릴 때 이전 버튼의 초점, 늦게 실패한 예전 노트). 교수 수업 화면 E2E를 5번 되풀이해 10/10 통과했다.
