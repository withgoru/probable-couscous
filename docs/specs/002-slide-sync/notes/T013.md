## 스펙과 plan에서 읽은 것

- tasks: 실제 서버 프로세스로 수업을 시작해 넘기고 보낸 뒤 강제로 끝내고 다시 띄우면, 진행 중 회차·현재와 가장 멀리 간 위치·항목·거둔 상태가 그대로다(001 `test_restart_process.py` 방식).
- plan C13: 위치·항목은 DB에 쓴 뒤 발행한다. 서버를 다시 시작하면 화면은 다시 붙어 DB 값으로 이어진다.

## 내가 정한 것 (스펙 밖)

1. **001 테스트의 서버 띄우기 도구를 그대로 쓴다.** `test_restart_process.py`의 `Process`(가짜 GitHub 로그인, 메일 내용 확인용 경로가 있는 uvicorn 프로세스)와 fixture를 가져왔다. 서버 코드는 바꾸지 않았다.
2. **넘기기는 실제 WebSocket으로 한다.** 서버가 이미 쓰는 `websockets` 라이브러리의 동기 클라이언트로, 교수 쿠키를 실어 `/ws/class/{강좌}`에 붙는다. 새 의존성은 없다.
3. **확인 범위**
   - 죽이기 전과 뒤의 `GET …/live` 응답 전체가 같다(위치, 가장 멀리 간 위치, 항목, 거둔 시각, `version`).
   - 학생에게는 거둔 항목이 여전히 없다. 볼 수 있는 끝(`limit`)과 묶음 파일도 그대로다.
   - 새 프로세스에서 이어서 넘기면 학생이 받고, `version`은 끊기지 않고 오른다.
4. **constitution 표시를 붙였다**(`-m constitution`, 001 C13 테스트와 같음). constitution 테스트가 30개에서 31개가 된다.
