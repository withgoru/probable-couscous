# T031 구현 노트: 수업 중 보관 막기

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC46: 수업이 진행 중인 강좌는 보관할 수 없다. "{회차 이름} 수업이 진행 중입니다. 수업을 끝낸 뒤 보관해 주세요."와 그 회차로 가는 버튼. 수업과 학생 로그인은 그대로다.
- plan: 보관은 같은 쓰기 트랜잭션에서 진행 중 회차를 찾고 409 `{detail, live_session_id}`. 시작·이어서 하기는 `UPDATE`에 "강좌가 `active`" 조건을 붙인다.

## 내가 정한 것 (스펙 밖)

1. **보관 거절 순서**: 진행 중 회차가 있으면 AC46 안내를 먼저 준다. 없을 때만 "이미 보관된 강좌입니다."를 본다. 수업 중인 보관된 강좌는 이제 생기지 않으므로 둘이 겹치지 않는다.
2. **시작·이어서 하기가 보관과 엇갈리면** "보관된 강좌는 수업을 시작할 수 없습니다."(409, AC11과 같은 문구). 권한 판단에서 막히는 것과 같은 결과다.
3. **종료는 그대로 보관된 강좌에서도 된다(T007).** 이번 변경 전에 생겼을 수 있는 "보관된 강좌의 진행 중 회차"를 끝낼 수 있게 남겼다. T007 테스트는 이 상태를 DB에 직접 만들어 확인하도록 바꿨다(보관 API로는 더 이상 만들 수 없다).
4. **화면**
   - 보관 확인 창 안에 서버 안내를 그대로 보이고, 할 일로 "수업 화면에서 수업 종료를 누른 뒤 다시 보관해 주세요."를 붙인다.
   - '수업 화면으로' 버튼은 `/courses/{강좌}/live`(plan의 교수 수업 화면 주소)로 간다. 강좌당 진행 중 회차는 하나라 회차 번호는 주소에 넣지 않았다. **이 화면은 T018에서 생긴다.** 그 전까지는 눌러도 빈 화면이다.
   - 목록은 다시 불러오지 않는다. 아무것도 바뀌지 않았기 때문이다.
5. **API 오류에 덧붙은 값**: `api.ts`의 오류 읽기가 `detail` 옆의 값(`live_session_id`)을 `ApiError.data`에 담도록 했다. 다른 API의 동작은 같다(덧붙은 값이 없으면 `data`가 비어 있다).
