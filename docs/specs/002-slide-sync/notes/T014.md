# T014 구현 노트: 수업 연결 모듈과 슬라이드 다리

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- plan "놓친 것 채우기": 연결 → 구독 → `GET …/live`로 통째로 받기 → 받은 `version`보다 큰 발행만 적용. 끊겼다 붙거나 `resync`를 받으면 다시 통째로. 휴대폰 화면이 다시 보이면 연결을 확인한다.
- plan "iframe과의 대화": `deck:ready`·`deck:moved`·`deck:intent`를 받고 `deck:goto`·`deck:limit`·`deck:mode`를 보낸다. 보낸 쪽 출처를 항상 확인한다. 이동 판단은 학생 화면 한 곳에서만 한다.
- tasks: 다시 붙는 간격 1·2·5·10초. 가짜 WebSocket과 가짜 iframe으로 vitest.

## 내가 정한 것 (스펙 밖)

1. **모듈 두 개**: `src/lib/classLive.ts`(수업 연결)와 `src/lib/deckBridge.ts`(슬라이드 다리). 둘 다 Svelte 스토어 약속(`subscribe`)을 지켜서 화면이 `$이름`으로 바로 쓴다. 001 `adminLive.ts`와 같은 방식(가짜 소켓·위치 주입)이다.
2. **수업 연결이 따라가는 회차**: 정한 회차(다시 보기)가 있으면 그 회차, 없으면 회차 목록의 `live_session_id`다. 회차 상태가 바뀌면(`session.updated`) 다시 받아서, 수업이 시작되면 진행 중 회차로 넘어간다(AC23).
3. **발행 적용 규칙**: 받은 `version`의 **바로 다음 번호만** 적용한다.
   - 같거나 작은 번호는 무시한다(이미 받은 것).
   - 번호를 건너뛰었으면 놓친 것이 있으므로 통째로 다시 받는다.
   - 불러오는 동안 온 발행은 모아 두었다가 받은 뒤 차례로 적용한다.
4. **역할별 적용**
   - 위치(`position`)는 모두에게 바로 적용한다(AC25의 1초). 진행 중에는 묶음이 바뀌지 않으므로 볼 수 있는 끝(`limit`)도 가장 멀리 간 위치로 함께 옮긴다.
   - 학생: 보낸 항목은 바로 붙이고, 거둔 항목은 바로 뺀다.
   - 교수: 항목이 바뀌면 통째로 다시 받는다. 교수 목록에는 거둔 시각이 필요한데 발행에는 없어서다.
5. **넘기기(`goto`)는 약속(Promise)이다.**
   - 요청마다 `req`를 붙이고 `ack`의 `version`으로 끝난다. 서버가 거절하면 `{reason, message}`로 실패한다.
   - 연결이 없거나 기다리는 중에 끊기면 바로 실패한다: "연결이 끊겼습니다. 다시 연결되면 넘겨 주세요." 다시 보내지는 않는다. 교수가 다시 누르면 된다.
6. **학생 따라가기 상태**: 바꿀 때 서버에 알리고, 다시 붙으면 직접 넘겨 보는 중일 때만 다시 알린다. 서버는 새 연결을 따라가는 중으로 세기 때문이다.
7. **화면이 다시 보이면**: 연결돼 있으면 통째로 다시 받는다. 끊긴 채였다면 기다리던 간격을 무시하고 바로 다시 붙는다.
8. **불러오기 실패**: 안내(`loadError`)를 두고 1·2·5·10초 간격으로 다시 불러온다. 마지막 상태는 지우지 않는다.
9. **내보내기**: `goodbye`를 받거나 4403으로 닫히면 상태가 `gone`이 되고 다시 붙지 않는다(T011 약속).
10. **슬라이드 다리**
    - 같은 출처이고 그 iframe 창에서 온 메시지만 받는다. 모양이 맞지 않는 메시지는 버린다.
    - 보낼 때도 대상 출처를 같은 출처로 정한다(`*`를 쓰지 않는다).
    - `deck:ready` 전의 지시는 종류마다 마지막 것만 기억했다가 준비되면 보낸다. iframe이 다시 뜨면(새 `deck:ready`) 다시 보낸다.
    - "제한 없음"(`limit: null`)도 지시로 기억한다.
