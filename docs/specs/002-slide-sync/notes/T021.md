# T021 구현 노트: 수업 종료 확인

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC37: **수업 종료**를 누르면 "수업을 끝낼까요? 학생은 이번 수업에서 본 슬라이드와 받은 자료를 계속 볼 수 있습니다."를 확인한 뒤, 회차가 '종료'가 되고 관리 페이지로 돌아간다.
- tasks: 취소하면 그대로다.

## 내가 정한 것 (스펙 밖)

1. **확인 창**: 기존 `ConfirmDialog`를 쓴다.
   - 제목 "수업을 끝낼까요?", 설명은 AC37의 뒷문장, 확인 버튼 "수업 종료"(위험 모양).
   - 열리면 초점은 '취소'에 있다(Enter를 잘못 눌러도 끝나지 않게).
   - 끝내지 못하면 창 안에 이유를 보이고 수업 화면에 머문다. 서버의 거절은 서버 문구, 연결 실패는 "수업을 끝내지 못했습니다." + "네트워크 연결을 확인하고 다시 시도해 주세요."다.
2. **끝낼 회차는 확인 창을 연 때 정한다.** 교수 연결은 진행 중인 회차를 따라가므로, 그 사이 다른 탭에서 이 회차를 끝내고 다른 회차를 시작하면 확인 시점의 회차가 바뀐다. 연 때의 회차를 끝내야 교수가 고르지 않은 회차를 끝내지 않는다. 이미 끝난 회차를 끝내도 서버는 그대로 돌려주므로 관리 페이지로 간다(리뷰에서 찾음).
3. **확인 창이 열린 동안에는 키보드로 슬라이드를 넘기지 않는다.** 발표용 리모컨이 보내는 화살표 키가 창 뒤에서 학생 모두의 슬라이드를 넘기지 않게 한다(리뷰에서 찾음).
4. **취소하면 초점을 '수업 종료' 버튼으로 돌려준다**(001 보관 확인 창과 같다). 다시 누르면 창이 다시 열린다(리뷰와 변형 검사에서 찾음).
5. **끝내는 중에 화면을 떠났으면**, 요청이 끝난 뒤 관리 페이지로 끌고 가지 않는다.
6. **'수업 종료' 버튼은 진행 중인 회차가 있을 때만 보인다.** 수업이 없거나 이미 끝났으면 없다.

## 확인한 것

- 테스트를 먼저 썼다.
  - 교수 수업 화면 10개: 확인 문구, 끝내고 이동, 취소, 연결 실패, 서버 거절, 버튼 없음, 리뷰 뒤 추가 4개
  - `api.test.ts` 1개
  - E2E "수업 종료를 확인하면 관리 페이지로 돌아가고 회차가 종료다": 확인 창 axe → 취소(초점 돌아옴) → 끝내기 → 관리 페이지의 회차 선택이 '종료', '이어서 수업하기' 버튼, 서버 상태 `ended`
- 검증은 서브에이전트가 했다.
  - 변형 검사: 10개 중 9개를 잡았다. 남은 하나(취소가 상태를 되돌리지 않음)는 "취소 뒤 다시 열기" 테스트로 잡았다.
  - 코드 리뷰: 다른 회차를 끝낼 수 있음(높음), 창 뒤 화살표 넘기기, 취소 뒤 초점, 화면을 떠난 뒤 이동을 찾았다. 모두 고쳤다.
  - 고친 것은 변형 5개로 다시 확인했다(모두 잡음).
- 클라이언트 598개, svelte-check, 빌드, E2E 17개 통과.
