# T007 구현 노트: 수업 시작·종료·이어서 하기 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC9: 예정 회차를 시작하면 '진행 중'. 슬라이드 없이 시작할지는 화면이 확인한다(서버는 허용).
- AC10: 강좌당 진행 중 하나. 다른 회차가 진행 중이면 "{회차 이름} 수업이 진행 중입니다. 먼저 끝내 주세요."와 그 회차로 가는 버튼.
- AC11: 보관된 강좌는 "보관된 강좌는 수업을 시작할 수 없습니다.".
- AC37·AC38: 종료하면 '종료', 학생 화면은 새로 고치지 않아도 바뀐다(발행).
- AC40: 이어서 하면 마지막 위치와 가장 멀리 간 위치가 그대로이고, 다른 회차가 진행 중이면 AC10과 같다.
- plan: `POST …/start`, `…/end`, `…/resume`. 진행 중인 다른 회차가 있으면 409와 그 회차 번호. `session.updated{회차, 상태, version}`를 `class:{강좌}` 방에. 기록 종류는 `session_started`, `session_ended`, `session_resumed`.

## 내가 정한 것 (스펙 밖)

1. **종료는 `session.manage`로 판단한다(plan은 `session.present`).** `session.present`는 보관된 강좌를 거절한다(T003). 수업 중에 강좌를 보관하면 그 회차를 끝낼 방법이 없어 '진행 중'으로 묶여 남는다. 끝내기는 정리하는 일이라 보관된 강좌에서도 되게 했다. 시작과 이어서 하기는 그대로 `session.present`라서 보관된 강좌에서 거절된다. "보관하면 진행 중인 수업도 끝나는가"는 스펙의 열린 질문으로 남아 있다(아래 질문).
2. **409 응답 모양은 `{"detail": 안내, "live_session_id": 번호}`.** 화면(T018)이 안내를 그대로 보이고 그 회차로 가는 버튼을 만든다.
3. **같은 요청을 다시 보내도 괜찮다.** 이미 진행 중인 회차를 시작하거나 이어서 하면, 또는 이미 끝난 회차를 끝내면 200과 지금 상태를 돌려준다. 이때는 아무것도 바꾸지 않고 기록하지 않으며 발행하지 않는다(두 번 누름, 다시 보낸 요청). 순서가 맞지 않는 요청은 409다.
   - 끝난 회차를 시작하면 "끝난 회차입니다. '이어서 수업하기'로 다시 시작해 주세요."
   - 예정 회차를 끝내거나 이어서 하면 "아직 시작하지 않은 회차입니다."
4. **진행 중 하나는 DB 색인 하나가 지킨다.** 미리 확인하는 코드도 처음에 썼지만, 변형 검사에서 색인이 결과를 똑같이 막아서 뺐다. 색인에 막히면 진행 중인 회차를 읽어 AC10 안내로 바꾼다. 두 화면이 동시에 눌러도 같다(쓰기 트랜잭션이 직렬로 처리된다).
5. **응답은 회차 목록 항목 + `version`.** 위치와 항목은 T008의 `…/live`가 준다.
6. **발행은 커밋 뒤, 실패해도 결과는 그대로다.** `realtime.publish_class`를 더했고 `publish_admin`과 같은 내부 함수를 쓴다. 발행에는 번호·상태·`version`만 싣는다.
7. **시작은 위치를 따로 되돌리지 않는다.** 예정 회차는 위치가 기본값(1번·0단계)이고 넘기기는 진행 중에만 된다. 테스트가 시작 뒤 위치가 1·0인지 확인한다.
