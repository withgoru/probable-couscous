# T010 구현 노트: 보내기·거두기 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC31: 글(1~2000자)과 링크(선택). 둘 다 비면 보낼 수 없다.
- AC32: 링크는 http:// 또는 https://로 시작해야 하고, 아니면 "링크는 http:// 또는 https://로 시작해야 합니다.".
- AC33: 보낸 항목은 1초 안에 학생 화면에 나타난다.
- AC35: 거두기는 되살리지 않는다. 교수 목록에는 거둔 항목으로 남는다.
- plan: `POST …/items`(`client_key`), `POST …/items/{i}/retract`, `item.created{회차, 항목, version}`, `item.retracted{회차, 항목 번호, version}`, 기록 `item_sent`·`item_retracted`(본문 없음).

## 내가 정한 것 (스펙 밖)

1. **오류 모양은 001 명단 API와 같은 `{field, message}`.** 화면이 어느 칸 옆에 문구를 둘지 안다. 칸 이름은 `body`, `url`이고, 칸과 무관하면 `null`이다.
   - 둘 다 비었으면 "글이나 링크를 입력해 주세요."
   - 글이 2000자를 넘으면 "글은 2000자 이하로 입력해 주세요."
   - 링크가 2000자를 넘으면 "링크는 2000자 이하로 입력해 주세요."(스펙에 없는 상한. 터무니없는 값만 막는다)
   - `client_key`가 없거나 이상하면 "보내기 요청이 올바르지 않습니다. 화면을 새로 고쳐 주세요."
2. **글은 쓴 그대로 둔다.** 공백만 있으면 빈 칸으로 본다. 앞뒤 공백, 줄바꿈, 들여쓰기는 교수가 쓴 대로 저장한다(코드 조각을 보낼 수 있다). 링크는 앞뒤 공백을 뗀다.
3. **링크 검사**: 전체가 `http://` 또는 `https://` 뒤에 공백 없는 글자로 이뤄져야 한다. `HTTPS://`처럼 대문자도 받는다. `javascript:` 같은 다른 형식은 모두 거절한다.
4. **`client_key`**: 영문·숫자·`-`·`_` 1~64자이고, 회차마다 따로 센다. 같은 키가 다시 오면 처음 저장한 항목을 같은 응답(201)으로 돌려준다. 새로 저장하지 않고, 기록하거나 발행하지도 않는다.
   - 수업이 끝난 뒤 늦게 온 같은 키도 저장된 항목을 돌려준다. 처음 온 요청만 "진행 중인 회차" 조건을 본다.
   - 거둔 뒤에 같은 키가 오면 거둔 항목 그대로다(되살아나지 않는다).
5. **진행 중이 아니면** 409 "진행 중인 수업에만 보낼 수 있습니다.". 다른 강좌의 회차나 없는 회차는 404.
6. **거두기는 수업이 끝난 뒤에도 된다.** 다시 보기(AC39)에 남은 항목을 정리할 수 있게 했다. 이미 거둔 항목을 다시 거두면 처음 거둔 시각 그대로 돌려준다.
7. **발행 내용**: `item.created`에는 학생 화면이 바로 붙일 수 있게 항목(`id`, `body`, `url`, `created_at`)을 싣는다. 거둔 시각은 싣지 않는다. 학생에게 가는 내용과 같고, 개인정보가 없다. `item.retracted`에는 번호만 싣는다.
8. **`version`**: 보내기·거두기도 회차 `version`을 1 올린다. 넘기기·시작·종료와 같은 수 하나라 화면이 놓친 것을 알아본다.
