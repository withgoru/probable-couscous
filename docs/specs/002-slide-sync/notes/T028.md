## 스펙과 plan에서 읽은 것

- tasks T028: 테스트용 묶음으로 교수 화면·프로젝터·학생 두 명을 서로 다른 컨텍스트로 연다. 아래를 차례로 지난다.
  1. 시작
  2. 넘기기(학생·프로젝터가 따라옴)
  3. 비공개 묶음은 따라가기만
  4. 교수가 공개
  5. 학생이 넘겨 따라가기 풀기와 끝까지
  6. '교수 화면으로'
  7. 보내기·거두기
  8. 학생 연결 끊었다 붙이기(놓친 항목 회복)
  9. 종료
  10. 다시 보기
- 완료 기준: CI의 `e2e`에서 통과.

## 내가 정한 것 (스펙 밖)

1. **테스트 하나로 수업 한 번을 끝까지 따라간다**(`e2e/class-flow.spec.ts`). 각 화면의 자세한 동작은 화면별 E2E(`class-live`, `student-class`)가 이미 본다. 여기서는 화면들이 함께 움직이는지를 본다.
2. **누가 무엇을 하는가**
   - 교수: 관리 페이지에서 수업 시작 → 수업 화면 → 프로젝터 창을 연다.
   - 공개: 같은 브라우저의 다른 탭(관리 페이지)에서 공개 스위치를 켠다. 수업 화면에는 스위치가 없다(사용자 결정).
   - 보내기·거두기·종료: 수업 화면에서 화면을 눌러서 한다.
   - 묶음 올리기와 학생 명단은 API로 준비한다(화면은 다른 E2E가 본다).
   - 학생 두 명은 각자 휴대폰 크기의 브라우저로 이메일·코드 입장을 거쳐 대기 화면에서 기다린다. 수업이 시작되면 새로 고치지 않고 수업 화면이 된다.
3. **한 화면이 움직일 때 다른 화면이 그대로인 것도 본다**
   - 학생 A가 넘겨 보는 동안 B, 프로젝터, 서버의 수업 위치는 그대로다.
   - 교수가 넘기면 B와 프로젝터는 따라오고 A는 보던 곳에 머문다.
   - '교수 화면으로'는 교수의 지금 위치로 간다.
   - 동기화 현황 숫자(따라가는 중·직접 넘겨 보는 중)도 따라 바뀐다.
4. **연결 끊기**: 학생 B의 페이지만 WebSocket을 감싸 직접 끊는다(T027과 같은 도구, `e2e/class-helpers.ts`로 옮겼다). A는 붙어 있어서 끊긴 동안 보낸 항목이 바로 오는지 함께 본다.
5. **정리**: 실패해도 연 브라우저 컨텍스트를 닫는다.

## 확인한 것

- 이 작업은 테스트 코드뿐이라 변형 검사는 하지 않았다. 검증은 서브에이전트의 리뷰로 했다.
  - 막는 문제는 없었다.
  - 흔들릴 수 있는 곳 하나: 공개 스위치는 화면이 먼저 바뀌므로, 서버에 남기 전에 탭을 닫을 수 있었다. 서버에 남은 것을 확인한 뒤 닫는다.
  - 닿기만 하고 확인하지 않던 것을 더했다.
    - 넘겨 보는 동안 교수가 넘기면 A는 그대로
    - 프로젝터가 학생의 넘기기에 반응하지 않음
    - 회차가 진행 중이 됨
    - 비공개 묶음에서 →
    - 교수 목록의 최근 항목과 거둔 표시
    - 두 학생의 다시 보기 자료
    - 다시 보기 끝에서 다음이 흐려짐
    - 지난 회차 목록
- 이 테스트를 5번 이어서 돌려 모두 통과했다(한 번에 약 8초).
