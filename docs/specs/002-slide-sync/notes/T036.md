# T036 구현 노트: 학생 — 미리 볼 수 있는 회차

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC49: 학생 대기 화면의 지난 회차 목록 위에 **미리 볼 수 있는 회차**가 있다.
  - 공개 묶음이 있는 '예정' 회차가 회차 순서대로 보인다.
  - 열면 처음부터 끝까지 넘겨 본다.
  - 그런 회차가 없으면 목록이 보이지 않는다.
  - 미리 보던 회차의 수업이 시작되면 AC23대로 수업 화면으로 바뀐다.
- 서버는 T032에서 이 회차들을 목록에 넣고 순서를 정했다. T033에서 공개 묶음의 파일을 내준다.

## 내가 정한 것 (스펙 밖)

1. **목록**
   - 서버가 준 예정 회차 가운데 공개 묶음이고 열 수 있는 것만 보인다. 열 수 없는 묶음(파일 없음)은 미리 볼 것이 없어 뺐다(리뷰에서 찾음).
   - 순서는 서버가 준 대로(회차 순서)다.
   - 버튼은 "미리 보기"이고, 읽는 이름은 "{회차 이름} 미리 보기"다.
2. **미리 보기 화면**: 다시 보기 화면을 그대로 쓰되 세 가지가 다르다.
   - 제목은 "{회차 이름} 미리 보기", 슬라이드 이름은 "미리 보는 슬라이드"다.
   - 돌아가는 버튼은 "회차 목록으로"다.
   - 수업 전이라 받은 자료가 없어 '자료' 구역을 두지 않는다.
   - 묶음 파일이 없으면 "슬라이드를 열 수 없습니다. 목록으로 돌아가 주세요."(리뷰에서 찾음)
3. **새로 고치지 않아도 목록이 바뀐다**
   - 기다리는 동안 교수가 공개·비공개를 바꾸거나 묶음을 올리거나 지우면 목록을 다시 받는다.
   - 다시 연결되거나 `resync`가 와도 다시 받는다(리뷰에서 찾음).
   - 다시 받는 동안 보던 목록은 그대로 둔다. 실패해도 보던 목록은 그대로이고, 아직 아무것도 없으면 실패를 알린다(리뷰에서 찾음).
   - 미리 보기에서 목록으로 돌아오면 다시 받는다. 보는 동안 지워진 회차가 남지 않게 하려는 것이다(리뷰에서 찾음).
4. **보는 동안 볼 수 없게 되면**(비공개로 바뀜, 묶음을 지움·바꿈. 학생에게는 없는 회차가 된다)
   - "이 회차는 이제 미리 볼 수 없습니다."와 "목록으로 돌아가 주세요."를 보인다.
   - 처음 열 때 이미 그렇다면(목록을 받은 뒤 지워짐) 같은 안내다.
   - 이 안내는 경고(`role="alert"`)로 읽힌다. 알림 자리로 다시 알리면 두 번 읽혀서 하지 않는다(리뷰에서 찾음).
   - 초점을 잃었으면 '회차 목록으로'에 둔다. 다른 곳에 있으면 그대로 둔다.
   - 그 뒤에 교수가 다시 공개해도 이 화면은 바뀌지 않는다. 목록으로 돌아가 다시 연다(리뷰에서 찾음, 초점이 다시 움직이지 않게).
5. **수업이 시작되면**: 미리 보던 회차든 다른 회차든 수업 화면으로 바뀌고 "수업이 시작되었습니다."가 읽힌다(T023 그대로).

- 테스트를 먼저 썼다(구현 전 실패 확인).

  - `ReplayView.test.ts`: 미리 보기 2개, 검증 뒤 6개

- 검증은 서브에이전트가 했다.
  - 변형 검사: 26개 중 16개를 잡았다. 놓친 것은 테스트를 더해 잡았다.
    - 진행 중·끝난 회차 거르기
    - 다른 알림·수업 중에는 목록을 받지 않음

    - '미리 볼 수 없음'이 미리 보기의 404에만 해당함

    - 지워진 회차가 남음: 돌아오면 다시 받고, 처음 열 때 맞는 안내를 보인다.
    - 다시 받기가 끼어들면 불러오는 중에 멈춤: 고쳤다.
    - 파일 없는 묶음의 안내: 고쳤다.
    - 두 번 읽힘: 경고로만 읽힌다.
    - 다시 공개되면 초점이 움직임: 안내를 지킨다.

## 확인이 필요한 질문

- 서버는 회차 이름을 바꾸거나 지울 때 수업 방에 알리지 않는다. 그래서 대기 화면의 미리 보기 목록은 다른 알림이 오거나 목록으로 돌아올 때까지 예전 이름·지운 회차를 보인다. 지운 회차는 열면 "이제 미리 볼 수 없습니다"로 안내되고, 돌아오면 목록에서 빠진다. 서버에서 이름 바꾸기·지우기 때도 `session.updated`를 보내게 할지 정해 달라(서버 변경이라 이번에 하지 않았다).
