# T037 구현 노트: 학생 다시 보기 — 공개 묶음은 끝까지, 비공개는 자료만

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC38: 수업이 끝나면 같은 회차의 다시 보기로 이어진다(T026).
- AC39: 지난 회차를 열면 거두지 않은 자료가 보인다. 공개 묶음이면 처음부터 끝까지 넘겨 보고, 비공개 묶음이면 "이 회차의 슬라이드는 공개되지 않았습니다.".
- AC41: 끝난 회차의 묶음을 바꾸면 새 묶음은 비공개로 시작하고, 교수가 공개하면 다시 보기에 새 묶음 전체가 보인다.
- T035가 이미 다시 보기의 범위 끝 문구와 `limit`을 뺐다(T035 노트 6번). 비공개 묶음 안내는 T033이 넣었다.

## 내가 정한 것 (스펙 밖)

1. **보는 동안에도 바뀐다**
   - 다시 보기 화면을 열어 둔 동안 교수가 그 회차를 공개·비공개하거나(`deck.updated`) 묶음을 올리거나 지우면(`session.updated`), 새로 고치지 않아도 상태를 다시 받는다.
   - 다시 연결되거나(`ready`) 서버가 놓친 알림 대신 `resync`를 보내도 다시 받는다(리뷰에서 찾음).
   - 수업 연결 모듈(`classLive`)은 받은 알림을 그대로 넘겨 주는 `onEvent`를 갖게 됐다. 따라가는 회차가 아닌 회차의 알림도 넘긴다. 모듈이 먼저 처리한 뒤에 넘기므로, 받는 쪽이 실패해도 연결은 이어진다(리뷰에서 찾음).
2. **다시 받을 때의 위치**
   - 같은 묶음이면 보던 곳을 지킨다.
   - 다른 묶음(바꾼 묶음)이면 처음부터 본다. 예전 위치와 예전 묶음의 단계 수는 새 묶음과 맞지 않기 때문이다(리뷰에서 찾음).
3. **처음 받기와 다시 받기는 같은 길을 지난다**
   - 요청마다 번호를 붙여 늦게 온 예전 응답은 버린다.
   - 다시 받기가 처음 응답보다 먼저 오면, 그것으로 처음처럼 시작 위치와 초점을 정한다.
   - 받지 못했을 때: 보던 화면이 있으면 그대로 두고, 없으면 이유와 할 일을 보인다. 전에는 "불러오는 중"에 머물 수 있었다(리뷰에서 찾음).
4. **알림과 초점**
   - 공개되면 "슬라이드가 공개되었습니다.", 비공개가 되면 "이 회차의 슬라이드는 공개되지 않았습니다."를 학생 수업 화면의 늘 있는 알림 자리로 읽힌다. 앞의 글은 이 작업에서 정한 문구다.
   - 슬라이드가 사라져 초점을 잃었으면 제목으로 옮긴다. 다른 곳에 있으면 그대로 둔다.
5. **받아들인 것**
   - 비공개로 바뀌기 전에 이미 받은 슬라이드 파일은 브라우저에 남는다(spec 결정, AC50의 "그때부터 내주지 않는다").
   - 이 문제는 슬라이드 자리를 내려 화면에서는 사라지게 하는 데서 그친다.
