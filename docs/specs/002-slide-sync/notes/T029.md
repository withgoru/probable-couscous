- tasks: 새 화면(회차 관리, 교수 수업 화면, 프로젝터, 학생 수업 화면)에 axe 위반 0, 44px, 키보드만으로 시작·넘기기·보내기·학생 이전·다음과 '교수 화면으로'·복사, 아이콘 버튼의 읽는 이름, iframe `title`, 학생 화면 390px 가로 넘침 없음. 001 T034 방식의 E2E.

## 내가 정한 것 (스펙 밖)

1. **E2E** (`e2e/a11y.spec.ts`의 "002 수업 화면 (AC45)")
   - 001 T034처럼 Tab으로 지나가는 모든 요소의 포커스 링과 44px를 보고, 화면마다 axe를 돌린다.
   - 교수(노트북)
     - 관리 페이지: Tab 순회, 공개 스위치(Space), 수업 시작(Enter)
     - 수업 화면: 다음(Enter), → 키, 슬라이드 안으로 Tab해 →, 글 칸의 →는 넘기지 않음, 보내기·거두기(확인 창)
     - 프로젝터: Enter로 열기, 전체 화면 버튼
     - 수업 종료 확인 창: Escape로 닫으면 초점이 돌아옴
   - 학생(390px)
     - 수업 화면: 다음·이전(Enter), 교수 화면으로(초점이 다음으로 감), 복사(클립보드 확인)
     - 대기 화면, 미리 보기, 다시 보기: Tab 순회, axe, 가로 넘침
   - 모든 화면에서 iframe에 제목이 있는지 본다. 아이콘 버튼의 이름은 axe(`button-name`)와 이름으로 찾기로 본다.
   - 프로젝터의 F 키는 컴포넌트 테스트(`projector.test.ts`)가 본다.
2. **찾은 문제: 슬라이드에 초점이 들어가도 보이지 않았다**
   - Tab으로 슬라이드(iframe) 안에 들어가면 링이 없었다. 브라우저는 초점이 iframe 안의 문서에 있을 때 바깥의 iframe 요소에 `:focus`·`:focus-within`을 걸지 않아서, CSS만으로는 그릴 수 없다(실험으로 확인).
   - `frameFocus` 동작을 만들었다. 슬라이드 묶음은 같은 출처라 슬라이드 창 안의 focus·blur를 직접 듣고 `data-focused`를 붙인다.
     - 처음에는 바깥 창의 blur·focusout으로 알아보았는데, 약 35% 놓쳤다(변형 검사가 찾음).
   - 링은 iframe 옆의 덮개로 그린다.
     - 다른 요소와 같은 규칙: primary 2px + 간격 2px. 슬라이드 위라 안쪽으로 그린다.
     - iframe 자체의 outline은 간격이 없고 어두운 슬라이드 위에서 대비가 낮았다(리뷰에서 찾음).
     - 화면을 찍어 보이는 것을 확인했다.
   - `:focus-visible`처럼 키보드로 들어왔을 때만 보인다. 손가락이나 마우스로 슬라이드를 누르면 떼고, 다시 Tab으로 들어오면 붙인다. 휴대폰에서 누를 때마다 링이 남지 않게 하려는 것이다.
   - 교수 수업 화면, 학생 수업 화면, 다시 보기·미리 보기의 슬라이드에 붙였다. 다음 슬라이드 미리보기와 프로젝터는 초점을 받지 않는다.
   - E2E 점검 도구는 iframe에 초점이 있으면 그 덮개의 링을 본다.
3. **받아들인 것**
   - 다른 앱으로 갔다 와도 초점이 슬라이드 안에 있으면 링은 남는다.
   - 한 화면에 초점을 받는 슬라이드는 하나라는 전제로 만들었다(주석에 적었다).
