# T038 구현 노트: 학생 — 공개 묶음 미리 받기와 캐시

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- plan 위험 4: "학생이 입장할 때(수업 전) 묶음을 미리 받게 해 몰림을 줄인다. 해시 파일은 오래 캐시한다."
- T030 측정: 200명이 수업 시작에 한꺼번에 받으면 일부가 받지 못하고, 받지 못한 학생은 다시 받을 수 없다. 사용자 결정(2026-11-27): 미리 받기로 한다.
- tasks T038: 공개 묶음은 학생도 해시 파일을 오래 캐시, index.html은 매번 확인, 비공개 묶음은 T033 그대로. 대기 화면이 첫 미리 볼 수 있는 회차의 묶음 첫 화면 파일을 미리 받고, 수업이 시작되면 다시 받지 않는다.

## 내가 정한 것 (스펙 밖)

1. **서버 캐시**
   - `/decks/…`의 학생 열람 판단(`_student_access`)이 '공개'인지 '수업 중 비공개'인지를 함께 알려 준다.
   - 공개 묶음의 해시 파일에만 학생도 오래 캐시(`private, max-age=31536000, immutable`)를 준다. 판단은 한 곳(C8)이다.
   - index.html은 누구나 매번 확인한다. 비공개로 바꾸면 여기서 막혀 슬라이드가 열리지 않는다.
2. **무엇을 미리 받는가**
   - index.html이 바로 부르는 그 묶음의 JS·CSS(테스트용 묶음에서 7개, 약 520KB)만 받는다.
   - 첫 슬라이드가 나중에 불러오는 조각과 그림은 받지 않는다. 묶음을 열어 Slidev를 돌려 봐야 알 수 있어서다.
3. **언제 받는가**
   - 대기 화면에 있는 동안, 미리 볼 수 있는 회차 가운데 회차 순서로 첫 회차의 묶음을 받는다. 오늘 수업의 묶음이 비공개이고 다음 주 묶음이 공개라면 다음 주 것을 받는다(0.5MB 정도, 한 번).
   - 받은 묶음은 다시 받지 않는다. 받지 못했으면(잠깐 끊김 등) 목록을 다시 받을 때 다시 해 본다(리뷰에서 찾음).
   - 받지 못해도 화면에는 아무것도 알리지 않는다.
   - 휴대폰 데이터 절약 모드여도 받는다. 어차피 수업 시작에 받을 파일이고 한 번뿐이다.
   - 다시 보기·미리 보기를 열어 두어도 대기 중이면 받는다.
4. **받아들인 것**
   - 공개였다가 비공개로 바꾼 묶음의 해시 파일은 학생 브라우저 캐시에 남는다(공개였던 동안 볼 수 있던 것). 슬라이드는 index.html에서 막힌다. tasks에 적어 승인받았다.
   - **비공개 묶음(기본)에는 미리 받기가 없다.** 교수가 수업 전에 공개하지 않으면 T030의 위험이 그대로다(notes.md "미리 받기 뒤 다시 잼").

## 확인한 것

- 테스트를 먼저 썼다.
  - 서버: 공개 묶음 해시 파일의 오래 캐시(예정·진행 중·종료), index.html은 매번 확인, 비공개로 바꾸면 첫 화면이 바로 막힘. 기존 비공개 묶음 테스트는 그대로다.
  - `deckPrefetch.test.ts` 5개: 첫 화면 파일 고르기, 쿠키로 받기, 실패하면 조용히, 파일 하나 실패, 내용을 끝까지 읽기
  - `StudentClass.test.ts` 6개: 첫 회차 한 번, 비공개는 받지 않음, 묶음이 바뀌면 새로, 실패해도 알리지 않음, 수업이 먼저 시작되면 받지 않음, 실패하면 다시
  - E2E 1개: Chrome 개발자 도구 프로토콜로 미리 받은 해시 파일을 수업 시작에 다시 요청하지 않고(받기도 확인도 없음) 캐시에서 꺼내는지 본다.
  - 측정 스크립트에 `--preload`를 더했다.
- 검증은 서브에이전트가 했다.
  - 변형 검사: 14개 중 12개를 잡았다. 남은 2개(내용을 읽지 않음, 기다리지 않을 때도 받음)는 테스트를 더해 잡았다. 서버·E2E 변형 2개는 내가 따로 확인했다(모두 잡음).
  - 코드 리뷰: 막는 버그는 없었다. 찾은 것과 처리는 이렇다.
    - 측정이 가장 좋은 경우임: notes에 밝혔다.
    - 비공개 묶음에서는 위험이 남음: notes에 밝히고 여쭌다.
    - 실패한 미리 받기를 다시 하지 않음: 다시 한다.
    - E2E의 캐시 확인이 약함: 미리 받은 파일이 캐시에서 나왔는지로 바꿨다.
    - 다른 브라우저: 실기기 목록 13번에 더했다.
- 서버 928개, 클라이언트 833개, svelte-check, 빌드, E2E 35개 통과.
