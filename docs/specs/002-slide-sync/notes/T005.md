# T005 구현 노트: 슬라이드 묶음 올리기·검사·저장 서버

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC5: 올리면 "업로드됨", 파일 이름, 올린 시각, 슬라이드 수. 없으면 "비어 있음".
- AC6: 템플릿 빌드가 아니면 아무것도 바뀌지 않고 "슬라이드 묶음을 읽을 수 없습니다. Slidev로 빌드한 폴더(dist)를 zip으로 묶어 올려 주세요.", 상한(100MB)을 넘으면 "파일이 너무 큽니다. 100MB 이하로 올려 주세요."
- AC7: 진행 중인 회차에서는 바꾸기·지우기 불가, "수업 중에는 슬라이드를 바꿀 수 없습니다."
- 오류 동작: 끝까지 올라가지 않으면 이전 묶음이 그대로, "올리지 못했습니다. 다시 올려 주세요.", 반쯤 올라간 묶음은 쓰이지 않는다.
- plan: `PUT/DELETE …/sessions/{s}/deck`, `DeckStore`(임시 폴더에 풀고 이름 바꿔 교체), 기준 경로를 `/decks/{묶음 번호}/`로 바꿔 저장, 위험 7(경로 탈출·심볼릭 링크·압축 폭탄·파일 수). 설정 `DATA_DIR`, `DECK_MAX_BYTES`, `DECK_MAX_UNZIPPED_BYTES`, `DECK_MAX_FILES`.

## 내가 정한 것 (스펙 밖)

1. **본문은 zip 그대로, 파일 이름은 `filename` 질의 값.** plan은 `python-multipart` 폼 업로드라고 했지만, 001의 CSV 올리기가 이미 본문을 그대로 받는다. 같은 방식이 더 단순하고 새 의존성도 없다. 권한과 회차 상태(진행 중이면 409)를 먼저 보고, 통과한 뒤에만 본문을 임시 파일로 받는다. 받는 도중 상한을 넘으면 그 자리에서 413.
2. **저장 순서.** 묶음 번호가 있어야 기준 경로를 바꿀 수 있어서, 먼저 '지운 상태'(`removed_at` 있음)로 행을 넣어 번호를 얻는다. 그동안 화면에는 안 보인다. 파일을 검사하고 풀 때는 DB 잠금을 잡지 않는다(풀기가 몇 초 걸려도 수업 중인 다른 강좌의 쓰기를 막지 않게). 마지막 트랜잭션에서 회차가 그새 진행 중이 되지 않았는지 다시 보고, 이전 묶음을 지운 상태로 만들고 새 행을 살린다. 실패하면 새 행과 새 파일만 지운다.
3. **이전 묶음 파일은 커밋 뒤에 지운다.** 그 사이에 서버가 멈추면 쓰지 않는 파일이 남을 수 있다(행은 지운 상태라 보이지 않는다). 해롭지 않아 정리 작업은 만들지 않았다.
4. **받아들이는 묶음의 기준.** 맨 위에 `index.html`(기준 경로 `/__deck__/` 포함)과 `classroom-deck.json`(`format` 1, `slide_count` 1 이상, 슬라이드 수만큼의 `slides`). `dist` 폴더째 묶은 zip은 거절한다(템플릿 스크립트는 맨 위에 둔다). 모든 거절은 AC6 문구 하나로 보인다.
5. **위험한 zip은 두 겹으로 막는다.** 풀기 전에 선언된 크기 합계와 파일 수로 거절하고, 풀 때도 실제로 쓴 바이트를 세어 한도를 넘으면 멈춘다. 경로는 상대 경로만(`..`, 절대 경로, 드라이브, 역슬래시 거절), 심볼릭 링크 거절.
6. **크기 문구는 상한에 따라 바뀐다.** 기본 100MB면 AC6 문구 그대로이고, 설정으로 MB 단위가 아닌 값을 주면 바이트로 보인다.
7. **화면에 보일 파일 이름**은 폴더 부분을 빼고 120자로 줄인다(`.zip`은 남긴다). 비어 있으면 `slides.zip`. 저장 경로에는 쓰지 않는다(경로는 번호).
8. **`DATA_DIR`을 비우면 DB 파일과 같은 폴더**(그 아래 `decks/`). plan 위험 9(백업 때 DB와 함께 옮김)에 맞고, 테스트는 임시 DB 폴더를 쓰니 저장소 폴더를 더럽히지 않는다.
9. **회차 목록에 묶음 정보를 더했다**(`deck`: 번호, 파일 이름, 슬라이드 수, 크기, 올린 시각. 없으면 `null`). 화면은 T016.
10. **회차를 지우면 묶음 파일도 지운다**(T004에서 미룬 일).
11. 임시 파일 쓰기에 `anyio`(Starlette가 이미 쓰는 패키지, `constraints.txt`에 4.16.0 고정)를 썼다. 비동기 함수 안에서 파일을 막는 방식으로 쓰지 않으려는 것이다(ruff ASYNC230). 새 의존성은 아니다.
12. 기록: `deck_uploaded`, `deck_removed`(회차 번호와 묶음 번호만).
