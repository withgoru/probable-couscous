# T027 구현 노트: 학생 — 연결 끊김·느린 로딩·입장 끊김

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC44: 명단에서 빠졌거나 로그인이 끊긴 학생은 수업 화면 대신 입장 화면으로 간다.
- 오류 동작 "학생 연결이 끊김"
  - 끊기면 슬라이드는 마지막 화면 그대로이고, 위쪽에 "연결이 끊겼습니다. 다시 연결하는 중…"이 보인다.
  - 다시 붙으면 안내가 사라진다. 따라가던 학생은 교수 위치로 가고, 끊긴 동안 보낸 항목이 모두 나타나며, 거둔 항목은 사라진다(C12).
- 오류 동작 "학생 휴대폰이 느림": 슬라이드를 받는 중이면 그 자리에 "슬라이드를 불러오는 중…"이 보이고, 자료는 쓸 수 있다.
- 다시 붙기, 놓친 것 채우기, `goodbye`는 연결 모듈(T014)이 이미 한다. 이 작업은 학생 화면과 입장 페이지가 그것을 보이고 따르게 한다.

## 내가 정한 것 (스펙 밖)

1. **끊김 안내**
   - 학생 화면 맨 위, 늘 있는 알림 자리(`role="status"`)에 보인다. 수업 화면, 대기 화면, 다시 보기, 미리 보기 모두다.
   - 비어 있을 때는 화면 흐름을 차지하지 않는다. 그대로 두면 위쪽에 24px 여백이 생겼다(리뷰에서 찾음).
   - 처음 연결하는 중이나 입장이 끝난 뒤에는 보이지 않는다.
   - 다시 붙으면 "다시 연결되었습니다."가 읽힌다. 안내가 사라지는 것만으로는 읽히지 않기 때문이다(리뷰에서 찾음, 문구는 이 작업에서 정했다).
2. **끊긴 동안 내보내진 학생**(리뷰에서 찾음, 가장 흔한 AC44 경우: 휴대폰 화면이 꺼진 사이 교수가 명단에서 뺌)
   - 이때 서버는 다시 붙으려는 연결을 받지 않는다(코드 없이 닫힘). 그래서 학생 화면은 `goodbye`를 받지 못하고 "다시 연결하는 중…"에 머물렀다.
   - 이제 연결 모듈은 학생 연결이 붙기 전에 닫히면 회차 목록을 HTTP로 한 번 묻는다. 401·403이면 내보낸 것으로 보고 더 붙지 않는다.
   - 묻지 못하면(네트워크) 계속 다시 붙는다. 교수 화면은 묻지 않는다.
3. **입장 화면으로**
   - 입장이 끝나면(goodbye, 4403, 위의 거절) 학생 수업 화면이 한 번만 알리고, 입장 페이지는 이메일 단계로 돌아가 제목에 초점을 둔다. 수업 연결은 닫힌다.
   - 이메일 칸 위에 경고(`role="alert"`)로 이유를 보인다.
     - 서버가 알려 준 이유: 명단에서 빠짐, 로그아웃됨
     - 이유 없이 닫혔으면: "이 수업을 더 볼 수 없습니다. 이메일로 다시 입장해 주세요."(이 작업에서 정한 문구)
   - 이메일을 고치기 시작하면 이 안내는 사라진다.
4. **불러오는 중**
   - 슬라이드 자리를 가리는 바탕 위에 보인다. 바탕이 없으면 슬라이드가 그려지기 시작할 때 글자와 겹쳤다(리뷰에서 찾음).
   - 15초 안에 준비되지 않으면(파일을 받지 못함 등) "슬라이드를 열 수 없습니다. 자료는 계속 볼 수 있습니다."로 바꾼다. 늦게라도 준비되면 슬라이드가 보인다(리뷰에서 찾음).
   - 다시 보기와 미리 보기도 같다.
5. **받아들인 것**: 처음 연결이 실패하고 첫 불러오기도 실패하면, 대기 화면에 끊김 안내와 "잠시 뒤 자동으로 다시 불러옵니다." 안내가 함께 보인다. 서로 어긋나지 않아 두었다.
