# T016 구현 노트: 이 회차의 자료와 수업 시작 버튼 화면

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC5: "업로드됨"/"비어 있음" 배지, 파일 이름, 올린 시각, 슬라이드 수.
- AC6: 빌드 결과가 아니면 "슬라이드 묶음을 읽을 수 없습니다. …", 크면 "파일이 너무 큽니다. 100MB 이하로 올려 주세요.". 아무것도 바뀌지 않는다.
- AC7: 진행 중이면 바꾸기·지우기가 흐려지고 "수업 중에는 슬라이드를 바꿀 수 없습니다.".
- AC9: 예정 회차에 **수업 시작**. 슬라이드가 없으면 "슬라이드 없이 시작할까요? 메시지·자료 보내기만 쓸 수 있습니다."를 먼저 확인한다. 시작하면 교수 수업 화면이 열린다.
- AC10: 다른 회차가 진행 중이면 "{회차 이름} 수업이 진행 중입니다. 먼저 끝내 주세요."와 그 회차로 가는 버튼.
- AC11: 보관된 강좌는 "보관된 강좌는 수업을 시작할 수 없습니다.".
- AC18: 진행 중이면 **수업 화면으로**. AC40: 종료 회차에 **이어서 수업하기**.

## 내가 정한 것 (스펙 밖)

1. **배치**: 회차 선택 바로 아래에 수업 버튼, 그 아래에 '이 회차의 자료' 카드를 둔다. 수업 전에 가장 먼저 누르는 버튼이라 위에 두었다. 회차를 바꾸면 두 구역의 오류와 확인 창을 새로 시작한다.
2. **거절 문구는 서버 것을 그대로 쓴다.** 크기 상한은 서버 설정(`DECK_MAX_BYTES`)을 따르므로 화면이 미리 재지 않는다. 화면 문구와 서버 문구가 어긋나지 않게 하려는 것이다. 파일 칸은 `.zip`만 고르게 한다.
3. **올린 시각은 날짜와 함께** "3월 4일 14:05"로 보인다(`time.dateTime`). 수업 전 준비 자료라 날짜가 필요하다.
4. **파일이 사라진 묶음**(`available: false`)은 카드에 "슬라이드를 열 수 없습니다. 묶음을 다시 올려 주세요."를 보인다. 수업 시작 때는 슬라이드가 없는 것과 같이 "슬라이드 없이 시작할까요?"를 묻는다.
5. **'그 회차로 가는 버튼'은 관리 페이지에서 그 회차를 고르는 버튼**("{이름}로 가기")이다. 고르면 그 회차의 '수업 화면으로'가 보인다.
6. **화면의 판단과 서버가 엇갈리면** 서버의 거절 문구를 보이고 목록을 다시 불러온다. 다른 탭에서 먼저 시작한 경우 같은 것이다. 응답에 진행 중인 회차 번호가 있으면 "진행 중인 회차로 가기" 버튼도 보인다.
7. **이어서 수업하기는 확인 없이 바로 한다.** 스펙에 확인 문구가 없고, 되돌리려면 수업 종료를 누르면 된다. 버튼 아래에 "마지막 위치에서 이어지고, 보낸 항목도 그대로입니다."를 둔다.
8. **시작하면 `/courses/{강좌}/live`(T018의 교수 수업 화면)로 간다.** 그 화면이 생기기 전까지는 빈 화면이다.
9. **확인 창 모양**: `ConfirmDialog`에 `tone`을 더했다. "슬라이드 없이 시작"은 지우기가 아니어서 주 버튼 모양(`btn-default`)이다. 기본값은 그대로 `destructive`다.
10. **문구의 조사**: 파일 이름은 받침이 정해지지 않아 "올렸습니다: a.zip", "a.zip 파일을 지웁니다."처럼 조사가 붙지 않게 썼다.
