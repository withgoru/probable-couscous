# T011 구현 노트: 명단에서 빠진 학생의 연결 닫기

> 스펙과 plan에 없는, 구현하면서 내가 세운 계획과 판단의 요지다. 스펙이 우선한다. 고칠 부분이 있으면 알려 달라.

## 스펙과 plan에서 읽은 것

- AC44: 명단에서 빠졌거나 로그인이 끊긴 학생은 수업을 볼 수 없고 입장 화면으로 간다.
- plan: 001의 빼기·로그인 끊기가 방에 `member_revoked{멤버십}`을 발행하고, WebSocket 처리기가 그 연결에 `goodbye{reason}`을 보낸 뒤 닫는다.

## 내가 정한 것 (스펙 밖)

1. **발행은 저장이 끝난 뒤다.** 001 `roster.remove_entry`와 `revoke_login`이 로그아웃시킨 멤버십 번호를 돌려주도록 바꿨다(빼기는 입장한 적 없으면 `None`). 라우트가 커밋 뒤에 `member_revoked`를 발행한다. 입장한 적 없는 학생을 빼면 닫을 연결이 없어서 발행하지 않는다.
2. **`goodbye`의 이유와 문구**
   - 빼기: `removed`, "수강생 명단에서 빠져 이 수업을 볼 수 없습니다. 교수님께 문의해 주세요."
   - 로그인 끊기: `signed_out`, "이 강좌에서 로그아웃되었습니다. 강좌 링크를 다시 열어 이메일 인증부터 해 주세요."
   - 학생 화면(T024)은 이 문구를 보이고 입장 화면으로 보낸다.
3. **닫힘 코드는 4403.** 네트워크가 끊긴 것(다시 붙어야 함)과 내보낸 것(다시 붙으면 안 됨)을 화면이 구분하게 했다.
4. **`member_revoked`는 그 학생의 연결에만 의미가 있다.** 교수·프로젝터·다른 학생 연결에는 보내지 않는다. 교수 화면에는 현황 숫자만 바뀌어 간다(C7, C9). 같은 학생의 화면이 여러 개면 모두 닫는다.
5. 방은 강좌마다 따로라서, 다른 강좌의 연결은 건드리지 않는다(C5).
