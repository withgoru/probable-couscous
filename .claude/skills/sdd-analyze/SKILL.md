# /sdd-analyze

문서 세 개의 정합성을 점검한다. **파일을 수정하지 않는다.** 결과는 대화로 짧게 보고한다.

## 점검 항목

1. **AC 대응**: spec의 모든 AC가 tasks의 AC 대응표에 있는가. 대응 없는 AC를 나열한다.
2. **범위 초과**: tasks에 있지만 spec에 근거가 없는 작업(C16 위반 후보)을 나열한다.
3. **constitution**: plan의 점검 표가 비어 있거나 충족 방법이 구체적이지 않은 원칙, tasks가 위반할 소지가 있는 작업을 나열한다. 필수 회귀 테스트가 빠졌는지 확인한다.
4. **상태**: 앞 단계가 `approved`가 아닌데 뒤 단계가 `approved`인 경우, `stale`로 표시된 문서를 알린다.
5. **단계 침범**: spec에 구현 용어(프레임워크, 테이블, API 경로)가 있는가. plan이 spec의 요구사항을 그대로 반복하는가.
6. **미결정**: spec의 체크되지 않은 미결정 질문, plan의 결과가 비어 있는 위험·검증 항목.

## 출력 형식

```
점검 결과: 이상 없음 / 확인 필요 N건
1. [범주] 문제 한 줄 → 어느 문서의 어디를 어떻게 고치면 되는지 한 줄
```

항목이 없으면 "이상 없음"만 쓴다. 길게 쓰지 않는다.
